I created `pipeline_parallel.py` with `train_step_pipeline_afab`. I compared it against an ordinary, non-pipelined model with the same weights, using `torchrun` on CPU (gloo backend) with world sizes 1 and 2. In both cases the loss and every parameter gradient matched the reference exactly (max difference 0). I haven't run it against your actual hook-based test.

**How it works:**
- **Splitting the layers:** decoder layers are divided as evenly as possible, and any extra layers go to the lower ranks. For example, 5 layers on 2 ranks gives rank 0 layers 0–2 and rank 1 layers 3–4. Rank 0 also runs the token embedding, and the last rank also runs the final norm and output layer (`lm_head`). Each rank only calls its own layers' `forward`, so a hook-based layer count will only see those layers. The model itself isn't changed.
- **Forward pass, all microbatches first:**
  - Rank 0 embeds the input IDs.
  - Every other rank receives hidden states of shape `[mb, seq, hidden]` from the previous rank and marks them `requires_grad`.
  - Each rank runs its layers by calling the `LlamaDecoderLayer` modules directly, so the test's hooks fire. It builds the rotary position embeddings and causal mask the same way `LlamaModel` does.
  - Every rank except the last sends its output to the next rank. The last rank computes `cross_entropy(logits, targets) / num_microbatches`.
- **Backward pass, all microbatches second:**
  - The last rank calls `loss.backward()`.
  - Other ranks receive the gradient from the next rank and call `torch.autograd.backward(output, grad)`.
  - Every rank except rank 0 then sends the gradient of its received input back to the previous rank.
- **Communication** uses `dist.P2POp` with `dist.batch_isend_irecv`. Inputs, hidden states and gradients are moved to the given `device` and `dtype`, and no hooks are used.
- **Return value:** the last rank returns the total scaled loss (as a detached value); the other ranks return `None`.

**Assumptions to check:**
- The loss is computed directly against `targets` with no shifting, so it assumes the targets are already shifted.
- Every rank must be passed the `inputs` list, because non-first ranks use the input shapes to size their receive buffers.
- The function doesn't zero gradients or run an optimizer step, so gradients add up in `.grad` across calls.
