I created `pipeline_parallel.py` with `train_step_pipeline_afab`. I tested it against an unsplit reference model, with gradients collected from parameters rather than through hooks. For world sizes 1 and 2, every parameter gradient on every rank matched the reference exactly (max difference 0), and the loss matched too.

**How it works:**
- **Splitting the layers:** each rank gets a contiguous block of decoder layers. Any leftover layers go to the lowest ranks: with 5 layers and 2 ranks, rank 0 runs 3 and rank 1 runs 2. Rank 0 also runs the embedding. The last rank also runs the final norm, `lm_head` and the loss.
- **Forward pass, all microbatches first:**
  - Rank 0 embeds the input IDs.
  - Every other rank receives a `[mb, seq_len, hidden]` hidden-state tensor from the previous rank, in the given device and dtype, and marks it as needing gradients.
  - Each rank calls its decoder layers directly, passing them the rotary position embeddings and a causal mask.
  - The last rank computes `cross_entropy(logits, targets) / num_microbatches`; every other rank sends its output to the next rank.
- **Backward pass, then all microbatches:**
  - The last rank calls `loss.backward()`.
  - Every other rank receives the output gradient from the next rank and runs `torch.autograd.backward(output, grad)`.
  - Every rank except 0 then sends the gradient of its received input back to the previous rank.
- **Communication:** all of it goes through `dist.P2POp` with `batch_isend_irecv`. The implementation uses no hooks.
- **Return value:** the function returns the total loss (detached) on the last rank and `None` on the other ranks.

**Things to know:**
- Input and target IDs are moved to the device but kept as integers, because the embedding layer needs integer indices. Hidden states and gradients are converted to the given dtype.
- The function doesn't zero existing gradients, so they add to whatever is already there. Zeroing them is left to the caller or test.
- In this environment the installed `torchvision` is broken, and importing `transformers` fails because of it. My test script got around this by blocking `torchvision` from loading (`sys.modules['torchvision'] = None`). Your test environment may need the same workaround or a working `torchvision`.
