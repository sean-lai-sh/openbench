I created `pipeline_parallel.py` with `train_step_pipeline_afab`. I tested it against a normal single-process reference model at world sizes 1 and 2, using both the eager and sdpa attention modes. The loss matched, and the gradients on each rank's parameters were identical to the reference (max difference 0).

**How it works:**
- **Splitting the model:** the decoder layers are divided as evenly as possible, with at most one layer of difference between ranks (`_partition_layers`). Rank 0 also runs the token embedding, and the last rank also runs the final norm, `lm_head` and the loss.
- **Each rank's forward pass:** it builds the position embeddings and causal mask the same way `LlamaModel.forward` does, then calls its decoder layers as normal modules. It never calls `.forward` directly, so the test's hooks still fire. It doesn't register any hooks of its own.
- **Forward phase:** for each microbatch, a rank either embeds the input IDs (rank 0) or receives hidden states shaped `[mb, seq_len, hidden]` from the previous rank. It runs its layers, then sends the result on to the next rank. The last rank instead computes `cross_entropy / num_microbatches`. All received tensors are moved to the given `device` and `dtype`.
- **Backward phase:** after all forwards finish, the last rank calls `loss.backward()` for each microbatch. The other ranks receive the gradient from the next rank and call `torch.autograd.backward(output, grad)`. Every rank except rank 0 then sends its input's gradient back to the previous rank.
- **Communication:** all sends and receives use `dist.P2POp` with `batch_isend_irecv`.
- **Return value:** the last rank returns the total loss with gradients detached; other ranks return `None`.

**Two things to know:**
- **Environment issue:** `torchvision` doesn't work in this environment (`operator torchvision::nms does not exist`), and that stops `transformers` from importing normally. My test script worked around it with `sys.modules['torchvision'] = None`. The grading tests may hit the same import error if they run here.
- **Tied embeddings:** if a model ties `lm_head` to the embedding (Llama doesn't by default), the copies on the first and last ranks are not kept in sync. Nothing in the task asked for that.
