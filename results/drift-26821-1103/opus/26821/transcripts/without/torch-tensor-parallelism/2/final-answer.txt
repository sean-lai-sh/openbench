I wrote `parallel_linear.py`, and a test run on CPU passed at world sizes 1, 2 and 4. At each size, both classes gave the same results as a plain `torch.nn.Linear` built from the same `master_weight`. That covered the forward output, the input gradient, and the gradients for each rank's weight and bias shards.

**How each class works:**
- **`ColumnParallelLinear`**: each rank keeps an equal slice of the output rows of `master_weight` (`master_weight[r*c:(r+1)*c, :]`, where `c = out_features / world_size`). Its bias is a zero vector of length `c`. Each rank computes its slice of the output, and the slices are joined along the last dimension with `all_gather`. In the backward pass the output gradient is split back to each rank, and the input gradients are summed across ranks with `all_reduce`.
- **`RowParallelLinear`**: each rank keeps an equal slice of the input columns of `master_weight` (`master_weight[:, r*c:(r+1)*c]`, where `c = in_features / world_size`). The bias is the full length on every rank, starts at zero, and is added once after the partial outputs are summed with `all_reduce`. In the backward pass the output gradient goes to every rank unchanged, and the input gradient is gathered back together.

**Choices the task didn't specify:**
- The weight uses the same layout as `nn.Linear`, `(out_features, in_features)`. So "split by columns" here means splitting the output dimension (rows of the stored tensor), and "split by rows" means splitting the input dimension. If the tests expect a transposed weight, the slicing would need to change.
- `RowParallelLinear` accepts either the full input, which it splits itself, or an input that's already been split for this rank. It decides by checking whether the last dimension equals `in_features`.
- `in_features` and `out_features` must divide evenly by the world size; otherwise construction fails with an assertion error.
- If `torch.distributed` hasn't been initialised, both classes behave as a single process (world size 1, rank 0).
