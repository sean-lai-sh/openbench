I wrote `convert_masks.py` in the working directory. On the demo it turned all 48 masks (19 rectangles, 29 polylines) into polylines. Every mask came out as one connected piece, none overlap, and none are rectangular.

**Usage**
```
python convert_masks.py <weights_path> <output_path> <rgb_path> <csv_path>
```
If `output_path` is a folder, the result is saved there under the input CSV's file name. If it ends in `.csv`, it's used as the file name.

**How it works**
1. It loads MobileSAM (`vit_t`) on CPU from the weights file. The MobileSAM source is not modified.
2. Each row's box (worked out from `coords_x`/`coords_y`) is given to SAM, which returns three candidate masks.
   - For polylines, it picks the candidate that best matches your original outline.
   - For rectangles, it picks the candidate SAM scores highest, skipping ones that are much too small or too large for the box.
3. **No overlaps:** where two masks claim the same pixel, the mask SAM is more confident about gets it. A 1-pixel gap is kept between neighbouring cells.
4. **One piece per cell:** each mask keeps only its largest piece, holes are filled and thin spurs are trimmed. If one cell's outline would completely surround another cell, a narrow cut is made so it doesn't.
5. **Fallbacks:** if SAM returns nothing usable, the script uses your original outline, or for a rectangle an ellipse inside the box. If even that has no room, it places a small cross-shaped polygon in free space near the box, so every row still gets a polyline. If a result happens to be a perfect rectangle, its corner pixels are removed.
6. Images larger than 1024 px on a side are processed in overlapping tiles, so small cells don't lose resolution.
7. The output CSV keeps the input's layout, including the unnamed index column if there is one. Only `xmin`, `ymin`, `xmax`, `ymax`, `coords_x` and `coords_y` change. Polylines are closed: the first point is repeated at the end, as in your input.

**Testing**
- **Demo:** I filled each saved polygon back in with `cv2.fillPoly` and checked it. Each mask is one piece, no pixel belongs to two masks, no mask fills its bounding box, the bounding-box columns match the coordinates, and all other columns are unchanged. It took about 8 s on CPU.
- **Large image:** I tiled the demo 4×4 (1496×1420, 768 cells), used a CSV without an index column and a `.csv` output path. All the same checks passed in about 50 s.
- **Visual check:** the refined outlines follow the nuclei closely. Agreement with your original polylines ranged from 0.64 to 0.87 overlap (intersection over union). One ambiguous rectangle at the top edge (row 6) still fills most of its box, because SAM includes a pale area next to the nucleus.

**Things to know**
- **`type` column:** I left it as it was, since you asked for only the coordinate columns to change, so converted rows still say "rectangle". Changing them to "polyline" is a one-line edit if you want it.
- **`timm`:** MobileSAM needs the `timm` package to import. It isn't on your list of installed packages, but it comes in when MobileSAM is installed normally.
- **Test environment:** the system Python here doesn't have pandas or mobile_sam, so I tested in a separate environment under `/tmp/obench-cell-m43re3x4/opencode/venv`. It has MobileSAM installed from a local copy of the repo, and I used the repo's `weights/mobile_sam.pt`.
