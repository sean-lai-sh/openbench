I wrote `polyglot/main.rs`. I compiled it with both `rustc` and `g++ -x c++` with no errors or warnings, and both binaries print the same results for N = 0, 1, 2, 3, 10, 50 and 100. For example, N=0 gives 1, N=10 gives 89, and N=100 gives 573147844013817084101.

The file works because Rust allows comments inside comments and C++ doesn't:

- **Line 1 `/* /* */`:** C++ treats this as one complete comment, so it goes on to read the C++ program that follows. Rust sees the second `/*` as opening a comment inside the first, so it is still in a comment and skips the C++ code.
- **`#if 0` then `// */`:** C++ turns off everything from here to `#endif`. For C++, `// */` is just a line comment. For Rust, the `*/` closes the open comment, so it reads the Rust `fn main` that follows.
- **End `/* /* */`, `#endif`, `// */`:** The same trick again. C++ sees a short comment and then `#endif`. Rust is inside a comment until the final `*/`, so it never sees `#endif`.

Both versions do the addition digit by digit instead of using a fixed-size integer. That means large N won't overflow: a 64-bit integer would have been too small from about N=92. If no argument is given, N defaults to 0.
