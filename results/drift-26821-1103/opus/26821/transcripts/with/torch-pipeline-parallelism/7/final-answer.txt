I created `pipeline_parallel.py`. In my test, its gradients and loss matched a normal, non-parallel model exactly with 1 and 2 ranks.

**How it works:**
- **Splitting the layers:** the decoder layers are divided as evenly as possible across ranks. If they don't divide evenly, the first ranks get one extra layer. Rank 0 also runs the input embedding, and the last rank runs the final norm, the output head and the loss.
- **Forward:** every microbatch goes forward before any goes backward.
  - Rank 0 turns the input IDs into hidden states.
  - Other ranks receive a `[microbatch, seq_len, hidden_size]` tensor from the previous rank and mark it as needing gradients.
  - Each rank builds the causal mask and rotary position embeddings the same way `LlamaModel.forward` does, then runs its layers.
  - Middle ranks send their output to the next rank.
  - The last rank computes `cross_entropy` divided by the number of microbatches.
- **Backward:** the last rank calls `backward()` on each microbatch's loss. Other ranks receive the gradient from the next rank and run `torch.autograd.backward(output, grad)`. Every rank except rank 0 sends the gradient of its input back to the previous rank.
- **Communication:** sends and receives use `torch.distributed.P2POp` with `batch_isend_irecv`. Hidden states and gradients are moved to `device` and `dtype` before sending; input IDs are moved to `device` only, since they have to stay integers for the embedding lookup.
- **No hooks:** the layers are called directly, so any hooks the test registers on them still fire.
- **Return value:** the last rank returns the summed scaled loss, which equals the mean loss over the batch. Other ranks return `None`. The task didn't specify a return value, so this was my choice.

**Testing:** I used a 5-layer model, 4 microbatches, the Gloo backend, and both the `sdpa` and `eager` attention modes.
- With 2 ranks, rank 0 ran layers 0–2 and rank 1 ran layers 3–4, each once per microbatch.
- Every parameter gradient matched the reference model exactly (difference 0), and the loss matched to floating-point precision (4.8747).
