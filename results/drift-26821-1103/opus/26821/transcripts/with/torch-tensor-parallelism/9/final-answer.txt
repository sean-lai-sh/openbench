I created `parallel_linear.py` and tested it with the gloo backend at world sizes 1, 2 and 4. On every rank, the outputs, input gradients, and weight and bias gradients matched a regular `nn.Linear` (compared against that rank's slice where the parameter is split).

**How it works:**
- **Weight layout:** `master_weight` is expected in the same shape `nn.Linear` uses, `(out_features, in_features)`. Each rank copies out its own slice.
- **`ColumnParallelLinear`:** each rank keeps its share of the output rows of `master_weight` (dim 0). The bias is sharded the same way, with `out_features / world_size` entries per rank, all set to zero. Each rank computes its part of the output, and an all-gather joins the parts along the last dimension.
- **`RowParallelLinear`:** each rank keeps its share of the input columns of `master_weight` (dim 1). The bias is full size (`out_features`) on every rank and set to zero. The partial outputs are summed with all-reduce, and the bias is added once, after the sum.
- **Gradients:** small custom autograd functions handle the communication in the backward pass:
  - All-gather in the forward pass becomes a split in the backward pass.
  - All-reduce in the forward pass becomes an identity in the backward pass.
  - The input to the column layer is all-reduced in the backward pass, so each rank gets the full input gradient.

**Things you might not expect:**
- `RowParallelLinear` accepts either the full input (last dimension = `in_features`), which it splits itself, or an input that is already split (last dimension = `in_features / world_size`).
- `in_features` and `out_features` must divide evenly by `world_size`; otherwise construction fails with an assertion error.
- If `torch.distributed` hasn't been initialized, the layers act as world size 1.
