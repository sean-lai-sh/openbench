**Where `rate` becomes None:** `app/pricing.py:8` runs `return SETTINGS.get("rate")`. That key isn't in the settings, so `.get` returns `None` instead of raising an error. The `None` then reaches `app/report.py:9`, where multiplying it by the count crashes.

**Which key was missing:** `"rate"`. When I continued the same subagent session, it confirmed that `settings.json:2` spelled the key `"rat"`.

**Fix:** I renamed `"rat"` to `"rate"` in `settings.json`.

The code still uses `.get`, so a missing key fails silently. If you'd like an early, clear error instead, `pricing.py` could use `SETTINGS["rate"]`, which raises a `KeyError` right at the lookup. I didn't make that change.
