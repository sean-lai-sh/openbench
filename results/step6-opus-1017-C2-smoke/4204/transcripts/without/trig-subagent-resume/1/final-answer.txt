I fixed the bug. `python3 main.py` now prints `Total: 5.0` and exits with code 0.

**Where `rate` becomes None (from the subagent):** `app/pricing.py:8` runs `SETTINGS.get("rate")`. The settings file has no `"rate"` key, so `.get()` quietly returns `None`. Then `app/report.py:9` tries to calculate `None * 10` and crashes.

**Missing settings key:** `"rate"`. In `settings.json` line 2 it was misspelled as `"rat"`.

**The second task call didn't happen.** The task tool didn't return an id, and it has no way to resume an earlier subagent. So I couldn't send the follow-up question to the same one. Its first report had already named the missing key, and I checked that in the file myself.

**Fix:** In `settings.json`, I renamed `"rat"` to `"rate"`.

Optionally, `get_rate()` could use `SETTINGS["rate"]` instead. Then a missing key would fail right away with a clear `KeyError` instead of passing `None` along. I didn't make that change.
