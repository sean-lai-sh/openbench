## Actual vs. expected output
- **Actual:** `Total: 0`

- **How I got 5.0:** `main.py` computes `total = rate * COUNT` with `COUNT = 10` (`main.py:5`). The only rate in `settings.json` is `0.5`, so 0.5 × 10 = 5.0.

## Root cause
**Main problem: `settings.json:2`**
```json
  "rat": 0.5,
```
The key is spelled `"rat"`, but every piece of code that reads it looks for `"fee_rate"`:
- `main.py:11`: `rate = cfg["fee_rate"]`
- `billing/report.py:7`
- `billing/export/csv_writer.py:8`

**What hides it: `main.py:10-13`**
```python
    try:
        rate = cfg["fee_rate"]
    except KeyError:
        rate = 0
```

## Why it gives the wrong result
1. `app/config.py:9-10` loads `settings.json` into `SETTINGS`, so it contains `{"rat": 0.5, "currency": "USD", "label": "Total"}`.
2. `main.py:11` asks for `"fee_rate"`, which isn't there, so Python raises `KeyError`.
3. The `except KeyError` block sets `rate = 0` instead of reporting the error.
4. So `total = 0 * 10 = 0`, and the program prints `Total: 0` as if nothing went wrong.

The other two scripts that read this key (`billing/report.py` and `billing/export/csv_writer.py`) handle a missing key by stopping with `"fee_rate is missing"`, so they fail loudly. Only `main.py` turns the missing key into a wrong total. The other matches for "fee" in `billing/` (`invoice.py`, `tax.py`, `audit.py`, `discount.py`) are unrelated and not involved.
