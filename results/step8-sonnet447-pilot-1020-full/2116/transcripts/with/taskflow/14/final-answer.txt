`python3 -m unittest` now passes: 25 tests, no failures. I didn't touch the tests. There were six root-cause defects in the code under `taskflow/`.

- **`queue.py`:** `_Entry.sort_key` was `(seq, -priority)`. It's now `(-priority, seq)`, so higher priority goes first and insertion order only breaks ties.
- **`retry.py`:** `should_retry` was `attempts_made < max_attempts - 1`. It's now `< max_attempts`, which gives `max_attempts` total attempts.
- **`statemachine.py`:** `batch_order_ok` had its comparison reversed (`>=`). It's now `current_priority <= prev_priority`, matching the "non-increasing priority within a batch" rule. With the queue bug fixed, the old check would have failed runs as soon as the second one was admitted.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`. Multi-unit tasks leaked capacity and stalled the resource tests.
- **`events.py`:** `_prefix_matches` tested `prefix.startswith(topic + ".")`, which is backwards. It's now `topic.startswith(prefix + ".")`. This was why `History` never saw `job.term.*` events, so its failed, skipped and outcome-count queries came back empty.
- **`config.py`:** `deep_merge` recursed with its arguments swapped (`deep_merge(value, result[key])`). That let the defaults override a task's own `retry` settings. It now calls `deep_merge(result[key], value)`.

I made one more change in `scheduler.py`. `_cascade_skip` used `dag.dependents`, which returns direct children only. It now uses `dag.transitive_dependents`, so tasks further downstream of a failure are skipped too, as the docstring says.
