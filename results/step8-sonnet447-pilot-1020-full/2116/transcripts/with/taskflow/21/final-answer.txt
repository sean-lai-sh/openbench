`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. I found seven root causes, and several of them were behind failures that looked unrelated:

- **`queue.py`**: the sort key was `(seq, -priority)`, so insertion order beat priority. It is now `(-priority, seq)`.
- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which was off by one. It is now `attempts_made < max_attempts`. This was behind the retry failures in the pipeline tests.
- **`events.py`**: `_prefix_matches` had the `startswith` arguments reversed. It now checks `topic.startswith(prefix + ".")`. This was behind the `history` outcome sets missing skipped jobs.
- **`statemachine.py`**: `batch_order_ok` required priority to be non-decreasing within a batch. The docstring says non-increasing, so it now checks `current <= prev`.
- **`config.py`**: `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own values. This is why a task's `retry` override was ignored.
- **`resources.py`**: `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Multi-unit resource costs leaked capacity, so later tasks never got admitted.
- **`scheduler.py`**: `_cascade_skip` used the direct `dag.dependents`. It now uses `transitive_dependents`, so a permanent failure skips everything downstream, not just the direct children.
