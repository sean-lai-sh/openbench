`python3 -m unittest` now passes all 25 tests. I fixed seven bugs, and I didn't touch the tests.

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so the queue ignored priority and ran in insertion order. It now returns `(-priority, seq)`.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` checked `prefix.startswith(topic + ".")`, which is backwards. It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing within an admission batch. It now requires non-increasing, as its docstring says.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. That leaked capacity, and tasks that needed resources never ran.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own retry settings. It now recurses with `(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children, so skips stopped one level down. It now uses `dag.transitive_dependents`.

I stopped once the suite was green. I didn't audit the modules the tests don't touch, such as `history.py`, `stats.py` and `filters.py`, so defects could remain there.
