`python3 -m unittest` now passes all 25 tests. I fixed seven defects and didn't touch the tests.

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison backwards. It now requires `current <= prev`, i.e. non-increasing priority within a batch.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Pools leaked capacity, so resource-limited runs never finished.
- **`config.py`:** `deep_merge` swapped its arguments when recursing, so the defaults overrode the task's own values. It now recurses as `deep_merge(result[key], value)`.
- **`events.py`:** `_prefix_matches` tested `prefix.startswith(topic + ".")`, the wrong way round. It now tests `topic.startswith(prefix + ".")`. That is why `History` never received the `job.term.*` events.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so every downstream task is skipped.
