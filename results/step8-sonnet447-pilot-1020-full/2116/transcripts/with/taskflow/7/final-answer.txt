`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. There were six root-cause defects:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority runs first and ties go in insertion order.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which stopped one attempt short. It now uses `attempts_made < max_attempts`. This was the cause of the retry failures in the pipeline tests.
- **`events.py`:** `_prefix_matches` had the arguments reversed (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing, but the docstring says non-increasing. It now checks `current_priority <= prev_priority`. The queue ordering fix exposed this one, because the guard was failing correctly ordered batches.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Multi-unit releases leaked capacity, which caused the resource tests to deadlock.
- **`config.py`:** `deep_merge` recursed with the base and override swapped, so defaults overrode task settings. The recursion is now `deep_merge(result[key], value)`.

I also changed the failure cascade in `scheduler.py`. `_cascade_skip` only skipped direct dependents. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped. That fixed the skip-chain, diamond and history-count tests.
