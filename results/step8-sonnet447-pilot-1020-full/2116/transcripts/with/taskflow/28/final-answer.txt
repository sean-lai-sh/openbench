`python3 -m unittest` now passes: all 25 tests. I didn't touch the tests. There were seven bugs, all in the code under `taskflow/`:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which was off by one. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison backwards. Within an admission batch, priority must be non-increasing, so it now checks `current_priority <= prev_priority`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own values. It now calls `deep_merge(result[key], value)`.
- **`resources.py`:** `ResourcePool.release` subtracted `1` instead of `cost`, which left pools stuck full and blocked later tasks.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.
- **`events.py`:** `_prefix_matches` had the prefix test reversed. It now checks `topic.startswith(prefix + ".")`. Before this, `History` never received the `job.term.*` events, so its failed, skipped and outcome-count queries came back empty.

Several of the pipeline test failures traced back to the same few causes, such as the retry, queue and resource bugs.
