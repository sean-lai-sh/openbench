`python3 -m unittest` now passes: all 25 tests, with no test files changed. There were seven bugs, each fixed with a one-line change:

- **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave one attempt too few. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`**: `batch_order_ok` had its comparison reversed. It now requires `current_priority <= prev_priority`, matching the "non-increasing priority within a batch" rule. With the queue ordering bug in place, this guard was failing jobs outright.
- **`config.py`**: `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own values. It now merges `(result[key], value)`.
- **`events.py`**: `_prefix_matches` had its operands reversed, so a prefix subscription to `job.term` never matched `job.term.failed`. That left the history's failed, skipped and succeeded sets empty. It now checks `topic.startswith(prefix + ".")`.
- **`scheduler.py`**: `_cascade_skip` used the direct `dag.dependents`. It now uses `dag.transitive_dependents`, so a permanent failure skips every downstream task, not just its direct children.
- **`resources.py`**: `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Pools never fully drained, which stalled the resource-limited pipelines.
