`python3 -m unittest` now passes: all 25 tests, with no test files changed. There were seven separate bugs:

- **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave one attempt too few. It is now `attempts_made < max_attempts`.
- **`events.py`**: `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`, so `job.term` subscribers receive `job.term.failed` and the other terminal events.
- **`statemachine.py`**: `batch_order_ok` required priorities to be non-decreasing within an admission batch, the opposite of what its docstring says. It now requires `current <= prev`. Together with the queue fix, this stopped valid dispatches from being failed outright.
- **`resources.py`**: `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Multi-unit tasks leaked capacity, which stalled resource-limited runs.
- **`config.py`**: `deep_merge` recursed with its arguments swapped. Because of that, the defaults overrode a task's own `retry` settings.
- **`scheduler.py`**: `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so a permanent failure skips every downstream task.
