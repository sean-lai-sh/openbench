`python3 -m unittest` now passes all 25 tests. I didn't edit any tests. I fixed seven logic bugs:

- **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`, so insertion order beat priority. It now returns `(-priority, seq)`.
- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`. This one change fixed all the retry-related pipeline failures.
- **`events.py`**: `_prefix_matches` checked `prefix.startswith(topic + ".")`, which is backwards. It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`**: `batch_order_ok` required priorities to be non-decreasing within a batch. Its docstring says non-increasing, so it now checks `current_priority <= prev_priority`.
- **`resources.py`**: `ResourcePool.release` did `self.used -= 1` instead of subtracting `cost`. Pools never fully freed, which stalled the resource-limited pipelines.
- **`config.py`**: `deep_merge` passed its arguments to the recursive call in the wrong order, so defaults overrode task settings in nested blocks like `retry`. It now calls `deep_merge(result[key], value)`.
- **`scheduler.py`**: `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.

I didn't read `history.py` or the other modules the tests don't exercise, so there may be bugs there that the suite doesn't catch.
