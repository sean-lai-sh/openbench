`python3 -m unittest` now passes all 25 tests. I didn't modify any tests.

There were six root causes:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` required priority to be non-decreasing. After the queue fix, that guard would have failed the second task in any batch with mixed priorities. It now requires non-increasing priority, as its docstring says.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own `retry` values. It now recurses as `deep_merge(base_child, override_child)`.
- **`scheduler.py`:** `_cascade_skip` walked only the direct dependents of a failed task. It now uses `dag.transitive_dependents`, so everything downstream is skipped.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`. Multi-unit tasks leaked capacity and later tasks never ran.
- **`events.py`:** `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). `History` therefore never received the `job.term.*` events, which left `failed_jobs()` and `outcome_counts()` empty.
