`python3 -m unittest` now passes all 25 tests. I didn't touch the tests.

There were seven defects, in these files:

- **`queue.py`:** `_Entry.sort_key` sorted by `(seq, -priority)`. It now sorts by `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which was off by one. It now uses `attempts_made < max_attempts`, which makes retries and the attempt counts come out right.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of the released cost. It now subtracts `cost`, which fixes the resource tests.
- **`events.py`:** `_prefix_matches` had its arguments backwards. It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` accepted ascending priority. It now requires `current <= prev`, as the docstring says.
- **`config.py`:** `deep_merge` recursed with the arguments swapped, so the base overrode the task's values. It now calls `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used the direct `dependents`, so only children were skipped. It now uses `transitive_dependents`, so every downstream task is skipped.
