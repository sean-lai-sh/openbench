`python3 -m unittest` now passes: 25 tests, all OK. I didn't modify any tests.

I found six defects, each a logic error in the code under `taskflow/`:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so insertion order beat priority. It now returns `(-priority, seq)`, as the docstring says.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` had the arguments reversed (`prefix.startswith(topic + ".")`). Prefix subscriptions like `job.term` therefore never matched `job.term.failed` and similar topics. It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing within an admission batch. The docstring says non-increasing, so it now returns `current <= prev`.
- **`resources.py`:** `ResourcePool.release` did `self.used -= 1` instead of `-= cost`. Multi-unit resource costs leaked, which blocked later admissions.
- **`scheduler.py`:** `_cascade_skip` used the direct `dag.dependents`, so only children were skipped. It now uses `transitive_dependents`, which skips every downstream task.
- **`config.py`:** `deep_merge` recursed as `deep_merge(value, result[key])`. That let the base values override the task's own, so a task's `retry.max_attempts` was lost. It now recurses as `deep_merge(result[key], value)`.
