`python3 -m unittest` now passes: all 25 tests, with no test files changed. There were six root-cause bugs, and fixing some of them uncovered others.

- **`queue.py`:** `_Entry.sort_key` ordered by `(seq, -priority)`. It now orders by `(-priority, seq)`, so higher priority goes first and FIFO breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which cut every retry budget short by one attempt. It is now `attempts_made < max_attempts`.
- **`resources.py`:** `ResourcePool.release` always subtracted 1 instead of `cost`. Multi-unit resource costs leaked, which blocked later admissions.
- **`events.py`:** `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`, so prefix subscribers see the whole subtree.
- **`statemachine.py`:** `batch_order_ok` required priority to be non-decreasing within an admission batch. The docstring and the queue ordering say non-increasing, so it is now `current_priority <= prev_priority`. Without this fix, the first three fixes above would have exposed this guard failing the run.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own values. A task's `retry.max_attempts` was being replaced by the default.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents` (direct children only). It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.
