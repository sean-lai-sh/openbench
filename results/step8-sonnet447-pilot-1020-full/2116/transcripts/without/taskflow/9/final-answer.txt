`python3 -m unittest` now passes: all 25 tests, with no test files changed. There were eight separate defects:

- **`queue.py`:** `_Entry.sort_key` sorted by `(seq, -priority)`. It now sorts by `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`, matching the docstring. This is what broke all the retry pipeline tests.
- **`events.py`:** `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). It now uses `topic.startswith(prefix + ".")`, so `job.term` subscribers receive `job.term.failed` and `job.term.skipped`. This is why the history's skipped and failed sets came back wrong.
- **`statemachine.py`:** `batch_order_ok` required priority to be non-decreasing within an admission batch. Once the queue was fixed, that made the scheduler fail correctly ordered tasks outright. It now requires `current <= prev`, as the docstring says.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`, so multi-unit resource costs were never fully returned.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so defaults overrode the task's own values. It now recurses as `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used direct `dependents`. It now uses `transitive_dependents`, so a permanent failure skips every downstream task, not just the direct children.
