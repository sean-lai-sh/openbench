All 25 tests now pass. I fixed seven bugs, each in the module whose docstring described the behavior the code didn't have:

- **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority dispatches first and insertion order breaks ties.
- **`retry.py`**: `should_retry` had an off-by-one (`attempts_made < max_attempts - 1`). It now uses `attempts_made < max_attempts`.
- **`statemachine.py`**: `batch_order_ok` required priority to be non-decreasing, but its docstring says non-increasing. I flipped the comparison to `current <= prev`. This guard would have started failing runs once the queue order was fixed.
- **`resources.py`**: `ResourcePool.release` did `used -= 1` instead of `used -= cost`, which leaked capacity for any task costing more than 1.
- **`events.py`**: `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`.
- **`scheduler.py`**: `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so a permanent failure skips the whole downstream chain.
- **`config.py`**: `deep_merge` recursed with its arguments swapped, so the base overrode the task's own values. For example, a task's `retry.max_attempts` was lost. It now recurses with the base first and the override second.
