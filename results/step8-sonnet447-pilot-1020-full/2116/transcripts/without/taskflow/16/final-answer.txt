`python3 -m unittest` now reports all 25 tests passing. I didn't touch the tests, and I didn't read the modules the suite doesn't exercise (e.g. `history.py`), so any bugs there are undetected.

There were six bugs, fixed in these places:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and ties go in FIFO order.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave one retry too few. It now uses `attempts_made < max_attempts`, so three attempts allowed means retries after attempts 1 and 2.
- **`events.py`:** `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` required priority to be non-decreasing within an admission batch. The docstring says non-increasing, so it now returns `current_priority <= prev_priority`.
- **`resources.py`:** `ResourcePool.release` did `self.used -= 1` instead of subtracting `cost`. Multi-unit releases leaked capacity, which stalled resource-limited runs.
- **`config.py`:** `deep_merge` recursed as `deep_merge(value, result[key])`, which swapped base and override in nested dicts. A task's `retry` override was losing to the defaults. The arguments are now in the right order.

I also found one bug the tests exposed once the others were fixed. `Scheduler._cascade_skip` in `scheduler.py` used `dag.dependents()`, which returns only direct children. It now uses `dag.transitive_dependents()`, so a permanent failure skips everything downstream.
