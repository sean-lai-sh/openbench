`python3 -m unittest` now passes: 25 tests, all OK. I didn't change any tests. I stopped once the suite was green and did not review the rest of the package for other defects.

There were seven defects. Several showed up under tests for a different module than the one with the bug.

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave one retry too few. It now uses `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`, so a prefix subscription receives its whole subtree.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing, but its docstring says non-increasing. I changed it to `current_priority <= prev_priority`.
- **`resources.py`:** `ResourcePool.release` always subtracted 1 instead of `cost`. Pools never fully freed up, which stalled the resource-limited runs.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so defaults overrode the task's own settings. It now recurses with `(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so a permanent failure skips everything downstream.
