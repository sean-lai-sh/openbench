`python3 -m unittest` now passes: all 25 tests, with no test changes. There were seven defects, in these files:

- **`taskflow/retry.py`**: `should_retry` was off by one. It stopped retrying one attempt early, so `max_attempts=3` allowed only two attempts. It now returns `attempts_made < max_attempts`.
- **`taskflow/queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`. That made the queue FIFO and ignored priority. It now returns `(-priority, seq)`.
- **`taskflow/resources.py`**: `ResourcePool.release` subtracted 1 instead of `cost`. Multi-unit costs leaked capacity, which made the resource-limited pipelines stall.
- **`taskflow/statemachine.py`**: `batch_order_ok` had its comparison reversed. It now accepts non-increasing priority within an admission batch, as its docstring says.
- **`taskflow/config.py`**: `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own values. A task's `retry.max_attempts` was being replaced by the default of 1.
- **`taskflow/events.py`**: `_prefix_matches` tested `prefix.startswith(topic + ".")`, the wrong way round. `History` never saw `job.term.*` events, so its failed/skipped lists and outcome counts came back empty. It now tests `topic.startswith(prefix + ".")`.
- **`taskflow/scheduler.py`**: `_cascade_skip` used `dag.dependents`, which returns direct children only. It now uses `transitive_dependents`, so a permanent failure skips every downstream task.

I didn't look for defects beyond what the tests exercise.
