`python3 -m unittest` now passes: 25 tests run, all OK. I didn't modify any tests. There were seven defects across seven modules:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so the queue ordered by insertion first. It now returns `(-priority, seq)`, which gives highest priority first with FIFO as the tie-break.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which was off by one and gave a task one fewer retry than its budget allowed. It now uses `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` had its operands swapped (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`, so prefix subscriptions match their subtree.
- **`statemachine.py`:** `batch_order_ok` required priority to be non-decreasing within an admission batch, the opposite of what its docstring says. It now requires non-increasing priority.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of subtracting the cost. Multi-unit resources leaked capacity and later tasks were never admitted.
- **`scheduler.py`:** `_cascade_skip` iterated over the direct dependents only. It now uses `transitive_dependents`, so a permanent failure skips every task downstream of it.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own `retry` settings. It now recurses as `deep_merge(result[key], value)`.
