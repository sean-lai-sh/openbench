`python3 -m unittest` now passes all 25 tests. I didn't touch the tests, and I didn't read the modules the tests don't exercise.

I found seven defects, each in a different place:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so the queue ran in insertion order. It now returns `(-priority, seq)`, which gives priority first and FIFO within a priority.
- **`retry.py`:** `should_retry` was off by one (`attempts_made < max_attempts - 1`), so a task with 3 attempts got only 2. It now uses `attempts_made < max_attempts`. This one caused most of the retry and pipeline failures.
- **`events.py`:** `_prefix_matches` had its arguments reversed, so prefix subscriptions never matched their subtree. It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing within an admission batch. The docstring says non-increasing, so it now requires `current <= prev`. With the queue ordering fixed, the old check would have failed every mixed-priority batch.
- **`config.py`:** `deep_merge` recursed with its arguments swapped (`deep_merge(value, result[key])`). That let the defaults override a task's own values, for example `retry.max_attempts`. It now calls `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so a permanent failure skips everything downstream.
- **`resources.py`:** `ResourcePool.release` always subtracted 1 instead of `cost`. Pools never fully freed, so resource-limited tasks stalled. It now subtracts `cost`.
