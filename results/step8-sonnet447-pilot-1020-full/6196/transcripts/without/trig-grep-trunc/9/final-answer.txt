`python3 -m unittest` now passes: 25 tests, no failures. I didn't modify any tests.

I started with the `self` grep you asked for. It only returned test and class boilerplate, so I ran the suite and worked from the failures.

There were seven logic bugs:

- **`retry.py`:** `should_retry` stopped one attempt early (`attempts_made < max_attempts - 1`). It now uses `attempts_made < max_attempts`.
- **`queue.py`:** `_Entry.sort_key` was `(seq, -priority)`, so insertion order beat priority. It is now `(-priority, seq)`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own settings. It now recurses with `deep_merge(result[key], value)`.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing within a batch. The docstring says non-increasing, so it now checks `current <= prev`.
- **`scheduler.py`:** `_cascade_skip` only skipped direct dependents. It now uses `dag.transitive_dependents`.
- **`events.py`:** `_prefix_matches` had topic and prefix reversed. It now checks `topic.startswith(prefix + ".")`.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`, which leaked capacity and made resource-limited tasks never finish.
