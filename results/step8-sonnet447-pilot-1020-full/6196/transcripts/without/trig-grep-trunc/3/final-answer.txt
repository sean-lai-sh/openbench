`python3 -m unittest` now passes all 25 tests. I didn't modify any tests. I found and fixed seven bugs, and some were hidden behind others:

- **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave one retry too few. It now uses `attempts_made < max_attempts`.
- **`config.py`**: `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own `retry` settings. The arguments are now in the right order.
- **`resources.py`**: `ResourcePool.release` subtracted 1 instead of `cost`, which leaked capacity on multi-unit tasks.
- **`statemachine.py`**: `batch_order_ok` had its comparison reversed. A batch is meant to be non-increasing in priority, but the check demanded non-decreasing. This was failing correctly ordered dispatches outright.
- **`scheduler.py`**: `_cascade_skip` only skipped direct dependents. It now uses `dag.transitive_dependents`, so the whole downstream chain is skipped.
- **`events.py`**: `_prefix_matches` tested `prefix.startswith(topic + ".")`, which is backwards. It now tests `topic.startswith(prefix + ".")`. This had stopped `History` from recording any terminal outcomes.
