`python3 -m unittest` now passes: 25 tests, all OK. I fixed seven logic bugs and didn't touch the tests.

- **`taskflow/queue.py`:** `_Entry.sort_key` now returns `(-priority, seq)`. It had the fields swapped, so the queue ran in insertion order and ignored priority.
- **`taskflow/retry.py`:** `should_retry` now returns `attempts_made < max_attempts`. It had an off-by-one that gave up one attempt early.
- **`taskflow/config.py`:** `deep_merge` now recurses as `deep_merge(result[key], value)`. The arguments were swapped, so the defaults overrode the task's own settings.
- **`taskflow/resources.py`:** `ResourcePool.release` now does `used -= cost`. It was decrementing by 1, so multi-unit costs were never fully returned and later tasks were blocked.
- **`taskflow/statemachine.py`:** `batch_order_ok` now requires `current <= prev`. The comparison was inverted, so the scheduler's guard rejected a normal batch and failed the run.
- **`taskflow/scheduler.py`:** `_cascade_skip` now uses `dag.transitive_dependents`. It used direct dependents only, so grandchildren stayed `PENDING` instead of being skipped.
- **`taskflow/events.py`:** `_prefix_matches` now uses `topic.startswith(prefix + ".")`. The operands were reversed, so `job.term` prefix subscribers never received `job.term.failed` and similar. This left the history's failed, skipped and succeeded sets empty.

The failures were mostly in `test_pipelines.py`, but the causes were in the lower-level modules. Fixing them in order exposed the later ones. The last three failing tests were all the `events.py` bug.
