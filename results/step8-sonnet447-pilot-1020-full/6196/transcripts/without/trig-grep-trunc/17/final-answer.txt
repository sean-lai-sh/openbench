I started with the grep for `self` you asked for. It hit the 100-match cap and mostly returned test files, so I ran the suite and read the failing modules instead.

I fixed eight bugs, each of which contradicted what its own docstring says:

1. **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It is now `attempts_made < max_attempts`.
2. **`queue.py`**: `_Entry.sort_key` was `(seq, -priority)`, so the queue ignored priority and ran in FIFO order. It is now `(-priority, seq)`.
3. **`config.py`**: `deep_merge` recursed with its arguments swapped, so the base value overrode the task's own value in nested dicts like `retry`. It now recurses as `deep_merge(result[key], value)`.
4. **`statemachine.py`**: `batch_order_ok` required priorities within an admission batch to be non-decreasing. It now requires non-increasing, as the docstring says. This guard was making the scheduler mark correctly ordered runs as FAILED.
5. **`scheduler.py`**: `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so every downstream task is skipped.
6. **`events.py`**: `_prefix_matches` checked `prefix.startswith(topic + ".")`, which is backwards. It is now `topic.startswith(prefix + ".")`. Before this fix, `History` never received the `job.term.*` events.
7. **`resources.py`**: `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Any task with a cost above 1 leaked capacity, which blocked resource-limited pipelines.
