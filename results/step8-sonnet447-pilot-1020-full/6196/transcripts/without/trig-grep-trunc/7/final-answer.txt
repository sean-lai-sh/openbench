All 25 tests now pass with `python3 -m unittest`. I didn't modify any tests. As you suggested, I started with a grep for `self`. That matched too many lines to help, so I worked from the failing tests instead.

I fixed eight bugs. Each one is a one-line change.

- **`queue.py`:** `_Entry.sort_key` ordered by `(seq, -priority)`. It now orders by `(-priority, seq)`, so higher priority runs first and ties go in insertion order.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`. That is off by one, so a task with `max_attempts == 3` got only two attempts. It now uses `attempts_made < max_attempts`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own settings. It now merges in the right order.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. That leaked capacity and stalled the resource-limited pipelines.
- **`statemachine.py`:** `batch_order_ok` used `>=`, but its docstring and the scheduler need non-increasing priority within a batch. It now uses `<=`. Before this, the guard failed any task admitted after another one in the same batch.
- **`scheduler.py`:** `_cascade_skip` used the direct dependents. It now uses `dag.transitive_dependents`, so a failure skips everything downstream.
- **`events.py`:** `_prefix_matches` checked `prefix.startswith(topic + ".")`, which is backwards. It now checks `topic.startswith(prefix + ".")`. `History` had never received `job.term.*` events, which is why the history tests failed.
