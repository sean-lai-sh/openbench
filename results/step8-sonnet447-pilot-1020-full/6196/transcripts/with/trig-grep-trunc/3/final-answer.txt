`python3 -m unittest` now passes all 25 tests. I didn't modify any tests. I made eight one-line fixes in six files.

I began with the `self` grep you asked for. It matched far too much to be useful (the output was truncated at 100 matches), so I moved on to running the suite.

- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It is now `attempts_made < max_attempts`.
- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so the queue ignored priority. It now returns `(-priority, seq)`.
- **`statemachine.py`:** `batch_order_ok` had its comparison reversed. It now requires non-increasing priority, as the docstring says.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`, so resource pools never fully freed.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own retry settings.
- **`scheduler.py`:** `_cascade_skip` skipped only direct dependents, not transitive ones. It now uses `dag.transitive_dependents`.
- **`events.py`:** `_prefix_matches` tested `prefix.startswith(topic + ".")` instead of `topic.startswith(prefix + ".")`. Prefix subscribers therefore never received `job.term.*` events, and the history's failed, skipped and succeeded sets stayed empty.
