`python3 -m unittest` now passes: 25 tests, all OK. I didn't modify any tests. The suite was failing because of seven separate logic bugs:

- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, so it stopped one attempt early. It now uses `attempts_made < max_attempts`.
- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so insertion order beat priority. It now returns `(-priority, seq)`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the base overrode the task's own values. It now recurses as `deep_merge(result[key], value)`.
- **`statemachine.py`:** `batch_order_ok` had its comparison inverted (`>=`). Once the queue ordering was fixed, this would have wrongly failed jobs during admission. It now uses `<=`.
- **`scheduler.py`:** `_cascade_skip` used the direct `dependents`, so only immediate children were skipped. It now uses `transitive_dependents`.
- **`resources.py`:** `ResourcePool.release` did `self.used -= 1` instead of subtracting `cost`. Pools with a cost above 1 never freed fully, which stalled the resource tests.
- **`events.py`:** `_prefix_matches` had `prefix.startswith(topic + ".")` backwards. The `job.term` prefix subscription therefore never matched `job.term.failed` and the other terminal topics, which left the history's outcome sets empty. It now uses `topic.startswith(prefix + ".")`.
