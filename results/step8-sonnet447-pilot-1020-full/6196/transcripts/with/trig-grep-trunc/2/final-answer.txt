`python3 -m unittest` now passes all 25 tests. I didn't edit any tests. The failures traced back to seven defects:

1. **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave one attempt too few. It is now `< max_attempts`.
2. **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so the queue ignored priority. It now returns `(-priority, seq)`.
3. **`config.py`:** `deep_merge` recursed with its arguments swapped, so defaults overrode a task's own `retry` settings. It now recurses with `(base, override)`.
4. **`statemachine.py`:** `batch_order_ok` checked `current >= prev`, the opposite of the non-increasing-priority rule in its docstring. It now checks `current <= prev`.
5. **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so a failure skips the whole downstream chain.
6. **`events.py`:** `_prefix_matches` had its operands reversed (`prefix.startswith(topic + ".")`). Prefix subscriptions like `job.term` never received `job.term.failed` or the other terminal events, so the history's outcome lists stayed empty. It now uses `topic.startswith(prefix + ".")`.
7. **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Multi-unit resources leaked capacity and tasks stalled.
