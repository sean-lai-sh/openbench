All 25 tests now pass with `python3 -m unittest`. I didn't modify any tests.

My first `grep` for `self` was too broad. It matched everywhere and got truncated at 100 results, so I got nothing useful from it and went straight to the failing tests.

I fixed seven logic bugs:

- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so the queue ignored priority and ran in insertion order. It now returns `(-priority, seq)`.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Pools leaked capacity, so resource-limited runs stalled.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own `retry` settings. It now recurses with `(result[key], value)`.
- **`statemachine.py`:** `batch_order_ok` had its comparison backwards. It required priorities to be non-decreasing within an admission batch, which is the opposite of what its docstring says.
- **`scheduler.py`:** `_cascade_skip` only skipped direct dependents. It now uses `transitive_dependents`, so skips reach the whole downstream chain.
- **`events.py`:** `_prefix_matches` checked `prefix.startswith(topic + ".")`, which is the wrong way round. It now checks `topic.startswith(prefix + ".")`. Before this, `History` never received the `job.term.*` events, so its failed, skipped and outcome-count queries came back empty.
