`python3 -m unittest` now passes all 25 tests. I didn't modify any tests.

I fixed these seven defects:

1. **`taskflow/queue.py`:** The sort key was `(seq, -priority)`, so tasks came out in insertion order and priority never counted. It is now `(-priority, seq)`, as the docstring says.
2. **`taskflow/retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It is now `attempts_made < max_attempts`.
3. **`taskflow/config.py`:** `deep_merge` recursed with its arguments swapped (`deep_merge(value, result[key])`), so the pipeline defaults overrode a task's own settings. It is now `deep_merge(result[key], value)`.
4. **`taskflow/statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing within a batch. Its docstring says non-increasing, so I flipped the comparison to `current_priority <= prev_priority`.
5. **`taskflow/scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children, so a failure skipped only the first level. It now uses `dag.transitive_dependents`.
6. **`taskflow/events.py`:** `_prefix_matches` had the `startswith` check reversed (`prefix.startswith(topic + ".")`). `History` therefore never received `job.term.*` events. It is now `topic.startswith(prefix + ".")`.
7. **`taskflow/resources.py`:** `ResourcePool.release` did `self.used -= 1` instead of subtracting the cost. A task costing 2 left units held, and the resource-limited tasks stalled. It now does `self.used -= cost`.

I didn't use the search results that the `self` grep returned. That pattern matches almost every method in the project, so I ran the suite and traced each failure instead.
