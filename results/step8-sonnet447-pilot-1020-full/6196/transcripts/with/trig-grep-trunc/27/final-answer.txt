All 25 tests now pass with `python3 -m unittest`. I didn't touch the tests. The grep for `self` you asked me to start with was truncated at 100 matches and showed nothing useful, so I ran the suite and read the failures instead.

I found seven bugs and fixed each one:

1. **`retry.py`, `should_retry`:** it used `attempts_made < max_attempts - 1`, which gave up one attempt early. It is now `attempts_made < max_attempts`.
2. **`queue.py`, `_Entry.sort_key`:** the key was `(seq, -priority)`, so it ignored priority and ran in plain insertion order. It is now `(-priority, seq)`.
3. **`config.py`, `deep_merge`:** the recursive call had its arguments swapped, so defaults overrode the task's own values. It is now `deep_merge(result[key], value)`.
4. **`statemachine.py`, `batch_order_ok`:** the comparison was backwards. It rejected the normal non-increasing priority order and failed those runs. It now checks `current <= prev`.
5. **`scheduler.py`, `_cascade_skip`:** it skipped only the direct dependents of a failed task. It now uses `dag.transitive_dependents`, which matches the docstring.
6. **`events.py`, `_prefix_matches`:** the check was reversed (`prefix.startswith(topic + ".")`). `History` therefore never received `job.term.*` events. It is now `topic.startswith(prefix + ".")`.
7. **`resources.py`, `ResourcePool.release`:** it did `used -= 1` instead of `used -= cost`. Multi-unit resources were never fully released, which stalled the resource tests.

Some failures only showed up after earlier fixes. For example, the priority-order bug in the queue hid the inverted guard in the state machine, and the leaked resource units kept the resource tests failing until the last fix.
