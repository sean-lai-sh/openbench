`python3 -m unittest` now passes all 25 tests. I didn't modify any tests. The initial grep for `self` was truncated at 100 matches and didn't help, so I worked from the test failures instead.

I fixed seven defects across seven files, all under `taskflow/`:

- **`queue.py`:** The sort key was `(seq, -priority)`. It is now `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave one attempt too few. It is now `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` required priority to be non-decreasing within an admission batch. It now requires non-increasing, which matches its docstring and the queue's output order.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own nested `retry` and `resources` values. It now passes `(result[key], value)`.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Pools never fully freed, which stalled the resource tests.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents` (direct children only). It now uses `dag.transitive_dependents`, so a permanent failure skips everything downstream.
- **`events.py`:** `_prefix_matches` had the arguments reversed (`prefix.startswith(topic + ".")`). `History` never received `job.term.*` events, which broke the failed, skipped and outcome-count queries. It is now `topic.startswith(prefix + ".")`.

Some of these were masked by others, as the task warned. For example, the retry-count failures only got past the `should_retry` fix once the queue and resource bugs were fixed.
