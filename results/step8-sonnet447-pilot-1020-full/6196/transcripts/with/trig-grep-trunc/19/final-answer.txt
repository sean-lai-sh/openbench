`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. There were seven root-cause bugs, each fixed in the module where it lived:

- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave one attempt too few. It is now `attempts_made < max_attempts`.
- **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`, so the queue ignored priority. It now returns `(-priority, seq)`.
- **`config.py`**: `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own settings. It now recurses as `deep_merge(result[key], value)`.
- **`resources.py`**: `ResourcePool.release` did `used -= 1` instead of subtracting `cost`. Multi-unit tasks leaked capacity and blocked later tasks.
- **`statemachine.py`**: `batch_order_ok` had its comparison backwards (`>=` instead of `<=`). Once the queue ordered correctly, the guard rejected valid dispatches and failed those jobs.
- **`scheduler.py`**: `_cascade_skip` used `dag.dependents` (direct children only) instead of `dag.transitive_dependents`, so skips didn't reach grandchildren.
- **`events.py`**: `_prefix_matches` tested `prefix.startswith(topic + ".")`, the wrong way round. `job.term.*` events never reached `History`, so its failed, skipped and succeeded lists stayed empty.
