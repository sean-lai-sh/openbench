`python3 -m unittest` now passes: all 25 tests, with no test files changed. There were seven bugs, all in the code under `taskflow/`:

1. **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority dispatches first and equal priorities stay FIFO.
2. **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which was off by one. It now uses `attempts_made < max_attempts`.
3. **`resources.py`**: `ResourcePool.release` did `used -= 1` instead of `used -= cost`, so multi-unit resources leaked.
4. **`statemachine.py`**: `batch_order_ok` had its comparison inverted (`>=`). It now returns `current_priority <= prev_priority`, matching the non-increasing-priority rule in its docstring.
5. **`config.py`**: `deep_merge` recursed with its arguments swapped, so the pipeline defaults overrode a task's own values. A task's `retry` override was lost this way. It now merges the task's values over the defaults.
6. **`scheduler.py`**: `_cascade_skip` only skipped direct dependents. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.
7. **`events.py`**: `_prefix_matches` had the prefix test backwards (`prefix.startswith(topic + ".")`). It now uses `topic.startswith(prefix + ".")`, so `job.term` subscribers receive `job.term.failed` and the other terminal events. That fixed the empty history outcome sets.
