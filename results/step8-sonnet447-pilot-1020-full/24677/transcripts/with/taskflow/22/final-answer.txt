All 25 tests now pass with `python3 -m unittest`. I fixed seven defects in `taskflow/` and didn't touch the tests.

1. **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so the queue ordered by insertion first and priority second. It now returns `(-priority, seq)`.
2. **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
3. **`statemachine.py`:** `batch_order_ok` had its comparison reversed. Once the queue ordering was fixed, it would have rejected valid dispatches and failed those runs. It now requires `current_priority <= prev_priority`.
4. **`config.py`:** `deep_merge` recursed as `deep_merge(value, result[key])`, which swapped the arguments so the defaults overrode the task's own settings. It now calls `deep_merge(result[key], value)`.
5. **`events.py`:** `_prefix_matches` checked `prefix.startswith(topic + ".")` instead of `topic.startswith(prefix + ".")`. Prefix subscribers such as `History`'s `job.term` subscription never received any events.
6. **`scheduler.py`:** `_cascade_skip` iterated `dag.dependents()`, which returns only direct children. It now uses `transitive_dependents()`, so a permanent failure skips everything downstream.
7. **`resources.py`:** `ResourcePool.release` did `self.used -= 1` instead of `self.used -= cost`. Multi-unit tasks leaked capacity and later tasks were never admitted.

Several of these hid one another. The resource-pool leak only showed up once the retry and priority fixes were in, and the queue fix exposed the reversed batch guard.
