`python3 -m unittest` now passes: 25 tests, no failures. I didn't modify any tests.

I found and fixed seven bugs, each a one-line logic error:

- **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority dispatches first and insertion order breaks ties.
- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`. It now uses `attempts_made < max_attempts`, matching its docstring. This also fixed the retry tests in `test_pipelines.py`.
- **`config.py`**: `deep_merge` recursed with the arguments swapped, so the base value overrode the task's own value. A task's `retry.max_attempts` was being lost. It now recurses with the base first and the override second.
- **`scheduler.py`**: `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so everything downstream of a permanent failure is skipped.
- **`statemachine.py`**: `batch_order_ok` required priority to be non-decreasing within an admission batch. The docstring says non-increasing, so I flipped the comparison to `<=`. This had been masked by the queue ordering bug.
- **`resources.py`**: `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Pools never fully released, which stalled the resource-limited pipelines.
- **`events.py`**: `_prefix_matches` had the prefix check reversed. It now uses `topic.startswith(prefix + ".")`, so `job.term` subscribers receive `job.term.failed` and similar topics. This fixed the history tests.
