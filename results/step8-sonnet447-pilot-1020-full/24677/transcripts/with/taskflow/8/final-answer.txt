All 25 tests now pass with `python3 -m unittest`. I didn't modify the tests. There were seven bugs across six modules:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority dispatches first and ties go in insertion order.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the base overrode the task's own values. It now merges `(result[key], value)`.
- **`statemachine.py`:** `batch_order_ok` had its comparison inverted. It now requires non-increasing priority within a batch, as the docstring says.
- **`scheduler.py`:** `_cascade_skip` only skipped direct dependents. It now uses `dag.transitive_dependents`, so the whole downstream chain is skipped.
- **`events.py`:** `_prefix_matches` tested `prefix.startswith(topic + ".")`, which is backwards. It now tests `topic.startswith(prefix + ".")`, so `job.term` matches `job.term.failed`. This fixed the history tests.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Pools never fully freed, which blocked later tasks.
