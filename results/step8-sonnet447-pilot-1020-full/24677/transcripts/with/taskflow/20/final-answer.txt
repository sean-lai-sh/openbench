`python3 -m unittest` now passes all 25 tests. I didn't modify any tests, and all the edits are in `taskflow/`.

The defects were in six separate places. Some tests failed because of a bug in a different module, as you warned:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so insertion order won over priority. It now returns `(-priority, seq)`.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which was off by one. It now uses `attempts_made < max_attempts`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own `retry` settings. It now merges `result[key]` with `value` in the right order.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing within an admission batch. The docstring says non-increasing, so it now checks `current <= prev`.
- **`scheduler.py`:** `_cascade_skip` only skipped direct dependents. It now skips everything downstream, using `dag.transitive_dependents`.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`, which leaked pool capacity.
- **`events.py`:** `_prefix_matches` had the prefix check backwards, so `job.term` subscribers never received `job.term.failed` and similar topics. That left the history's succeeded, failed and skipped sets empty.
