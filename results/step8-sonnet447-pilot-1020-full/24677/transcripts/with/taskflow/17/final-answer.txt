`python3 -m unittest` now passes: all 25 tests ran with no failures. I didn't touch the tests.

There were seven root causes, none of them in the module the failing test was named after:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own settings. A task's `retry` override was lost. It now recurses as `deep_merge(result[key], value)`.
- **`statemachine.py`:** `batch_order_ok` had its comparison reversed. It required priority to be non-decreasing within an admission batch instead of non-increasing. It now checks `current_priority <= prev_priority`.
- **`scheduler.py`:** `_cascade_skip` skipped only direct dependents. It now uses `dag.transitive_dependents`, so a permanent failure skips everything downstream.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Multi-unit costs leaked, and runs that needed those resources deadlocked.
- **`events.py`:** `_prefix_matches` checked `prefix.startswith(topic + ".")`, which is backwards. It now checks `topic.startswith(prefix + ".")`, so the history's `job.term` prefix subscription receives `job.term.failed` and the other terminal events.
