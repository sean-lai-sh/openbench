`python3 -m unittest` now passes: all 25 tests, with no test files changed. I fixed six defects:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the base value overrode the task's own value in nested dicts like `retry`. The recursion is now `deep_merge(result[key], value)`.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing within an admission batch. The docstring says non-increasing, so it now checks `current <= prev`. Once the queue ordering was fixed, the old check made the scheduler wrongly fail the second job in a batch.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so a permanent failure skips everything downstream.
- **`events.py`:** `_prefix_matches` had the prefix test backwards (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`. This had stopped `History` from seeing any `job.term.*` events.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Multi-unit tasks leaked capacity and pipelines stalled.
