`python3 -m unittest` now passes all 25 tests. I didn't modify any tests. There were eight defects, and fixing them in sequence uncovered the later ones:

- **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave one retry too few. It now uses `attempts_made < max_attempts`.
- **`resources.py`**: `ResourcePool.release` did `self.used -= 1` instead of subtracting `cost`. Resources leaked, which stalled the resource-limited pipelines.
- **`statemachine.py`**: `batch_order_ok` required priorities to be non-decreasing within an admission batch. It now requires non-increasing, as its docstring says.
- **`scheduler.py`**: `_cascade_skip` iterated over the direct dependents only. It now uses `transitive_dependents`, so the whole downstream chain is skipped.
- **`config.py`**: in `deep_merge`, the recursive call had its arguments swapped, so the defaults overrode the task's own values. Per-task retry settings were lost.
- **`events.py`**: `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). `History` never received the `job.term.*` events, so its failed, skipped and outcome-count queries came back empty.
