All 25 tests now pass with `python3 -m unittest`. I didn't touch the tests.

I found six root causes, in six different modules:

- **`queue.py`:** `_Entry.sort_key` sorted by `(seq, -priority)`, so insertion order beat priority. It now sorts by `(-priority, seq)`.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing within an admission batch. The docstring says non-increasing, so I flipped the comparison to `<=`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own values. For example, `retry.max_attempts` stayed at the default of 1. It now recurses as `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` skipped only direct dependents. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.
- **`events.py`:** `_prefix_matches` had the prefix check backwards, so prefix subscribers never received `job.term.*` events. That left the history's failed, skipped and succeeded sets empty. It now checks `topic.startswith(prefix + ".")`.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. That leaked capacity and stalled resource-limited pipelines. It now subtracts `cost`.
