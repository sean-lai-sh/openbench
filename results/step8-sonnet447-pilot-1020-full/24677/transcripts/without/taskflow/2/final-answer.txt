`python3 -m unittest` now passes all 25 tests. I fixed seven logic errors under `taskflow/` and didn't touch the tests.

| File | Bug | Fix |
|---|---|---|
| `queue.py` | `_Entry.sort_key` returned `(seq, -priority)`, so the queue ignored priority. | It now returns `(-priority, seq)`. |
| `retry.py` | `should_retry` used `attempts_made < max_attempts - 1`, so a retry was refused one attempt early. | It now uses `attempts_made < max_attempts`. |
| `config.py` | `deep_merge` recursed with its arguments swapped, so the base overrode the task's own values. | It now calls `deep_merge(result[key], value)`. |
| `scheduler.py` | `_cascade_skip` skipped only direct dependents, so grandchildren stayed `PENDING`. | It now walks `dag.transitive_dependents`. |
| `statemachine.py` | `batch_order_ok` required priority to be non-decreasing within an admission batch. The docstring says non-increasing. | It now checks `current <= prev`. |
| `events.py` | `_prefix_matches` had its arguments reversed, so `job.term` subscribers never received `job.term.failed` or `job.term.skipped`. | It now checks `topic.startswith(prefix + ".")`. |
| `resources.py` | `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Pools leaked capacity and multi-unit tasks never finished. | It now does `used -= cost`. |

Some of these hid others. The queue ordering bug had been masking the batch-order guard bug. The guard then failed runs outright, which hid the cascade-skip and prefix-match problems.
