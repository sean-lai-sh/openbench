`python3 -m unittest` now reports all 25 tests passing. I didn't touch the tests.

There were eight bugs. Several were hiding others, as you warned:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so insertion order beat priority. It now returns `(-priority, seq)`.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`, which matches the docstring (3 attempts allowed means retries after attempts 1 and 2).
- **`statemachine.py`:** `batch_order_ok` had the comparison reversed (`>=`). It rejected the normal non-increasing priority order within an admission batch, and the scheduler then marked those runs FAILED. It is now `<=`.
- **`resources.py`:** `ResourcePool.release` did `self.used -= 1` instead of `-= cost`. That leaked capacity for any task costing more than 1, so later tasks never got admitted.
- **`events.py`:** `_prefix_matches` had its arguments swapped (`prefix.startswith(topic + ".")`). Prefix subscriptions such as `job.term` never matched `job.term.failed`, so `History` recorded no terminal outcomes.
- **`config.py`:** `deep_merge` recursed as `deep_merge(value, result[key])`, so the defaults overrode the task's own nested values like `retry.max_attempts`. The arguments are now in the right order.
- **`scheduler.py`:** `_cascade_skip` iterated `dag.dependents(...)`, which returns only direct children, so skips stopped one level down. It now uses `dag.transitive_dependents(...)`.

I only checked the code against the tests, not beyond them.
