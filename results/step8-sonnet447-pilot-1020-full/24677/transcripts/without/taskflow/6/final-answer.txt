`python3 -m unittest` now passes: 25 tests, no failures. I didn't touch the tests. Eight bugs across eight files caused the failures:

- **`queue.py`:** the sort key was `(seq, -priority)`, so the queue ran in insertion order and ignored priority. It is now `(-priority, seq)`.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave one retry too few. It is now `attempts_made < max_attempts`.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Pools never fully freed, so resource-limited tasks stalled.
- **`events.py`:** `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). Prefix subscribers such as `job.term` never saw `job.term.failed` or `job.term.skipped`.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing within an admission batch. The docstring says non-increasing, so it is now `current <= prev`.
- **`scheduler.py`:** `_cascade_skip` iterated over `dag.dependents`, which returns direct children only. It now uses `dag.transitive_dependents`, so skips reach the whole downstream chain.
- **`config.py`:** `deep_merge` recursed as `deep_merge(value, result[key])`, which swapped base and override for nested dicts. A task's `retry.max_attempts` was being overwritten by the default. The call is now `deep_merge(result[key], value)`.
