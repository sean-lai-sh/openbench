`python3 -m unittest` now passes: 25 tests, 0 failures. I didn't touch the tests. There were seven bugs, all in `taskflow/`:

1. **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
2. **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
3. **`config.py`**: `deep_merge` recursed with the arguments swapped, so defaults overrode a task's own settings. It now recurses as `deep_merge(result[key], value)`.
4. **`scheduler.py`**: `_cascade_skip` only skipped direct dependents. It now uses `dag.transitive_dependents`, so the whole downstream chain is skipped.
5. **`statemachine.py`**: `batch_order_ok` required priorities to be non-decreasing within an admission batch. The docstring says non-increasing, so it now checks `current <= prev`.
6. **`events.py`**: `_prefix_matches` had its operands reversed, so a `job.term` prefix subscriber never received `job.term.failed` or the other sub-topics. It now checks `topic.startswith(prefix + ".")`.
7. **`resources.py`**: `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Multi-unit resources leaked capacity, which stalled the pipelines that used them.

Several of these were hiding others. For example, the retry and priority fixes had to land before the skip-cascade and history failures were visible.
