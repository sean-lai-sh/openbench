`python3 -m unittest` now passes: all 25 tests, with no test files modified. There were seven separate defects, spread across six modules:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority dispatches first and ties go in insertion order.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which was off by one. It now uses `attempts_made < max_attempts`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own values. It now merges `result[key]` with `value`.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`, which left pool usage stuck above zero.
- **`statemachine.py`:** `batch_order_ok` required priority to be non-decreasing within a batch. It now requires non-increasing, as the docstring says.
- **`scheduler.py`:** `_cascade_skip` skipped only direct dependents. It now uses `transitive_dependents`, so the whole downstream chain is skipped.
- **`events.py`:** `_prefix_matches` had the prefix and topic reversed (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`. This was why `History` never recorded terminal outcomes.
