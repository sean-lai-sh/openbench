`python3 -m unittest` now passes: all 25 tests, with no test files changed. There were seven defects, in six modules:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority dispatches first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave one retry too few. It now uses `attempts_made < max_attempts`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the pipeline defaults overrode a task's own nested values (for example `retry.max_attempts`). It now merges `result[key]` with `value`.
- **`scheduler.py`:** `_cascade_skip` only skipped direct dependents. It now uses `dag.transitive_dependents`, so a permanent failure skips everything downstream.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`, which leaked capacity for any task costing more than 1.
- **`statemachine.py`:** `batch_order_ok` had its comparison inverted (`>=`). It now requires non-increasing priority within a batch (`<=`), as its docstring says.
- **`events.py`:** `_prefix_matches` tested `prefix.startswith(topic + ".")`, the wrong way round. It now tests `topic.startswith(prefix + ".")`, so `job.term` subscribers receive `job.term.failed` and the rest. This was why the history's terminal-outcome sets were empty.

The queue, resource and state-machine bugs were hiding each other. After the first fixes, the remaining pipeline failures came down to the prefix-matching bug.
