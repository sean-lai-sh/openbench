`python3 -m unittest` now reports all 25 tests passing. I didn't modify any tests. There were seven bugs, all in code under `taskflow/`:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave one retry too few. It now uses `attempts_made < max_attempts`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the base overrode the override. It now calls `deep_merge(result[key], value)`.
- **`statemachine.py`:** `batch_order_ok` had its comparison backwards. It now requires `current_priority <= prev_priority`, matching the "non-increasing priority" rule in its docstring.
- **`scheduler.py`:** `_cascade_skip` skipped only direct dependents. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.
- **`resources.py`:** `ResourcePool.release` always subtracted 1 instead of `cost`. Multi-unit resources leaked and later tasks never got admitted.
- **`events.py`:** `_prefix_matches` tested `prefix.startswith(topic + ".")`, which is the wrong way round. It now tests `topic.startswith(prefix + ".")`. This was why `History` never saw the `job.term.*` events.
