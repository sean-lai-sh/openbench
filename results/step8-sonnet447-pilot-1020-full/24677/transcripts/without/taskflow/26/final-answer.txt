`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. I fixed seven bugs, one line each:

- **`queue.py`**: `_Entry.sort_key` ordered by `(seq, -priority)`. It now uses `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`resources.py`**: `ResourcePool.release` subtracted 1 instead of `cost`, so multi-unit tasks leaked capacity and later tasks blocked.
- **`statemachine.py`**: `batch_order_ok` required priority to be non-decreasing within a batch. It now requires non-increasing, as the docstring says.
- **`scheduler.py`**: `_cascade_skip` skipped only direct dependents. It now uses `dag.transitive_dependents`, so the whole downstream chain is skipped.
- **`config.py`**: `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own retry settings. It now calls `deep_merge(result[key], value)`.
- **`events.py`**: `_prefix_matches` tested `prefix.startswith(topic + ".")` backwards. It now tests `topic.startswith(prefix + ".")`. Before this, `History` never saw the terminal events (`job.term.*`), so its failed, skipped and outcome-count queries were empty.

Several of these were hiding each other. For example, the retry and priority fixes had to land before the cascade-skip and history failures showed their real causes.
