`python3 -m unittest` now passes: all 25 tests. I didn't modify any tests. There were eight root-cause bugs, spread across seven modules:

- **`queue.py`:** `_Entry.sort_key` sorted by `(seq, -priority)`, so insertion order beat priority. It now sorts by `(-priority, seq)`.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`, which leaked capacity and stalled resource-limited runs. It now subtracts `cost`.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing within an admission batch. The docstring says non-increasing, so it now checks `current_priority <= prev_priority`.
- **`scheduler.py`:** `_cascade_skip` called `dag.dependents`, which returns only direct children. It now calls `transitive_dependents`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the base overrode the task's own values. A task's `retry` override was silently lost. It now merges `deep_merge(base_child, override_child)`.
- **`events.py`:** `_prefix_matches` checked `prefix.startswith(topic + ".")`, which is backwards. It now checks `topic.startswith(prefix + ".")`, so `History` receives the `job.term.*` events.

The bugs masked each other, as you warned. Retries, resource limits and priority ordering failed together until the queue, retry and resource fixes were in. The history failures only showed once the prefix match was fixed.
