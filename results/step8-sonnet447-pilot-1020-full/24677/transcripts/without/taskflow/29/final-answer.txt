`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. There were seven separate defects, and a few were masked by others, as you warned.

| File | Bug | Fix |
|---|---|---|
| `taskflow/queue.py` | `_Entry.sort_key` returned `(seq, -priority)`, so insertion order beat priority. | Changed to `(-priority, seq)`. |
| `taskflow/retry.py` | `should_retry` used `attempts_made < max_attempts - 1`, one retry too few. | Changed to `attempts_made < max_attempts`. |
| `taskflow/resources.py` | `ResourcePool.release` subtracted 1 instead of `cost`, which leaked capacity and stalled resource-limited runs. | Changed to subtract `cost`. |
| `taskflow/statemachine.py` | `batch_order_ok` required non-decreasing priority, the reverse of its docstring. | Changed to `current <= prev`. |
| `taskflow/scheduler.py` | `_cascade_skip` skipped only direct dependents. | Now uses `dag.transitive_dependents`. |
| `taskflow/config.py` | `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own `retry` settings. | Swapped the arguments back. |
| `taskflow/events.py` | `_prefix_matches` had `startswith` reversed, so prefix subscribers such as `History` never received `job.term.*` events. | Now checks `topic.startswith(prefix + ".")`. |
