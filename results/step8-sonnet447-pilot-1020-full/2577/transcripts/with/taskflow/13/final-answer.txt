`python3 -m unittest` now passes: all 25 tests, with no test files changed. There were seven bugs, in six modules.

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority runs first and equal priorities stay first-in-first-out.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` was inverted. It now requires non-increasing priority within an admission batch (`current <= prev`).
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so defaults overwrote task overrides. It now calls `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used the direct `dag.dependents`, so only direct children were skipped. It now uses `dag.transitive_dependents`.
- **`events.py`:** `_prefix_matches` tested `prefix.startswith(topic + ".")`, which is backwards. It now tests `topic.startswith(prefix + ".")`. This was why `History` never saw the `job.term.*` events.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`, which leaked capacity. Tasks needing a whole pool never got admitted after the first one.
