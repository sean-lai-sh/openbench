Scheduler's cascade uses only direct dependents; use transitive.

def sub(f,a,b):
    s=open(f).read(); assert a in s; open(f,'w').write(s.replace(a,b))
sub('taskflow/scheduler.py','for dep_id in self.dag.dependents(failed_run.id):','for dep_id in self.dag.transitive_dependents(failed_run.id):')

`python3 -m unittest` now passes all 25 tests. I fixed seven defects, and I didn't touch the tests.

- **`queue.py`:** the sort key was `(seq, -priority)`. It is now `(-priority, seq)`, so higher priority runs first and ties go in insertion order.
- **`retry.py`:** `should_retry` had an off-by-one, `attempts_made < max_attempts - 1`. It is now `attempts_made < max_attempts`, which gives the full attempt budget.
- **`events.py`:** the prefix match was backwards. It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing, but the docstring says non-increasing. It now checks `current <= prev`. This one was hidden behind the queue bug: once the queue ordered correctly, the guard would have rejected valid batches.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own values. It now merges `(result[key], value)`.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`, which leaked capacity. It now subtracts `cost`.
- **`scheduler.py`:** `_cascade_skip` walked only the direct dependents of a failed task. It now uses `transitive_dependents`, so everything downstream is skipped.
