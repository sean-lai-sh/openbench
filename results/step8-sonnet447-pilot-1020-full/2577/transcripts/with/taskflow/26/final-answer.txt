`python3 -m unittest` now passes: 25 tests, no failures. I didn't touch the tests. There were six root causes, and each fix was a single line:

- **`queue.py`**: the sort key was `(seq, -priority)`. It's now `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It's now `attempts_made < max_attempts`.
- **`resources.py`**: `ResourcePool.release` subtracted 1 instead of `cost`, so pools leaked capacity.
- **`events.py`**: `_prefix_matches` had its arguments reversed. It now checks `topic.startswith(prefix + ".")`.
- **`config.py`**: `deep_merge` recursed as `deep_merge(override_child, base_child)`, so the defaults overrode the task's own values. The arguments are now in the right order.
- **`scheduler.py`**: `_cascade_skip` only skipped direct dependents. It now uses `transitive_dependents`.

I also changed `batch_order_ok` in `statemachine.py` from `>=` to `<=`, so a batch only admits priorities in non-increasing order, as its docstring says. No test failed because of it, so I haven't seen it exercised. With the old `>=` it would have rejected any batch that ran in correct priority order.
