`python3 -m unittest` now passes: 25 tests, 0 failures. I fixed seven defects and didn't touch the tests.

- **`queue.py`:** the sort key was `(seq, -priority)`. It's now `(-priority, seq)`, so higher priority runs first and ties go in insertion order.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which cut the last allowed attempt. It's now `attempts_made < max_attempts`.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`. It now subtracts `cost`.
- **`statemachine.py`:** `batch_order_ok` had its comparison backwards. Priorities within a batch must be non-increasing, so it now checks `current <= prev`.
- **`events.py`:** `_prefix_matches` tested `prefix.startswith(topic + ".")` with the operands swapped. It now tests `topic.startswith(prefix + ".")`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own settings. It now recurses as `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` only skipped direct dependents. It now uses `transitive_dependents`, so a permanent failure skips everything downstream.

The retry tests failed for two reasons at once: the config merge and the retry boundary. Fixing one alone would have left them failing.
