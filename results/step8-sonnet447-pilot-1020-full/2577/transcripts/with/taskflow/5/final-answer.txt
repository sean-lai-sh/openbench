`python3 -m unittest` now passes: 25 tests, 0 failures. I didn't touch the tests. I found and fixed six defects:

- **`queue.py`:** the sort key was `(seq, -priority)`. It is now `(-priority, seq)`, so higher priority dispatches first and ties go FIFO.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It is now `attempts_made < max_attempts`.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`, so multi-unit tasks leaked capacity and the pool deadlocked.
- **`events.py`:** `_prefix_matches` had its arguments swapped. It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` was inverted. It now allows only non-increasing priority within a batch.
- **`config.py`:** `deep_merge` recursed as `(override, base)`, so defaults overrode the task's own values. It now recurses as `(base, override)`.
- **`scheduler.py`:** `_cascade_skip` used `dependents`, which returns only direct children. It now uses `transitive_dependents`, so skips reach the whole downstream chain.

The fixes uncovered each other. The inverted `batch_order_ok` guard was failing priority-ordered runs outright, which hid the queue-ordering problems.
