`python3 -m unittest` now passes: 25 tests, no failures. I didn't touch the tests.

I fixed seven bugs, one line each:

- **`queue.py`:** the sort key was `(seq, -priority)`. It now sorts on priority first, then insertion order.
- **`retry.py`:** `should_retry` stopped one attempt early. A task with `max_attempts=3` could only run twice. It now allows a retry while `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison backwards. It now accepts non-increasing priority within an admission batch, as its docstring says.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overwrote a task's own settings. A task's `retry.max_attempts` was being lost. It now merges `(base, override)`.
- **`events.py`:** `_prefix_matches` had the prefix check reversed. Prefix subscribers such as `job.term` never received `job.term.failed` and similar events, which is why the history's terminal-outcome lists were empty. It now checks that the topic starts with `prefix + "."`.
- **`scheduler.py`:** `_cascade_skip` only skipped direct dependents. It now uses `transitive_dependents`, so everything downstream of a permanent failure is skipped.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of the task's cost. Multi-unit tasks leaked capacity and blocked later tasks. It now subtracts `cost`.
