`python3 -m unittest` now passes, all 25 tests. I didn't touch the tests.

There were seven root causes, in six files:

- **`queue.py`:** `_Entry.sort_key` was `(seq, -priority)`. It now sorts by `(-priority, seq)`, so higher priority goes first and ties go in FIFO order.
- **`retry.py`:** `should_retry` was off by one (`attempts_made < max_attempts - 1`). It now uses `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` had its arguments reversed. It now checks `topic.startswith(prefix + ".")`.
- **`resources.py`:** `ResourcePool.release` always subtracted 1. It now subtracts `cost`.
- **`statemachine.py`:** `batch_order_ok` had the comparison backwards. It now requires the current priority to be less than or equal to the previous one.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the base values overrode the task's own. It now recurses as `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` skipped only direct dependents. It now uses `transitive_dependents`, so skips cascade through the whole downstream chain.

I ran the suite after the first batch of fixes and again after the last two. Fixing the queue and retry bugs exposed the config and cascade-skip failures. I didn't audit the modules the tests don't exercise (`history`, `metrics` and so on), so a similar bug could still be hiding there.
