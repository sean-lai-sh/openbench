`python3 -m unittest` now passes: 25 tests, all OK. I didn't touch the tests. There were seven defects, all in the code under `taskflow/`:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so the queue ignored priority. It now returns `(-priority, seq)`.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which cut off the last allowed attempt. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison backwards. Admitting a lower-priority task after a higher one counted as a violation. It now requires `current <= prev`. This was hidden until the queue ordering was fixed.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own values. A task's `retry` override was lost. The recursion is now `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` only skipped a failed task's direct dependents. It now uses `dag.transitive_dependents`, so everything downstream is skipped.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of subtracting the cost. Multi-unit tasks leaked capacity and later tasks were never admitted.
- **`events.py`:** `_prefix_matches` checked `prefix.startswith(topic + ".")`, the reverse of what it should. `History` never saw the `job.term.*` events, so its failed, skipped and outcome-count results were empty. It now checks `topic.startswith(prefix + ".")`.
