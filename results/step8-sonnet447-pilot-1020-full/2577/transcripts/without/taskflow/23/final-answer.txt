Fix the cascade to use transitive dependents.


`python3 -m unittest` now passes: 25 tests, all OK. I fixed seven defects and didn't touch the tests.

- **`queue.py`:** `_Entry.sort_key` sorted by `(seq, -priority)`. It now sorts by `(-priority, seq)`, so higher priority goes first and ties go in insertion order.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `< max_attempts`.
- **`events.py`:** `_prefix_matches` checked `prefix.startswith(topic + ".")`, which is backwards. It now checks `topic.startswith(prefix + ".")`.
- **`resources.py`:** `ResourcePool.release` subtracted 1 from `used` instead of `cost`. That left pools holding capacity after a task finished, which caused the resource-test failures.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing within a batch, the opposite of its docstring. It now requires non-increasing. Before the fix, the admission guard failed higher-priority tasks.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own values. The arguments are now in the right order.
- **`scheduler.py`:** `_cascade_skip` skipped only the direct dependents of a failed task. It now skips all transitive dependents.
