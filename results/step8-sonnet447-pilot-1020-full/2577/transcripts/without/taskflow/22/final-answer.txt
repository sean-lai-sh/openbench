Fix cascade to use transitive dependents.


`python3 -m unittest` now passes: 25 tests, all OK. I didn't touch the tests. There were six defects in total:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so the queue ignored priority and ran in insertion order. It now returns `(-priority, seq)`.
- **`retry.py`:** `should_retry` was off by one (`attempts_made < max_attempts - 1`), which cost every task its last attempt. It is now `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`), so prefix subscribers never saw subtopics. It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` compared with `>=` where the docstring requires non-increasing priority. It now uses `<=`.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`, so multi-unit costs were never fully released and tasks later stalled waiting for resources.
- **`config.py`:** `deep_merge` recursed with `(override, base)` swapped, so the base values beat the overrides. That wiped per-task retry settings. It now recurses with `(base, override)`.
- **`scheduler.py`:** `_cascade_skip` only skipped direct dependents. It now uses `transitive_dependents`, so a permanent failure skips everything downstream of it.
