`python3 -m unittest` now passes: 25 tests, no failures. I didn't touch the tests. There were seven bugs, in six modules:

- **`queue.py`:** The sort key was `(seq, -priority)`. It is now `(-priority, seq)`, so higher priority dispatches first and ties go FIFO.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It is now `attempts_made < max_attempts`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own nested values. It now merges the task's values on top of the defaults.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`. Pools never fully freed after a multi-unit task, which stalled the resource tests. It now subtracts `cost`.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing. The documented rule is non-increasing, so it now checks `current <= prev`. The old check made the scheduler fail correct dispatches.
- **`scheduler.py`:** The skip cascade used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so everything downstream of a permanent failure is skipped.
- **`events.py`:** `_prefix_matches` had its arguments reversed. Because of that, `History` never saw the `job.term.*` events.
