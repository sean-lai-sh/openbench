Scheduler cascade should use transitive_dependents.


`python3 -m unittest` now passes: 25 tests, no failures. I didn't modify any tests.

There were six bugs:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so tasks came out in insertion order and priority was ignored. It now returns `(-priority, seq)`.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which cut every task one attempt short. It now uses `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` had the prefix and topic the wrong way round, so prefix subscriptions never matched a topic under them. It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` required priority to be non-decreasing within an admission batch, which contradicts its docstring. It now requires non-increasing.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own nested `retry` settings. It now merges `(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` skipped only the direct dependents of a failed task. It now uses `transitive_dependents`, so everything downstream is skipped.
- **`resources.py`:** `ResourcePool.release` did `self.used -= 1` instead of subtracting the cost. Pools never fully freed, so tasks costing more than 1 unit stalled.
