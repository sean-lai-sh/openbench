I created `parallel_linear.py` with both classes. A quick test passed with world sizes 1, 2 and 4: I ran several processes on CPU and compared each layer against a regular `nn.Linear` using the same weights. Outputs matched, and so did the gradients for weights, bias and input, with each rank checked against its own slice. That test script is at `/tmp/t_pl.py`, not in the project folder.

**How the weights are laid out:** the code expects `master_weight` in the same shape `nn.Linear` uses, `(out_features, in_features)`. If your tests pass it the other way round, the size check in the constructor will fail.

**`ColumnParallelLinear`**
- Each rank keeps its share of the output dimension: rows `[rank*out/ws : (rank+1)*out/ws]` of the weight, where `ws` is the world size.
- The bias is split the same way and starts at zero.
- In the forward pass, each rank computes its part of the output, then all the parts are gathered and joined along the last dimension.
- Gradients are handled correctly in the backward pass: each rank's gradient is cut back to its own slice, and the gradients for the input are summed across ranks.

**`RowParallelLinear`**
- Each rank keeps its share of the input dimension: columns `[rank*in/ws : (rank+1)*in/ws]` of the weight.
- The bias is kept full on every rank and starts at zero.
- In the forward pass, each rank computes a partial result, the partial results are summed across ranks, and then the full bias is added once.
- The input can be either full-width or already split for that rank. If it's full-width, the layer takes the rank's slice itself, and in the backward pass the input gradient is gathered back to full width.

Both feature sizes must divide evenly by the world size; the constructors check this. If `torch.distributed` hasn't been set up, both layers act as if there is a single process.
