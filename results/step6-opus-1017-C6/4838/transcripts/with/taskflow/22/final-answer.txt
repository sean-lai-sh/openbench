All 25 tests now pass with `python3 -m unittest`. I found seven bugs, each a one-line change in `taskflow/`, and didn't touch the tests.

| File | Bug | Fix |
|---|---|---|
| `queue.py` (`_Entry.sort_key`) | Sorted by insertion order first, priority second, so tasks came out first-in-first-out regardless of priority | Changed the key to `(-priority, seq)` |
| `retry.py` (`should_retry`) | `attempts_made < max_attempts - 1` stopped one attempt early: with 3 allowed, it gave up after 2 | Changed to `attempts_made < max_attempts` |
| `statemachine.py` (`batch_order_ok`) | The check was backwards: it only allowed each task in a batch to have priority equal to or higher than the one before, and the docstring says equal or lower | Changed to `current_priority <= prev_priority` |
| `resources.py` (`ResourcePool.release`) | Always gave back 1 unit instead of the task's cost, so pools filled up and later tasks were never started | Changed to `self.used -= cost` |
| `events.py` (`_prefix_matches`) | The arguments were swapped, so subscribing to `"job.term"` never received `"job.term.failed"` and the like | Changed to `topic.startswith(prefix + ".")` |
| `config.py` (`deep_merge`) | When recursing into nested blocks, the defaults overwrote the task's own settings (e.g. a task's `retry.max_attempts=5` was lost) | Changed the call to `deep_merge(result[key], value)` |
| `scheduler.py` (`_cascade_skip`) | When a task failed for good, only its direct children were skipped, so tasks further downstream were left in `PENDING` | Now uses `dag.transitive_dependents(...)` |

Some of these were hidden behind others, as you warned. The pipeline tests named for retries, priority, resources and history were really caused by the queue, retry, state-machine, resource and event-bus bugs above. The transitive-skip failure only became clear once those were fixed.
