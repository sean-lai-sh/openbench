All 25 tests pass now: `python3 -m unittest` reports `Ran 25 tests ... OK`. At the start, 18 of the 25 were failing.

That result comes from the seven code changes from earlier; nothing new was needed this round. In each case the code had contradicted its own docstring, and I changed it to do what the docstring says:

1. **`queue.py`**: the queue now runs the highest-priority job first, and jobs with equal priority run in the order they were added.
2. **`retry.py`**: `should_retry` was cutting off one retry too early; it now allows the full `max_attempts`.
3. **`resources.py`**: `release` now gives back the job's actual cost to the pool instead of always 1.
4. **`statemachine.py`**: `batch_order_ok` now requires priorities within a batch to stay level or go down.
5. **`events.py`**: the prefix check in `_prefix_matches` had its two arguments reversed.
6. **`config.py`**: in `deep_merge`, values from the override now win over the base values when merging nested settings.
7. **`scheduler.py`**: when a job fails, every job downstream of it is now skipped, not just its direct dependents.

None of the tests were modified. I haven't reviewed `history.py`, `runner.py`, `model.py`, or the admission and retry paths in `scheduler.py`. No current test fails because of them, but they could still contain bugs the tests don't cover.
