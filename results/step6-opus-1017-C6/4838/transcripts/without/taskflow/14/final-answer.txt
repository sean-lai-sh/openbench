All 25 tests pass now (`python3 -m unittest` reports OK). I made eight one-line fixes in `taskflow/`, each one to make the code match its own docstring. I didn't touch the tests.

| File | Bug | Fix |
|---|---|---|
| `queue.py` (`_Entry.sort_key`) | Ordered by insertion sequence before priority, so the queue was plain first-in-first-out | Sort by `(-priority, seq)` |
| `retry.py` (`should_retry`) | `attempts_made < max_attempts - 1` stopped one attempt early | `attempts_made < max_attempts` |
| `config.py` (`deep_merge`) | The recursive call had its arguments swapped, so the defaults overwrote each task's own nested settings (e.g. a task's `retry.max_attempts`) | `deep_merge(result[key], value)` |
| `statemachine.py` (`batch_order_ok`) | Required priority to go *up* within one round of dispatch, so correctly ordered rounds were rejected and the task was failed | `current_priority <= prev_priority` |
| `resources.py` (`ResourcePool.release`) | Gave back 1 unit no matter what the task held, so pools leaked capacity | `self.used -= cost` |
| `events.py` (`_prefix_matches`) | The prefix check was backwards, so `"job.term"` subscribers never got `"job.term.failed"` and similar events | `topic.startswith(prefix + ".")` |
| `scheduler.py` (`_cascade_skip`) | Only skipped direct dependents when a task failed for good, leaving tasks further down stuck in `PENDING` | Use `dag.transitive_dependents` |
