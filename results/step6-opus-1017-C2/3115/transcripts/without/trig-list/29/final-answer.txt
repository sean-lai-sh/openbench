`load()` in `miniconf/loader.py` now handles `@include`. The existing 13 tests pass, but I didn't add any new tests for includes.

**How it works:** each `@include` line is replaced by the lines of the included file before parsing. Nested includes are expanded too, and paths resolve from the folder of the file that contains the directive.

**Checked by hand:**
- `examples/service.conf` loads correctly. It picks up the `[logging]` section from `logging.conf` (`level = info`, `json = True`) alongside its own keys and `[http]` section.
- A file that includes a missing file raises `ConfigError`.
- Two files that include each other raise `ConfigError` instead of looping forever.

**Behaviour you might trip over:**
- **Top-level file missing:** if the file passed to `load()` doesn't exist, it still raises `FileNotFoundError` as before. Only a missing *included* file raises `ConfigError`.
- **Same file included twice:** that's allowed, because it only counts as a cycle if a file includes itself through its own chain of includes.
- **Bare `@include`:** a line with no path raises `ConfigError`.
- **Section headers carry over:** if an included file starts a `[section]`, keys written after the `@include` line go into that section. That follows from treating the include as if its lines were written in place.
- **`loads()` is unchanged:** it still skips `@` lines without expanding them.
