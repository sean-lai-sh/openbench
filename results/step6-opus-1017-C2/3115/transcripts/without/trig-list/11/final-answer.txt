`miniconf.loader.load(path)` now handles `@include`. The change is all in `miniconf/loader.py`. The existing 13 tests still pass, and I checked each required behaviour with throwaway files; I didn't add any new tests to `tests/`.

**What I checked:**
- **The example:** `examples/service.conf` loads correctly. `name` is `billing`, `logging.level` is `info`, `logging.json` is `True` and `http.port` is `8080`.
- **Override order and nesting:** a file sets `x = 1`, then includes one that sets `x = 2` and `y = 2`, then sets `y = 9` itself. The result was `x = 2` and `y = 9`, as expected.
- **Relative paths:** an include inside `sub/` resolved against `sub/`, not the working directory.
- **Errors:** a missing include target, a file that includes itself, and a two-file cycle each raise `ConfigError`.

**How it works:** before parsing, each `@include` line is replaced by the lines of the file it points to, recursively. The parser itself is unchanged and already skipped lines starting with `@`. The directive must be the first token on the line, and everything after it is taken as the path, so paths with spaces work. An `@include` with no path raises `ConfigError`.

**Behaviour you might not expect:**
- **Including the same file twice is allowed.** Cycle detection only looks at the chain of files currently being expanded. So if two files both include a shared file, that's fine; only a real loop raises an error.
- **Sections carry over.** Expansion is purely positional, so if an included file opens a section, the lines after the `@include` belong to that section. In the example, `logging.conf` opens `[logging]` and `service.conf` then starts `[http]`, so it isn't a problem there.
- **Line numbers in parse errors can be wrong.** They refer to the expanded text, so a syntax error after an include points to the wrong line in the original file. Errors about the include itself (missing file, missing path) do give the correct file and line.
- **A missing top-level file still raises `FileNotFoundError`, as before.** Only a missing include target raises `ConfigError`.
