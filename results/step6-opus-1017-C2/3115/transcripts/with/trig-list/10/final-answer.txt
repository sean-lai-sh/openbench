`load()` now expands `@include` lines; all the changes are in `miniconf/loader.py`. The existing 13 tests pass.

I also checked it with a quick throwaway script and then deleted the files, so no tests were added to the suite. In that script:
- **Example files:** `examples/service.conf` loads with the `[logging]` keys pulled in from `logging.conf`.
- **Paths:** a nested include resolved relative to the file that contains it, not the working directory.
- **Ordering:** a key set before an include was overridden by it, and a key set after it won.
- **Errors:** a missing include target and a two-file cycle (`x → y → x`) each raised `ConfigError`.

A few details you might not expect:
- **Missing top-level file:** if the file passed to `load()` itself doesn't exist, it still raises `FileNotFoundError` as before. Only a missing include target raises `ConfigError`.
- **Same file twice:** including the same file twice through different branches is allowed. Only a file that ends up including itself counts as a cycle.
- **No path:** a bare `@include` with nothing after it raises `ConfigError`.
- **Section carries over:** because the included lines are pasted in place, a section opened inside an included file stays active after the `@include` line. In `service.conf`, a key placed straight after the include, with no new section header, would land in `[logging]`.
