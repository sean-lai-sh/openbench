`python3 -m unittest` now passes all 25 tests. I didn't modify any tests. I made eight one-line fixes, each of which makes the code do what its docstring already said:

- **`queue.py`:** `_Entry.sort_key` was `(seq, -priority)`, so the queue ignored priority. It's now `(-priority, seq)`.
- **`retry.py`:** `should_retry` had an off-by-one (`attempts_made < max_attempts - 1`). It's now `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison reversed. A batch must dispatch in non-increasing priority, so it now returns `current_priority <= prev_priority`.
- **`resources.py`:** `ResourcePool.release` always subtracted 1 instead of `cost`, which leaked capacity and stalled the resource tests.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own settings. It now merges `(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents` (direct children only). It now uses `dag.transitive_dependents`, so downstream tasks of a failed task are all skipped.
- **`events.py`:** `_prefix_matches` had the `startswith` operands swapped. It's now `topic.startswith(prefix + ".")`, which fixes the history terminal-outcome tests.
