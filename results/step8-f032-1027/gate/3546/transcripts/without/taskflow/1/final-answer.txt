`python3 -m unittest` now passes: 25 tests, all OK. I didn't touch the tests.

There were eight bugs, each a logic error. Some were masked by others, so the failure count fell in steps as I fixed them.

- **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`, so the queue ignored priority and ran in insertion order. It now returns `(-priority, seq)`.
- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`**: `batch_order_ok` required priorities to be non-decreasing, but the docstring says non-increasing. The scheduler's guard therefore marked the second job in a batch as FAILED. I flipped the comparison to `current <= prev`.
- **`config.py`**: `deep_merge` recursed with the arguments swapped, so the defaults overrode a task's own `retry` settings. It now recurses as `deep_merge(result[key], value)`.
- **`events.py`**: `_prefix_matches` checked `prefix.startswith(topic + ".")`, the wrong way round. The `job.term` prefix subscription therefore never received `job.term.failed` and the other terminal events. It now checks `topic.startswith(prefix + ".")`.
- **`resources.py`**: `ResourcePool.release` did `used -= 1` instead of `used -= cost`, which leaked capacity. It now subtracts `cost`.
- **`scheduler.py`**: `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so a failure skips everything downstream.
