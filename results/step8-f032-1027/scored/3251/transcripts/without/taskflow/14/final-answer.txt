`python3 -m unittest` now passes: 25 tests, all OK. I fixed seven bugs, one line each. I didn't touch the tests.

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` had the arguments reversed (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`, so prefix subscribers such as `job.term` receive `job.term.failed` and `job.term.skipped`.
- **`statemachine.py`:** `batch_order_ok` required priority to be non-decreasing within an admission batch. The docstring says non-increasing, so it now returns `current <= prev`.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`. Multi-unit resource holders leaked capacity and later tasks never got admitted.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own nested values (for example `retry.max_attempts`). It now recurses as `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.
