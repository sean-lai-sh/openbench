`python3 -m unittest` now passes all 25 tests. I didn't modify the tests.

There were seven bugs, in six modules:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` was off by one (`attempts_made < max_attempts - 1`). It is now `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison reversed. It now requires `current_priority <= prev_priority`, i.e. non-increasing priority within an admission batch.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. This leaked capacity, so resource-limited pipelines stalled.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so defaults overrode task settings. It now recurses with the base value first and the override second.
- **`scheduler.py`:** `_cascade_skip` used the direct `dag.dependents`, so only direct children were skipped. It now uses `dag.transitive_dependents`.
- **`events.py`:** `_prefix_matches` checked `prefix.startswith(topic + ".")` instead of `topic.startswith(prefix + ".")`. Prefix subscribers never received `job.term.*` events, so `History` recorded no terminal outcomes.
