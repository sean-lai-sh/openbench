`python3 -m unittest` now reports all 25 tests passing. I didn't touch the tests.

There were seven root-cause defects, each a one-line logic fix:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority dispatches first and FIFO breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison reversed. It now requires non-increasing priority (`current <= prev`).
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so defaults overrode a task's own nested values. It now merges `(result[key], value)`.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`, which leaked pool capacity and stalled the resource-limited runs.
- **`events.py`:** `_prefix_matches` checked the topic and prefix the wrong way round, so `job.term.*` events never reached `History`. It now checks `topic.startswith(prefix + ".")`.
- **`scheduler.py`:** `_cascade_skip` only skipped direct dependents. It now uses `dag.transitive_dependents`.
