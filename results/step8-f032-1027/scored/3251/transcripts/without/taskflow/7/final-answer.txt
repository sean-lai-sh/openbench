`python3 -m unittest` now passes: 25 tests, 0 failures. I didn't modify the tests.

Each fix is a one-line change:

- **`queue.py`:** `_Entry.sort_key` ordered by `(seq, -priority)`. It now uses `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing, which is the opposite of what the docstring says. It now requires non-increasing. This was masked by the queue ordering bug.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Pools leaked capacity, so resource-limited tasks never finished.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own values. A task's `retry` settings were being ignored.
- **`events.py`:** `_prefix_matches` had its operands reversed (`prefix.startswith(topic + ".")`). Prefix subscribers never saw `job.term.*` events, so the history's failed, skipped and outcome-count queries came back empty.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.
