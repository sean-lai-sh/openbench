`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. I found seven defects, one at a time, re-running the suite after each fix:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave one retry too few. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison backwards. It now requires each task admitted in a batch to have a priority no higher than the one before it.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`, so resources leaked and later tasks were blocked. It now subtracts the cost.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own `retry` settings. It now merges `result[key]` with `value`.
- **`scheduler.py`:** `_cascade_skip` skipped only direct dependents. It now uses `dag.transitive_dependents`.
- **`events.py`:** `_prefix_matches` tested `prefix.startswith(topic + ".")`, which is backwards. It now tests `topic.startswith(prefix + ".")`, so prefix subscribers such as `History`'s `job.term` receive the terminal events.
