`python3 -m unittest` now passes all 25 tests. I didn't modify any tests. Each fix below matches the behavior its docstring or comment describes.

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` required non-decreasing priority, but the docstring says admission batches must be non-increasing. It now checks `current <= prev`.
- **`config.py`:** In `deep_merge`, the recursive call had its arguments swapped, so the base value won over the override. It now merges `(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` skipped only direct dependents. It now uses `dag.transitive_dependents`, so the whole downstream chain is skipped.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`, which leaked capacity. It now subtracts `cost`.
- **`events.py`:** `_prefix_matches` had the prefix test reversed (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`, so `job.term` subscribers receive `job.term.failed` and the other terminal events.

I fixed these in order, re-running the suite after each one to see what the failures turned into. The earlier bugs had been hiding the scheduler, resource and event ones.
