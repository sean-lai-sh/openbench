`python3 -m unittest` now passes: all 25 tests run and report OK. I made seven fixes, and I didn't touch any tests.

- **`queue.py`:** `_Entry.sort_key` was ordering by `(seq, -priority)`. It now orders by `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` was off by one (`attempts_made < max_attempts - 1`), so a task got one attempt fewer than its policy allowed. It now uses `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` had its arguments reversed, so a prefix subscriber never saw `job.term.*` events. It now checks `topic.startswith(prefix + ".")`, which fixed the history outcome sets and counts.
- **`statemachine.py`:** `batch_order_ok` required priority to rise within a batch. It now requires priority to be non-increasing (`current <= prev`). Without this, the scheduler marked correctly ordered admissions as FAILED.
- **`resources.py`:** `ResourcePool.release` subtracted 1 from `used` no matter how many units were released. It now subtracts `cost`, which fixed the resource-limited pipeline tests.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own settings. It now calls `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used the direct `dag.dependents`, so only immediate children were skipped. It now uses `dag.transitive_dependents`, so the whole downstream chain is skipped.
