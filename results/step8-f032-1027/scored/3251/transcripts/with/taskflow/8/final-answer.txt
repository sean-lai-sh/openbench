`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. There were seven separate bugs:

- **`queue.py`:** `_Entry.sort_key` sorted by `(seq, -priority)`. It now sorts by `(-priority, seq)`, so higher priority goes first and ties are FIFO.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`. It now uses `attempts_made < max_attempts`, which gives the three attempts the docstring describes.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own settings. It now merges the task's values on top of the defaults.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`, so multi-unit costs were never fully returned.
- **`statemachine.py`:** `batch_order_ok` required priority to be non-decreasing within a batch. The docstring says non-increasing, so I flipped the comparison.
- **`scheduler.py`:** `_cascade_skip` used the direct dependents only. It now uses `dag.transitive_dependents`, so everything downstream of a failed task is skipped.
- **`events.py`:** `_prefix_matches` had the prefix check backwards, so `job.term` subscribers never received `job.term.failed` and similar events. That left the history's outcome sets empty.
