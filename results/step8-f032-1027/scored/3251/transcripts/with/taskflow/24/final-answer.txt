`python3 -m unittest` now reports all 25 tests passing. I didn't modify any tests.

There were seven separate defects. Several were hidden behind others, so the failures only cleared in stages.

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and ties are FIFO.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` was backwards. It now requires `current_priority <= prev_priority`, matching the "non-increasing priority within a batch" rule in its docstring.
- **`resources.py`:** `ResourcePool.release` did `self.used -= 1` instead of `-= cost`. That leaked capacity and left multi-unit tasks stuck.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the base value overrode the task's own value. Task-level retry overrides were being lost.
- **`events.py`:** `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`, so `job.term` subscribers receive `job.term.failed` and the other terminal events. This fixed the history tests.
- **`scheduler.py`:** `_cascade_skip` used the direct `dag.dependents`, so only immediate children were skipped. It now uses `transitive_dependents`.
