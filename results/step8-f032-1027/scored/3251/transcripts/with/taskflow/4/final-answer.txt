`python3 -m unittest` now passes: 25 tests, 0 failures. I didn't touch the tests. There were seven bugs:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison inverted. It now requires `current <= prev`, so priorities are non-increasing within a batch.
- **`config.py`:** `deep_merge` recursed as `deep_merge(value, result[key])`, which swapped base and override. It now recurses as `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` called `dag.dependents`, which returns only direct children. It now calls `transitive_dependents`.
- **`resources.py`:** `ResourcePool.release` did `self.used -= 1` instead of `-= cost`. Pools never fully released, so resource-limited pipelines stalled.
- **`events.py`:** `_prefix_matches` had its `startswith` check backwards. It now checks `topic.startswith(prefix + ".")`. Before the fix, `History` never received `job.term.*` events.
