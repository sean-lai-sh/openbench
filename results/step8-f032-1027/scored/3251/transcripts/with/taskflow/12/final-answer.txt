`python3 -m unittest` now runs all 25 tests and they pass. I didn't touch the tests. There were seven bugs, each fixed with a one-line change:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and ties break by insertion order.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`. It now uses `attempts_made < max_attempts`, which is what the docstring's `max_attempts == 3` example describes.
- **`statemachine.py`:** `batch_order_ok` had its comparison reversed. It now requires `current_priority <= prev_priority`, so a batch is non-increasing in priority.
- **`config.py`:** `deep_merge` recursed as `deep_merge(value, result[key])`, which swapped base and override. It now recurses as `deep_merge(result[key], value)`, so a task's `retry` override no longer replaces the defaults wholesale.
- **`resources.py`:** `ResourcePool.release` did `self.used -= 1` instead of `-= cost`. Multi-unit resources were never fully released.
- **`scheduler.py`:** `_cascade_skip` used the direct `dependents`. It now uses `transitive_dependents`, so a failure skips everything downstream, not just the direct children.
- **`events.py`:** `_prefix_matches` had its arguments backwards (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`, so `job.term` subscribers receive `job.term.failed` and the history's failed/skipped/succeeded sets fill in.
