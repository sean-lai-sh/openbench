`python3 -m unittest` now passes all 25 tests. I didn't edit any tests. There were seven defects:

- **`queue.py`:** `_Entry.sort_key` sorted by `(seq, -priority)`. It now sorts by `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison reversed. It now requires non-increasing priority within a batch. With the queue ordering broken, the guard was failing jobs outright.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`. That leaked capacity on any task with a cost above 1, and resource-limited pipelines then stalled.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own `retry` settings. It now merges `result[key]` with the override value.
- **`events.py`:** `_prefix_matches` checked `prefix.startswith(topic + ".")` instead of `topic.startswith(prefix + ".")`. The history's `job.term` subscription never fired, so failed, skipped and outcome-count queries came back empty.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so skips reach the whole downstream chain.
