`python3 -m unittest` now passes: 25 tests, none modified. There were seven separate bugs, in these places:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority comes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` had an off-by-one (`attempts_made < max_attempts - 1`). It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison reversed. It now requires `current_priority <= prev_priority`, which is non-increasing priority within a batch.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own values. It now merges `result[key]` with the override value.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`, which leaked capacity.
- **`events.py`:** `_prefix_matches` checked `prefix.startswith(topic + ".")`, which is backwards. It now checks `topic.startswith(prefix + ".")`, which restores `job.term.*` delivery to `History`.
- **`scheduler.py`:** `_cascade_skip` used the direct `dependents()` instead of `transitive_dependents()`, so only direct children were skipped.

Several failures were symptoms of these bugs. The retry and resource pipeline tests were failing because of the queue, retry and resource-release bugs. The history tests were failing because of the event prefix match.
