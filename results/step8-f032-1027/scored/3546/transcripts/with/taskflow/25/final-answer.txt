`python3 -m unittest` now passes all 25 tests. I didn't modify any tests. Here are the seven defects I fixed:

- **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority dispatches first and insertion order breaks ties.
- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave one attempt too few. It now uses `attempts_made < max_attempts`.
- **`resources.py`**: `ResourcePool.release` always did `used -= 1`. It now subtracts the actual `cost`, which stops resources leaking and blocking later tasks.
- **`statemachine.py`**: `batch_order_ok` required priority to be non-decreasing within a batch. It now requires non-increasing, as its docstring says. The old check was failing valid dispatches.
- **`scheduler.py`**: `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so a failure skips everything downstream.
- **`config.py`**: `deep_merge` recursed with the arguments swapped, so base values overwrote overrides in nested dicts. It now calls `deep_merge(result[key], value)`.
- **`events.py`**: `_prefix_matches` had its operands reversed (`prefix.startswith(topic + ".")`). It now uses `topic.startswith(prefix + ".")`, so `job.term` subscribers receive `job.term.failed` and the other terminal events. This fixed the history tests.
