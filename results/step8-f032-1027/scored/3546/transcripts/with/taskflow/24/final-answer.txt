`python3 -m unittest` now passes: 25 tests, no failures. I didn't modify any tests. I fixed seven defects in six modules.

| File | Defect | Fix |
|---|---|---|
| `queue.py` | `_Entry.sort_key` returned `(seq, -priority)`, so insertion order beat priority. | Changed it to `(-priority, seq)`. |
| `retry.py` | `should_retry` used `attempts_made < max_attempts - 1`, one attempt short. | Changed it to `attempts_made < max_attempts`. |
| `statemachine.py` | `batch_order_ok` used `>=`, but the batch invariant is non-increasing priority. | Changed it to `<=`. Once the queue ordered correctly, this guard was failing valid dispatches as `FAILED`. |
| `config.py` | `deep_merge` recursed with its arguments swapped, so defaults overrode a task's own nested values. | Recurse as `deep_merge(result[key], value)`. |
| `scheduler.py` | `_cascade_skip` used the direct `dependents`, so only immediate children were skipped. | Switched to `transitive_dependents`. |
| `resources.py` | `ResourcePool.release` did `used -= 1` instead of subtracting the cost, which leaked capacity and stalled multi-unit tasks. | Changed it to `used -= cost`. |
| `events.py` | `_prefix_matches` had the arguments reversed (`prefix.startswith(topic + ".")`), so `job.term` subscribers never saw `job.term.failed` and similar events. | Changed it to `topic.startswith(prefix + ".")`. |

The pipeline tests failed for several reasons at once: retries, resources, skips and history. Fixing the queue, retry, state machine and config bugs exposed the cascade, resource and event-prefix bugs behind them.
