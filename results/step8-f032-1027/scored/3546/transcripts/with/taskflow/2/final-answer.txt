`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. There were seven bugs, in these files:

- **`taskflow/queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and ties go in FIFO order.
- **`taskflow/retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave one attempt too few. It now uses `attempts_made < max_attempts`.
- **`taskflow/events.py`:** `_prefix_matches` had the arguments reversed (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`, so `job.term` receives `job.term.failed` and the other terminal events. This is why the history had no failed or skipped jobs.
- **`taskflow/statemachine.py`:** `batch_order_ok` had the comparison backwards. It now requires `current_priority <= prev_priority`, matching its docstring. With the old check, correctly ordered batches were being failed.
- **`taskflow/config.py`:** `deep_merge` recursed with the arguments swapped, so the defaults overrode the task's own settings. It now calls `deep_merge(result[key], value)`.
- **`taskflow/scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so everything downstream of a failed task is skipped.
- **`taskflow/resources.py`:** `ResourcePool.release` did `self.used -= 1` instead of subtracting `cost`. Multi-unit tasks therefore never freed their full allocation, and later tasks could never be admitted.
