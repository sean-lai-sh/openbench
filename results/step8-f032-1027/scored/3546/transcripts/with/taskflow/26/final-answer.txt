`python3 -m unittest` now passes all 25 tests. I didn't touch the tests.

There were seven bugs in the code under `taskflow/`:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so the queue dispatched by insertion order and ignored priority. It now returns `(-priority, seq)`.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which was off by one, so a task with 3 attempts only got 2. It now uses `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing, but the docstring says non-increasing within a batch. It now checks `current <= prev`.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`, so multi-unit costs leaked capacity and resource-limited runs stalled. It now subtracts `cost`.
- **`scheduler.py`:** `_cascade_skip` only skipped direct dependents. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own `retry` settings. It now calls `deep_merge(result[key], value)`.

Several of the retry and resource tests were failing because of more than one of these bugs, so I fixed one, re-ran, and re-diagnosed until the suite was clean.
