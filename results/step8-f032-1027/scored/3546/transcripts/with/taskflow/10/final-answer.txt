`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. I fixed seven defects in `taskflow/`:

- **`queue.py`:** `_Entry.sort_key` sorted by `(seq, -priority)`. It now sorts by `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing within a batch. The docstring says non-increasing, so I flipped the comparison to `current <= prev`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped for nested dicts, so the defaults overrode a task's own settings. It now calls `deep_merge(result[key], value)`.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`, which leaked capacity on multi-unit tasks.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which only returns direct children. It now uses `transitive_dependents`, so skips reach the whole downstream chain.
- **`events.py`:** `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). Prefix subscriptions like `job.term` therefore never saw `job.term.failed` and similar topics. It now checks `topic.startswith(prefix + ".")`.

The history test failures traced back to the last one, in the event bus.
