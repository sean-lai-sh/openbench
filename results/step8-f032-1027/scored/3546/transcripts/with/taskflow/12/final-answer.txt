`python3 -m unittest` now passes all 25 tests. I didn't modify the tests.

I fixed eight defects, each in the module that caused the failures:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority dispatches first and ties go FIFO.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave one attempt too few. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison backwards. It now accepts only non-increasing priority within a batch (`current <= prev`). With the queue ordering broken, this guard was also failing runs outright.
- **`events.py`:** `_prefix_matches` tested `prefix.startswith(topic + ".")`. It now tests `topic.startswith(prefix + ".")`. Before this, `History` never received the `job.term.*` events, which broke the failed/skipped/outcome-count queries.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Multi-unit resources leaked and later tasks never got admitted.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so defaults overrode per-task `retry` settings. It now recurses with `deep_merge(result[key], value)`.
