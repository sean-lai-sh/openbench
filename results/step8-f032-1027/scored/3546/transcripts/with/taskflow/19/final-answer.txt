`python3 -m unittest` now passes: 25 tests, 0 failures. I didn't modify any tests. There were seven bugs, each fixed in the module where it lived:

- **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`, so the queue ordered by insertion first. It now returns `(-priority, seq)`, which gives highest priority first and FIFO among equals.
- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave one attempt too few. It is now `attempts_made < max_attempts`.
- **`statemachine.py`**: `batch_order_ok` required priorities within a batch to be non-decreasing. It now requires non-increasing, as the docstring says.
- **`config.py`**: `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own values. It is now `deep_merge(result[key], value)`.
- **`resources.py`**: `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Multi-unit costs were never fully returned, which stalled resource-limited runs.
- **`scheduler.py`**: `_cascade_skip` iterated over `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so a permanent failure skips everything downstream.
- **`events.py`**: `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). Subscribing to `job.term` therefore never received `job.term.failed` and similar events, which left the history's outcome sets empty. It now checks `topic.startswith(prefix + ".")`.
