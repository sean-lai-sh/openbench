`python3 -m unittest` now passes: all 25 tests, with no test files changed. I found seven defects across six modules.

- **`queue.py`**: the sort key was `(seq, -priority)`, so tasks came out in plain insertion order. It is now `(-priority, seq)`, which gives highest priority first and FIFO within a priority.
- **`retry.py`**: `should_retry` allowed one retry too few, so `max_attempts=3` allowed only one retry. It is now `attempts_made < max_attempts`.
- **`events.py`**: `_prefix_matches` had its arguments reversed. It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`**: `batch_order_ok` required priority to be non-decreasing within an admission batch. The docstring and the queue ordering both say non-increasing, so it is now `current <= prev`.
- **`resources.py`**: `ResourcePool.release` subtracted 1 instead of `cost`, so multi-unit resources leaked and later tasks could not be admitted. It now subtracts `cost`.
- **`config.py`**: `deep_merge` swapped base and override when recursing into nested dicts, so defaults overwrote task-level `retry` settings. The arguments are now in the right order.
- **`scheduler.py`**: `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so everything downstream of a permanent failure is skipped.
