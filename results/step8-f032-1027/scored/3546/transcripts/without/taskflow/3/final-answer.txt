`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. There were seven root causes, and fixing the early ones exposed the later ones:

1. **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority dispatches first and equal priorities stay FIFO.
2. **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave one attempt too few. It is now `attempts_made < max_attempts`.
3. **`statemachine.py`:** `batch_order_ok` had its comparison backwards. It now requires `current <= prev`, because priorities should be non-increasing within a batch. Without this fix, a correct queue would have tripped the guard and failed jobs.
4. **`config.py`:** `deep_merge` recursed as `deep_merge(override, base)`, so defaults overrode the task's own values. It is now `deep_merge(base, override)`.
5. **`resources.py`:** `ResourcePool.release` did `self.used -= 1` instead of `-= cost`. That leaked capacity and stalled any pipeline using resource pools.
6. **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns direct children only. It now uses `dag.transitive_dependents`.
7. **`events.py`:** `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`. This is why history never recorded the `job.term.*` events.
