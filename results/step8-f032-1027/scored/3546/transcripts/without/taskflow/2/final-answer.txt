`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. There were eight bugs in total:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which cut the retry budget short by one. It now uses `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` had its arguments the wrong way round (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` required priority to be non-decreasing within an admission batch, the opposite of what its docstring says. It now requires `current <= prev`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own nested settings such as `retry`. It now recurses with `(base_child, override_child)`.
- **`resources.py`:** `ResourcePool.release` always subtracted 1 instead of `cost`, so resources leaked and later admissions stalled. It now subtracts `cost`.
- **`scheduler.py`:** `_cascade_skip` skipped only direct dependents. It now skips all transitive dependents.

The queue, retry and state machine bugs were already hiding behind each other in the pipeline tests. I fixed the four small modules first, then the rest, re-running the suite after each batch.
