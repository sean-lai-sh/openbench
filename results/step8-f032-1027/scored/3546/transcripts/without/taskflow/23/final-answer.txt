`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. There were eight separate defects:

1. **`queue.py`**: `_Entry.sort_key` sorted by `(seq, -priority)`. It now sorts by `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
2. **`retry.py`**: `should_retry` was off by one, using `attempts_made < max_attempts - 1`. It now uses `attempts_made < max_attempts`.
3. **`statemachine.py`**: `batch_order_ok` required priority to be non-decreasing within an admission batch. The docstring says non-increasing, so I flipped it to `current <= prev`.
4. **`config.py`**: `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own nested values. It now recurses with the base first and the override second.
5. **`resources.py`**: `ResourcePool.release` always subtracted 1 instead of `cost`, so capacity leaked and multi-unit tasks stalled. It now subtracts `cost`.
6. **`scheduler.py`**: `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so the whole downstream chain is skipped.
7. **`events.py`**: `_prefix_matches` had its arguments reversed in the `startswith` check. Prefix subscribers such as `History` never received `job.term.*` events, so `failed_jobs`, `skipped_jobs` and `outcome_counts` came back empty. It now checks `topic.startswith(prefix + ".")`.

Some of these were masked by others. The retry and resource fixes had to land before the pipeline tests exposed the cascade-skip and event-matching bugs.
