`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. There were seven defects, all in the code under `taskflow/`:

1. **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. The docstring says the ordering is `(-priority, seq)`, so I swapped them. Before, the queue ignored priority and popped in insertion order.
2. **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which is off by one. It now uses `attempts_made < max_attempts`, so a task with `max_attempts=3` retries after attempts 1 and 2 and fails permanently after attempt 3. Before, the last allowed attempt was never made.
3. **`statemachine.py`:** `batch_order_ok` had its comparison reversed. Its docstring says priorities must be non-increasing within an admission batch, so it now checks `current <= prev`. Once the queue ordering was fixed, the old check wrongly rejected valid batches.
4. **`events.py`:** `_prefix_matches` had its operands swapped. It checked `prefix.startswith(topic + ".")`, so a subscription to `job.term` never received `job.term.failed` and similar topics. It now checks `topic.startswith(prefix + ".")`. This had left `History` without any failed, skipped or succeeded records.
5. **`config.py`:** `deep_merge` recursed as `deep_merge(value, result[key])`, which made the base win over the override. It now recurses as `deep_merge(result[key], value)`. A task's `retry.max_attempts` was being overwritten by the defaults.
6. **`resources.py`:** `ResourcePool.release` did `self.used -= 1` instead of `-= cost`. Multi-unit resource costs leaked, which blocked later tasks in the resource tests.
7. **`scheduler.py`:** `_cascade_skip` used `dag.dependents()`, which returns only direct children. It now uses `dag.transitive_dependents()`, so a permanent failure skips every downstream task. It also fixed the diamond-shaped skip test.
