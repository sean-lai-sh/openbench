`python3 -m unittest` now passes: all 25 tests, with no test files modified. There were seven separate defects:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order only breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison backwards. It now returns `current_priority <= prev_priority`, which matches the "non-increasing priority within a batch" rule.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own values. It now merges `result[key]` with `value`.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`, so multi-unit tasks never fully freed their resources. It now subtracts `cost`.
- **`events.py`:** `_prefix_matches` checked `prefix.startswith(topic + ".")`, which is the wrong direction. It now checks `topic.startswith(prefix + ".")`, so a `job.term` subscription receives `job.term.failed` and the other terminal events. This is what fixed the history tests.
- **`scheduler.py`:** `_cascade_skip` used the direct `dag.dependents`, so only immediate children were skipped. It now uses `dag.transitive_dependents`.

I only ran the test suite. I didn't look for defects in the modules the tests don't exercise.
