`python3 -m unittest` now passes all 25 tests. I fixed seven defects, none of them in the tests:

- **`queue.py`:** `_Entry.sort_key` ordered by `(seq, -priority)`. It now orders by `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which allowed one attempt too few. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing within an admission batch, the opposite of what its docstring says. It now requires non-increasing priority. This fix and the queue ordering fix had been hiding each other.
- **`config.py`:** `deep_merge` recursed as `deep_merge(override, base)`, so defaults overrode a task's own settings. It now recurses as `deep_merge(base, override)`.
- **`events.py`:** `_prefix_matches` had its arguments reversed, so prefix subscriptions never matched. That left `History` with no terminal outcomes (`failed_jobs` and `outcome_counts` came back empty or zero). The check is now `topic.startswith(prefix + ".")`.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Pools never fully drained, so later tasks were blocked and some pipelines never finished.
- **`scheduler.py`:** `_cascade_skip` skipped only the direct dependents of a failed task. It now skips every transitive dependent.
