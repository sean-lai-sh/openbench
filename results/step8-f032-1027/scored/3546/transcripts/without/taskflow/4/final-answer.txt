`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. There were seven bugs, and I fixed them in six modules under `taskflow/`.

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so the queue ignored priority. It now returns `(-priority, seq)`.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave one attempt too few. It now uses `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` had the prefix and topic the wrong way round. It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` used `>=`, but the docstring says priorities within a batch must be non-increasing. It now uses `<=`.
- **`resources.py`:** `ResourcePool.release` always subtracted 1 unit instead of `cost`. This left resources held, which stalled the resource-limited pipelines.
- **`config.py`:** `deep_merge` swapped its arguments when recursing, so the base value overrode the task's own value. For example, `retry.max_attempts` stayed at the default. It now calls `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so everything downstream of a permanent failure is skipped.
