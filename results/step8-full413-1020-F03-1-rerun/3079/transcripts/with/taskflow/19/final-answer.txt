`python3 -m unittest` now passes: 25 tests, all OK. I didn't touch the tests. Each fix below was a logic error that contradicted its own docstring.

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority dispatches first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` had the arguments reversed (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`.
- **`resources.py`:** `ResourcePool.release` always subtracted 1 instead of `cost`. Capacity never came back for tasks that cost more than 1, which stalled the resource-limited runs.
- **`statemachine.py`:** `batch_order_ok` returned `current >= prev`, which is backwards. Within an admission batch priorities must be non-increasing, so it now returns `current <= prev`.
- **`config.py`:** `deep_merge` recursed as `deep_merge(value, result[key])`, so the defaults overrode the task's own values. It now recurses as `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.
