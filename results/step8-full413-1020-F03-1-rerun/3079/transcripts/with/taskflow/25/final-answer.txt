`python3 -m unittest` now passes all 25 tests. I didn't edit any tests. There were seven defects, and several were hiding others:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It should be `(-priority, seq)`, so higher priority goes first and ties go in insertion order.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave one retry too few. It now uses `attempts_made < max_attempts`.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Pools never fully freed, so resource-limited pipelines stalled.
- **`statemachine.py`:** `batch_order_ok` had its comparison reversed. It must allow only non-increasing priority within a batch, so it now checks `current <= prev`.
- **`events.py`:** `_prefix_matches` had its arguments swapped (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`. Before this fix, `History` never received the `job.term.*` events.
- **`config.py`:** `deep_merge` recursed as `deep_merge(value, result[key])`, which let the base override the task's own values. It now recurses as `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used the direct dependents only. It now uses `dag.transitive_dependents`, so a permanent failure skips the whole downstream chain.
