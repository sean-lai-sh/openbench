`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. There were six root causes, and several failures shared the same one:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and FIFO breaks ties.
- **`retry.py`:** `should_retry` was off by one (`attempts_made < max_attempts - 1`). It now uses `attempts_made < max_attempts`.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`, which leaked capacity for any task that held more than one unit.
- **`events.py`:** `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`, so `job.term` subscribers receive `job.term.failed` and the other terminal events.
- **`statemachine.py`:** `batch_order_ok` required priority to increase within an admission batch. The docstring says non-increasing, so it now checks `current <= prev`.
- **`config.py`:** `deep_merge` recursed with the base and override swapped, so defaults overrode task-level `retry` settings. It now recurses as `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so skips cascade through the whole downstream graph.
