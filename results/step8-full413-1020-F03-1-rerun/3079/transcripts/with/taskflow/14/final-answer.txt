`python3 -m unittest` now passes: 25 tests, all OK. I didn't touch the tests. There were seven bugs, each a one-line fix:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority dispatches first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`. It now uses `attempts_made < max_attempts`, which is off by one from the docstring's `max_attempts == 3` example.
- **`resources.py`:** `ResourcePool.release` did `used -= 1`. It now does `used -= cost`. This was the cause of the resource-limited pipelines never finishing.
- **`events.py`:** `_prefix_matches` had its arguments reversed. It now checks `topic.startswith(prefix + ".")`, so a prefix subscriber sees its whole subtree.
- **`statemachine.py`:** `batch_order_ok` required `current >= prev`. It now requires `current <= prev`, since a batch must dispatch in non-increasing priority order.
- **`config.py`:** `deep_merge` recursed with the base and override swapped, so defaults overrode per-task settings. It now recurses as `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so everything downstream of a permanent failure is skipped.
