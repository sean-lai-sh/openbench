`python3 -m unittest` now reports all 25 tests passing. I didn't touch the tests. There were seven root causes, none of them in the module the failing test was named for:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and FIFO breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` required priority to be non-decreasing within an admission batch. The docstring says non-increasing, so I flipped the comparison to `<=`.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`. Pools never fully freed, so tasks with resource costs stalled.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own settings. It now recurses with the base first and the override second.
- **`scheduler.py`:** `_cascade_skip` skipped only direct dependents. It now uses `dag.transitive_dependents`, so a permanent failure skips everything downstream.
- **`events.py`:** `_prefix_matches` had its arguments reversed, so prefix subscriptions never matched. That left `History` with empty failed and skipped sets. It now checks `topic.startswith(prefix + ".")`.
