`python3 -m unittest` now passes all 25 tests. I didn't modify any tests.

There were eight bugs in total:

- **`queue.py`:** `_Entry.sort_key` sorted by `(seq, -priority)`. It now sorts by `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` was off by one (`< max_attempts - 1`). It is now `< max_attempts`.
- **`events.py`:** `_prefix_matches` had its operands reversed. It now checks `topic.startswith(prefix + ".")`, so a prefix subscription receives its dotted subtree.
- **`statemachine.py`:** `batch_order_ok` had its comparison inverted. It now requires non-increasing priority within an admission batch (`current <= prev`).
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`, which leaked capacity and blocked later tasks.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the base overrode the task's own values. It now merges the override on top of the base.
- **`scheduler.py`:** `_cascade_skip` skipped only direct dependents. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.

The retry, resource-limit and pipeline tests were failing mainly because of the `should_retry`, `release` and cascade bugs. Fixing the first ones exposed the others.
