`python3 -m unittest` now passes: all 25 tests. I fixed seven bugs and didn't touch the tests.

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` checked `prefix.startswith(topic + ".")`, which is backwards. It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` required priority to be non-decreasing within a batch. The docstring says non-increasing, so it now returns `current <= prev`. With the queue ordering bug, this had been failing jobs at admission.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`. Multi-unit resource costs leaked capacity, and later tasks never got admitted.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so everything downstream of a failed task is skipped.
- **`config.py`:** `deep_merge` recursed with its arguments swapped. Defaults overrode the task's own values, for example the task's own `retry` settings. It now calls `deep_merge(result[key], value)`.
