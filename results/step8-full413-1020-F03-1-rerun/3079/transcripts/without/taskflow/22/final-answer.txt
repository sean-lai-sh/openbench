`python3 -m unittest` now passes all 25 tests. I didn't modify the tests. There were seven root causes, spread across six modules:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority is dispatched first and ties go in FIFO order.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave one attempt too few. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison backwards. It now requires non-increasing priority within a batch (`current <= prev`).
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own settings. It now merges `(result[key], value)`.
- **`events.py`:** `_prefix_matches` tested `prefix.startswith(topic + ".")`. It now tests `topic.startswith(prefix + ".")`, so prefix subscriptions like `job.term` receive `job.term.failed` and the other terminal events.
- **`resources.py`:** `ResourcePool.release` always subtracted 1 unit instead of `cost`. It now subtracts `cost`, which stops pools from leaking capacity and blocking later tasks.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so everything downstream of a permanent failure is skipped.
