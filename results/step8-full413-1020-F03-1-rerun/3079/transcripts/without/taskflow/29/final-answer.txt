`python3 -m unittest` now passes: 25 tests, 0 failures. I didn't modify any tests. There were seven defects, each a one-line logic error:

- **`queue.py`:** The ordering key was `(seq, -priority)`. It is now `(-priority, seq)`, so higher priority dispatches first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It is now `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison reversed, so it required priorities to rise within an admission batch. It now requires them to be non-increasing.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the base's values overrode the task's own values. It now recurses with the base first and the override second.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`, which leaked capacity on multi-unit tasks.
- **`scheduler.py`:** `_cascade_skip` used the direct `dag.dependents`. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.
- **`events.py`:** `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). `job.term.*` events never reached `History`, so the outcome sets and counts came back empty. It now checks `topic.startswith(prefix + ".")`.
