`python3 -m unittest` now passes: all 25 tests, with no test files changed. I found seven defects, listed below.

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which stopped one retry early. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison backwards. It now requires `current_priority <= prev_priority`, matching the "non-increasing priority within a batch" rule in its docstring.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own settings. It now calls `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` skipped only direct dependents. It now uses `dag.transitive_dependents`, so everything downstream of a failed task is skipped.
- **`events.py`:** `_prefix_matches` checked `prefix.startswith(topic + ".")`, the wrong way round. It now checks `topic.startswith(prefix + ".")`, so `job.term` subscribers get `job.term.failed` and the other terminal events. That fixed the empty history results.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Pools never freed their full capacity, which stalled the resource-limited pipelines.
