`python3 -m unittest` now passes: 25 tests, no failures. I didn't modify any tests. Each fix below is a single-line change.

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority dispatches first and ties go in insertion order.
- **`retry.py`:** `should_retry` was off by one (`attempts_made < max_attempts - 1`). It is now `attempts_made < max_attempts`.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`, which leaked capacity on multi-unit releases.
- **`events.py`:** `_prefix_matches` had its arguments backwards (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing, but its docstring says non-increasing. I flipped the comparison to match the docstring.
- **`config.py`:** `deep_merge` recursed with `(override, base)` swapped, so the pipeline defaults overrode a task's own settings. It now recurses with `(base, override)`.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so a permanent failure skips everything downstream.
