`python3 -m unittest` now passes all 25 tests. I fixed six defects:

- **`queue.py`**: `_Entry.sort_key` ordered by `(seq, -priority)`. It now uses `(-priority, seq)`, so higher priority runs first and ties go in FIFO order.
- **`retry.py`**: `should_retry` returned `attempts_made < max_attempts - 1`, which cut the retry budget by one. It now returns `attempts_made < max_attempts`.
- **`events.py`**: `_prefix_matches` had the prefix and topic swapped, so prefix subscribers never saw `job.term.*` events. It now checks `topic.startswith(prefix + ".")`.
- **`resources.py`**: `ResourcePool.release` subtracted 1 unit instead of `cost`, which leaked capacity. It now subtracts `cost`.
- **`statemachine.py`**: `batch_order_ok` checked `current >= prev`. That is the reverse of the documented non-increasing priority order. It now checks `current <= prev`.
- **`config.py`**: `deep_merge` swapped its arguments when it recursed, so the defaults overrode a task's own `retry` settings. It now recurses as `deep_merge(result[key], value)`.
- **`scheduler.py`**: `_cascade_skip` only skipped direct dependents. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.
