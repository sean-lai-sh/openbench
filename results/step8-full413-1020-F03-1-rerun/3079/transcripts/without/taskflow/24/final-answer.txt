`python3 -m unittest` now passes all 25 tests. I fixed seven logic bugs, and the only tests I ran were the existing suite.

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which cut the retry budget by one. It now uses `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` had the arguments of its `startswith` check reversed. It now checks `topic.startswith(prefix + ".")`, so `job.term.failed` reaches a `job.term` prefix subscriber.
- **`statemachine.py`:** `batch_order_ok` required non-decreasing priority, but its docstring says non-increasing. It now returns `current_priority <= prev_priority`. This guard was making the scheduler fail jobs outright in some batches.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Multi-unit resource costs leaked capacity.
- **`config.py`:** `deep_merge` recursed with the arguments swapped, so defaults overrode a task's own settings. It now calls `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so every downstream task is skipped.
