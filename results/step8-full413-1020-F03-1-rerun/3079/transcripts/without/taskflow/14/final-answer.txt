`python3 -m unittest` now passes: 25 tests, all OK. I didn't change any tests.

I fixed seven defects, one line each:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority comes first and insertion order only breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave one attempt too few. It now uses `attempts_made < max_attempts`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own settings. It now calls `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` only skipped direct dependents. It now uses `dag.transitive_dependents`.
- **`statemachine.py`:** `batch_order_ok` had its comparison reversed. It now returns `current_priority <= prev_priority`, which matches the docstring's non-increasing priority order.
- **`events.py`:** `_prefix_matches` tested `prefix.startswith(topic + ".")`, which is backwards. It now tests `topic.startswith(prefix + ".")`. This is why `History` never saw the `job.term.*` events.
- **`resources.py`:** `ResourcePool.release` always subtracted 1 instead of `cost`. It now subtracts `cost`, which fixes the resource-limited pipelines that never finished.
