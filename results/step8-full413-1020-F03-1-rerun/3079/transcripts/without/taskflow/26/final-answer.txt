`python3 -m unittest` now passes all 25 tests. I found six bugs, all in the code under `taskflow/`, and left the tests alone.

- **`queue.py`:** `_Entry.sort_key` sorted by `(seq, -priority)`. It now sorts by `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` was off by one (`attempts_made < max_attempts - 1`). It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` required priorities to rise within a batch. It now requires them to be non-increasing. This was the cause of the scheduler failing any second task admitted in the same tick.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`. Multi-unit tasks leaked capacity, which caused the resource tests to deadlock.
- **`events.py`:** `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). It now checks `topic.startswith(prefix + ".")`. This is why the history never saw the terminal events.
- **`config.py`:** `deep_merge` recursed with base and override swapped, so the defaults overrode the task's own settings. It now recurses as `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used the direct `dag.dependents`, so only immediate children were skipped. It now uses `transitive_dependents`.
