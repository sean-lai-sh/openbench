`python3 -m unittest` now passes: 25 tests, no failures. I didn't edit any tests. The fixes were these:

- **`queue.py`:** `_Entry.sort_key` sorted by `(seq, -priority)`, so priority was ignored. It's now `(-priority, seq)`.
- **`retry.py`:** `should_retry` was off by one and gave up one attempt early. It's now `attempts_made < max_attempts`.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of subtracting the cost, so multi-unit costs leaked capacity.
- **`statemachine.py`:** `batch_order_ok` had its comparison reversed. It's now `current <= prev`, so batches must be non-increasing in priority.
- **`config.py`:** `deep_merge` swapped its arguments in the recursive call, so the defaults overrode the task's own nested values. It's now `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used the direct `dependents`, so only children were skipped. It now uses `transitive_dependents`.
- **`events.py`:** `_prefix_matches` had the `startswith` check backwards. It's now `topic.startswith(prefix + ".")`, which fixes the prefix subscriptions that feed the history's terminal-outcome sets.
