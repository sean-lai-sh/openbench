`python3 -m unittest` now passes all 25 tests. I didn't modify any tests. The failures traced back to seven defects:

- **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority dispatches first and equal priorities stay FIFO.
- **`retry.py`**: `should_retry` was off by one (`attempts_made < max_attempts - 1`). It is now `attempts_made < max_attempts`.
- **`events.py`**: `_prefix_matches` had its arguments reversed. It now checks `topic.startswith(prefix + ".")`, so `job.term` subscribers receive `job.term.skipped` and the other subtopics.
- **`statemachine.py`**: `batch_order_ok` required priority to be non-decreasing within an admission batch. It now requires non-increasing, as its docstring says.
- **`resources.py`**: `ResourcePool.release` subtracted 1 instead of `cost`. Multi-unit resource costs leaked, which stalled the resource-limited pipelines.
- **`config.py`**: `deep_merge` recursed with `(override, base)` swapped, so pipeline defaults overrode per-task `retry` settings. It now recurses with `(base, override)`.
- **`scheduler.py`**: `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.
