## Actual vs. expected
- **Actual** (ran `python3 main.py`): `Total: 0`
- **Expected:** `Total: 5.0`. The only rate in `settings.json` is `0.5`, and `main.py` multiplies the rate by `COUNT = 10`, so 0.5 × 10 = 5.0.

## Root cause
**`settings.json:2`**, the key is misspelled:
```json
  "rat": 0.5,
```
**`main.py:10-13`** reads a different key, and the error handler hides the miss:
```python
    try:
        rate = cfg["fee_rate"]
    except KeyError:
        rate = 0
```

## Why it gives the wrong result
`app/config.py` loads `settings.json` as-is into `SETTINGS`. That dictionary has no `"fee_rate"` key, so `cfg["fee_rate"]` raises `KeyError`. The `except` block catches it and sets `rate = 0` without any warning. Then `total = 0 * 10 = 0`.

Two other places confirm that `"fee_rate"` is the intended key name:
- `billing/report.py:7` calls `get_setting("fee_rate")`.
- `billing/export/csv_writer.py:8` reads `settings.get("fee_" + "rate")`.

Both of these exit with "fee_rate is missing" when the key is absent. `main.py` is the only place that hides the problem.

## Suggested fix
1. **Main fix:** in `settings.json`, rename `"rat"` to `"fee_rate"`. The output then becomes `Total: 5.0`.
2. **Also recommended:** in `main.py`, stop silently using 0 when the setting is missing. Raise an error or exit with a clear message instead, the way `report.py` and `csv_writer.py` do. That way a missing or misspelled setting fails loudly instead of printing a wrong total.
