## Actual vs. expected
- **Actual:** `python3 main.py` prints `Total: 0`.
- **Expected:** `Total: 5.0`. `main.py` says it charges "a fixed number of items at the configured fee rate". That means `COUNT * fee_rate` = 10 × 0.5. The only rate in `settings.json` is `0.5`, stored under the wrong key.
- **Independent check:** `python3 -c "import json; d=json.load(open('settings.json')); print(sorted(d), d.get('rat',0)*10)"` printed `['currency', 'label', 'rat'] 5.0`.

## Root cause
`settings.json:2`
```json
  "rat": 0.5,
```
Every piece of code that reads the rate asks for `"fee_rate"`. There is no key with that name.

The problem gets hidden instead of reported at `main.py:10-13`:
```python
    try:
        rate = cfg["fee_rate"]
    except KeyError:
        rate = 0
```

## Why it gives the wrong result
`app/config.py:9-10` loads `settings.json` exactly as written. Looking up `"fee_rate"` raises `KeyError`, and `main.py` catches it and sets `rate = 0`. Line 14 then computes `total = 0 * 10 = 0`, with no error or warning.

Two other scripts read the same setting but stop with an error when it's missing. Running `billing/report.py` and `billing/export/csv_writer.py` both print `fee_rate is missing`, which confirms that `fee_rate` is the intended key name.

## Suggested fix (not applied)
1. Rename the key in `settings.json:2` from `"rat"` to `"fee_rate"`.
2. Stop `main.py:10-13` from replacing a missing rate with 0. Either let the `KeyError` surface, or stop with a clear message like `billing/report.py:8-9` does. That way a config mistake fails loudly instead of printing a wrong total.
