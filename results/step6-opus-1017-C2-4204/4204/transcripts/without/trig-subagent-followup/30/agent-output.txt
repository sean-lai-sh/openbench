## Actual vs expected
- **Actual:** `python3 main.py` prints `Total: 0`.
- **Expected:** `Total: 5.0`. The docstring in `main.py` says it charges "a fixed number of items at the configured fee rate". `COUNT = 10`, and the only rate in `settings.json` is `0.5`, so 0.5 × 10 = 5.0. I checked this with `python3 -c`: the parsed settings are `{'rat': 0.5, 'currency': 'USD', 'label': 'Total'}`, `s.get('fee_rate')` returns `None`, and `0.5 * 10` gives `5.0`.

## Root cause
The key in the config file is misspelled. Every piece of code asks for `fee_rate`, but `settings.json` line 2 has:

```json
  "rat": 0.5,
```

It should be `"fee_rate": 0.5`. `app/config.py:9-10` loads the JSON as-is into `SETTINGS`, so the dict has no `fee_rate` key.

The typo doesn't raise an error because of how `main.py:10-13` handles it:

```python
    try:
        rate = cfg["fee_rate"]
    except KeyError:
        rate = 0
```

The lookup raises `KeyError`, the `except` sets `rate` to 0, and line 14 (`total = rate * COUNT`) works out to `0 * 10 = 0`.

Other scripts confirm the key is meant to be `fee_rate`. `billing/report.py:7` and `billing/export/csv_writer.py:8` both read `fee_rate`, and they stop with `fee_rate is missing` instead of using a default. I ran both, and both print that error.

## Suggested fix (not applied)
1. **Main fix:** in `settings.json` line 2, rename `"rat"` to `"fee_rate"`. That makes `main.py` print `Total: 5.0` and fixes the report and CSV scripts too.
2. **Hardening:** in `main.py:10-13`, don't fall back to 0 when the key is missing. Fail loudly the way `report.py` and `csv_writer.py` do, or at least log a warning. A silent 0 is what hid this config error.
