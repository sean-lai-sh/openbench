**What happens:** `python3 main.py` prints `Total: 0`.

**What it should print:** `Total: 5.0`. `main.py` multiplies the fee rate by `COUNT = 10`. The only rate in `settings.json` is `0.5`, and `0.5 × 10 = 5.0`. I checked this with a one-line `python3 -c` command.

### Root cause
The setting's name in the config file is misspelled. The code looks for `fee_rate`, but the file says `rat`.

- `settings.json:2`:
  ```json
  "rat": 0.5,
  ```
- `main.py:10-13` looks up a different name, and quietly uses 0 when it can't find it:
  ```python
  try:
      rate = cfg["fee_rate"]
  except KeyError:
      rate = 0
  ```

`app/config.py` loads `settings.json` as-is into `SETTINGS`. Since there's no `fee_rate` entry, `cfg["fee_rate"]` raises `KeyError`. The `except` block hides that error and sets `rate = 0`, so the total is `0 * 10 = 0` and nothing warns you.

The `fee_rate` name is correct; the config file is what's wrong. `billing/report.py:7` and `billing/export/csv_writer.py:8` (which builds the name as `"fee_" + "rate"`) both look up `fee_rate`. Both stop with "fee_rate is missing" when it isn't there, which confirms the config typo.

### Suggested fix (not applied)
1. **Main fix:** in `settings.json`, rename `"rat"` to `"fee_rate"`. The output then becomes `Total: 5.0`.
2. **Hardening:** in `main.py`, stop turning a missing setting into a rate of 0. Let it fail loudly, the way `billing/report.py` does, so a config mistake like this can't produce a wrong total again.
