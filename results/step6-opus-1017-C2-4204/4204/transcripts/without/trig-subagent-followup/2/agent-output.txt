## Actual vs. expected
- **Actual:** `python3 main.py` prints `Total: 0`
- **Expected:** `Total: 5.0`
  - `main.py` charges `COUNT = 10` items at the configured fee rate (its docstring says "Charge a fixed number of items at the configured fee rate").
  - The only rate-like value in the config is `0.5`, and `python3 -c "print(0.5*10)"` gives `5.0`.
  - This assumes `0.5` is the intended fee rate. Nothing else in the config could be a rate.

## Root cause
**`settings.json:2`** has the wrong key name:
```json
"rat": 0.5,
```
All the code expects the key to be `fee_rate`:
- `main.py:11`: `rate = cfg["fee_rate"]`
- `billing/report.py:7`: `get_setting("fee_rate")`
- `billing/export/csv_writer.py:8`: `settings.get("fee_" + "rate")`

`app/config.py:14-15` loads the JSON as-is into `SETTINGS`, so the dict has `"rat"` but no `"fee_rate"`. In `main.py`, `cfg["fee_rate"]` raises `KeyError`, and this handler hides it:

**`main.py:10-13`**
```python
try:
    rate = cfg["fee_rate"]
except KeyError:
    rate = 0
```
So `rate` becomes 0 and `total = 0 * 10 = 0`, with no error or warning. The typo is the cause; the fallback is what makes it silent.

## Suggested fix
1. **Main fix:** in `settings.json` line 2, rename `"rat"` to `"fee_rate"`. That makes `main.py` print `Total: 5.0`, and it also fixes `billing/report.py` and `billing/export/csv_writer.py`, which would currently exit with "fee_rate is missing".
2. **Hardening (recommended):** in `main.py:10-13`, drop the `except KeyError: rate = 0` fallback. Either let the `KeyError` surface or exit with a clear message like `report.py` and `csv_writer.py` do. Silently treating a missing rate as 0 is what hid this bug.
