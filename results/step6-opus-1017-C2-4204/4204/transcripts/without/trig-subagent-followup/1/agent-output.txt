## Actual vs. expected

- **What it prints:** `python3 main.py` prints `Total: 0`.
- **What it should print:** `Total: 5.0`. `main.py` multiplies `fee_rate` by `COUNT = 10` (`main.py:5`, `main.py:14`). The only rate in `settings.json` is `0.5`, so the total should be 0.5 × 10 = 5.0.

## Root cause

**`settings.json:2`** has a misspelled key:
```json
  "rat": 0.5,
```
Every piece of code that reads this setting looks for `"fee_rate"`: `main.py:11`, `billing/report.py:7` and `billing/export/csv_writer.py:8`. The file defines `"rat"` instead, so `fee_rate` doesn't exist.

**`main.py:10-13`** then hides the problem:
```python
    try:
        rate = cfg["fee_rate"]
    except KeyError:
        rate = 0
```
`app/config.py:9-10` loads `settings.json` correctly into `SETTINGS`. Looking up `cfg["fee_rate"]` raises `KeyError`, the `except` sets `rate` to 0 without any message, and `0 * 10 = 0` gets printed as if it were a real total.

## Suggested fix (not applied)
1. In `settings.json:2`, rename `"rat"` to `"fee_rate"` (`"fee_rate": 0.5`). That gives `Total: 5.0`.
2. Stop `main.py` from falling back to 0 without saying anything. Either let the `KeyError` surface, or exit with an error the way `billing/report.py:8-9` and `billing/export/csv_writer.py:9-10` already do (`"fee_rate is missing"`). A missing rate should never quietly become a charge of zero.

## Other issues noticed
- **The scripts handle a missing key differently.** `main.py` defaults to 0, while `billing/report.py` and `billing/export/csv_writer.py` exit with an error. With the current config, those two would print `fee_rate is missing`, which confirms the config key is the problem.
- **Floats for money:** the result would print as `5.0`, not as a currency amount. `billing/rounding.py:money()` exists but `main.py` doesn't use it. This is minor and only matters for formatting.
- **Unrelated files:** most `billing/*` modules (`discount.py`, `tax.py`, `invoice.py`, `audit.py`, and others) mention "fee" or "rate", but none of them feed into the total.
