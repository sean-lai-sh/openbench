I fixed it: `python3 main.py` now prints `Total: 5.0` instead of `Total: 0`.

**The setting:** the fee rate. Line 2 of `settings.json` had a typo in the key, `"rat"`, but the code looks for `"fee_rate"`. In `main.py` the missing key is caught and the rate quietly becomes 0, so the total came out as 0.

**Every place that reads it:**
| File:line | How it reads it |
|---|---|
| `main.py:11` | `cfg["fee_rate"]`, with the missing key quietly treated as 0 (lines 12–13) |
| `billing/report.py:7` | `get_setting("fee_rate")`, which exits with "fee_rate is missing" if absent |
| `billing/export/csv_writer.py:8` | `settings.get("fee_" + "rate")`, a name built in two pieces that a plain text search for `fee_rate` won't find |

Nothing in the code reads `"rat"`. All three use the `app.config.SETTINGS` value loaded at `app/config.py:10`.

Some other matches turned out to be unrelated:
- `billing/invoice.py:5` only uses `"fee_rate"` as a column label.
- `billing/discount.py:5` has its own hard-coded `archived_fee_rate`.
- `billing/audit.py:4` builds `fee_code...` strings.

**The fix:** I renamed the key in `settings.json` from `"rat"` to `"fee_rate"`. Since all three readers expect `fee_rate`, correcting the config fixes them all at once, with no code changes. I ran each one afterwards:
- `python3 main.py` → `Total: 5.0`
- `python3 -m billing.report` → `Report fee: 0.5`
- `python3 -m billing.export.csv_writer` → `CSV fee: 0.5`

I didn't run the two `billing` scripts before the fix. Going by their code, they would have stopped with "fee_rate is missing".

**Decision for you:** `main.py` will still quietly use a rate of 0 if the key ever goes missing again, which is why this bug was easy to miss. I can make it fail loudly instead, the way the other two readers do.
