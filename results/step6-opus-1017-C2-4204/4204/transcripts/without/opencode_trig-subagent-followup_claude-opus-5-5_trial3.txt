## Actual vs. expected
- **Actual output:** `Total: 0`
- **Expected:** `Total: 5.0`. `settings.json` has one rate value, `0.5`, and `main.py` sets `COUNT = 10`, so 0.5 × 10 = 5.0.

## Root cause
The setting's name is misspelled in the data file, and `main.py` hides the error that this causes.

1. **`settings.json:2`**: the key is spelled wrong:
   ```json
   "rat": 0.5,
   ```
   The code looks up `"fee_rate"`, which doesn't exist in this file.

2. **`main.py:10-13`**: the missing key is silently replaced with 0:
   ```python
   try:
       rate = cfg["fee_rate"]
   except KeyError:
       rate = 0
   ```
   `cfg["fee_rate"]` raises `KeyError`, the `except` sets `rate = 0`, and line 14 (`total = rate * COUNT`) gives 0. No error is shown.

## Suggested fix (not applied)
- Rename the key in `settings.json` from `"rat"` to `"fee_rate"`.
- Also make `main.py` fail loudly when the key is missing, instead of defaulting to 0. `billing/report.py` and `billing/export/csv_writer.py` already do this with `SystemExit("fee_rate is missing")`. That way a bad config can't produce a wrong total without anyone noticing.
