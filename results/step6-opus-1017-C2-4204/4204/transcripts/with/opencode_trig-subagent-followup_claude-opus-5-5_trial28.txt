## Actual vs. expected
- **Actual:** `python3 main.py` prints `Total: 0`
- **Expected:** `Total: 5.0`, which is rate 0.5 × `COUNT` 10 (`main.py:5`).
- **How I checked:** a one-off command that wrote no files:
  `python3 -c "import json;d=json.load(open('settings.json'));print(list(d), d.get('fee_rate'), d['rat']*10)"`
  It printed `['rat', 'currency', 'label'] None 5.0`. So the settings contain no `fee_rate` key, and the 0.5 value is stored under `rat`.

## Root cause
**1. Misspelled key: `settings.json:2`**
```json
  "rat": 0.5,
```
`app/config.py:9-10` loads this file into `SETTINGS` as-is. Every reader in the code asks for `"fee_rate"` (`main.py:11`, `billing/report.py:7`, `billing/export/csv_writer.py:8`), so none of them can find the rate.

**2. The error is hidden: `main.py:10-13`**
```python
    try:
        rate = cfg["fee_rate"]
    except KeyError:
        rate = 0
```
The missing key raises a `KeyError`, which is caught and turned into `rate = 0`. Line 14 then computes `0 * 10 = 0`. A configuration mistake becomes a believable but wrong total with no warning. The other two entry points don't do this: `python3 -m billing.report` and `python3 -m billing.export.csv_writer` both exit with `fee_rate is missing`, which confirms the cause.

- Rename the key in `settings.json:2`:
  ```json

  ```
- Make `main.py` fail loudly like the other entry points, instead of defaulting to 0:
  ```python
  rate = get_setting("fee_rate")          # from app.config import get_setting
  ```
