## Findings

**Actual output:** `Total: 0`
**Expected output:** `Total: 5.0`. The only rate value in `settings.json` is `0.5`, and `main.py:5` sets `COUNT = 10`, so 0.5 × 10 = 5.0.

### What runs
- `main.py` imports only `app.config.SETTINGS`. Nothing in the `billing/` package is imported when `main.py` runs.
- `app/config.py:9-10` loads `settings.json` with `json.load` at import time.

### Root cause
`main.py` looks up a key that doesn't exist in `settings.json`, and a `try/except` hides the miss by using 0 instead.

`settings.json:2`. The key is `"rat"`, but the code expects `"fee_rate"`:
```json
  "rat": 0.5,
```

`main.py:10-13` turns the missing key into a rate of 0 without any warning:
```python
    try:
        rate = cfg["fee_rate"]
    except KeyError:
        rate = 0
```
Line 14 then computes `total = 0 * 10 = 0`.

### Why it's wrong
The settings file has the rate under the wrong name (`rat`). So `cfg["fee_rate"]` raises `KeyError`, and the fallback quietly sets the rate to 0. Every total becomes 0 and nothing reports an error.

`billing/export/csv_writer.py:8-10` reads the same key (`"fee_" + "rate"`), so `fee_rate` is the intended name. That file stops with "fee_rate is missing" when the key is absent, which shows the intended behaviour is to fail loudly, not default to 0.

Some things in `billing/` look related but aren't involved:
- `billing/discount.py:5` has `archived_fee_rate = 0.15`, a local constant that `main.py` never uses.
- `billing/audit.py:4` builds `"fee_code..."` strings, not a settings key.
