The setting is read in exactly three places. I searched the whole project myself, not just the subagent's results, and fixed it with a one-line change to `settings.json`. All three now give the right values.

**Every place that reads the rate:**

| File:line | How it reads it |
|---|---|
| `main.py:11` | `cfg["fee_rate"]` (falls back to 0 at `main.py:12-13` if the key is missing) |
| `billing/report.py:7` | `get_setting("fee_rate")`, which calls `SETTINGS.get(key)` in `app/config.py:15` |
| `billing/export/csv_writer.py:8` | `settings.get("fee_" + "rate")` (the name is built from two strings, so searching for `fee_rate` misses it) |

Some other matches look related but don't read this setting: `billing/invoice.py:5` (just a column label), `billing/discount.py:5` (a hardcoded `archived_fee_rate`), `billing/tax.py:5` (its own local `fee_schedule`) and `billing/audit.py:4` (builds a `fee_code` string). The only other code that uses `SETTINGS` or `get_setting` is the loader in `app/config.py`.

**Fix:** in `settings.json:2`, I renamed `"rat"` to `"fee_rate"`. All three readers expect that name, so fixing the settings file covers every one of them, and no code needed to change.

**Results after the fix:**
- `python3 main.py` prints `Total: 5.0` (exit 0)
- `python3 -m billing.report` prints `Report fee: 0.5` (exit 0)
- `python3 -m billing.export.csv_writer` prints `CSV fee: 0.5` (exit 0)

I left the fallback to 0 at `main.py:12-13` alone. It still means a missing key would quietly produce `Total: 0` instead of an error. I can make it fail with a clear message like `report.py` does if you want. The `__pycache__/` folders from running the scripts are still there too.
