The setting is read in three places. Correcting the key name in `settings.json` fixed all three, and each one now prints the right value.

**Where `fee_rate` is read:**

| File:line | How it reads it |
|---|---|
| `main.py:11` | `cfg["fee_rate"]` |
| `billing/report.py:7` | `get_setting("fee_rate")` |
| `billing/export/csv_writer.py:8` | `settings.get("fee_" + "rate")`. The name is split in two, so a plain search for `fee_rate` misses this one. |

I read every source file to make sure that's the complete list. A few other files mention `fee_` but don't read the setting:
- `billing/invoice.py:5` uses the text `"fee_rate"` only as a column heading.
- `billing/discount.py:5` has its own fixed `archived_fee_rate`.
- `billing/tax.py:5` uses an unrelated `fee_schedule`.
- `billing/audit.py:4` builds `fee_code` strings.

**Changes:**
1. `settings.json:2`: renamed the key from `"rat"` to `"fee_rate"`.
2. `main.py:10-12`: when `fee_rate` is missing, the script now stops with `fee_rate is missing`, the same as the other two. Before, it silently used a rate of 0, which is why the bug showed up as a wrong total rather than an error.

**Output after the fix:**
```
python3 main.py                        -> Total: 5.0
python3 -m billing.report              -> Report fee: 0.5
python3 -m billing.export.csv_writer   -> CSV fee: 0.5
```

I ran the two billing scripts with `python3 -m` from the project root. Running them by file path (e.g. `python3 billing/report.py`) would probably fail to import `app`, though I didn't test that. It's separate from the settings bug, so I left it alone.
