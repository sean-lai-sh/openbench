## Findings

**Actual output:** `Total: 0`
**Expected output:** `Total: 5.0`. `settings.json` gives a rate of `0.5`, and `main.py` charges `COUNT = 10` items, so 0.5 × 10 = 5.0.

`main.py` only imports `app.config`. That module reads `settings.json`. Nothing in `billing/` is imported, so that package plays no part in this bug.

## Root cause

There are two problems that together produce the wrong total.

1. **The key name in the settings file is misspelled.** In `settings.json:2`:
   ```json
   "rat": 0.5,
   ```
   The code looks for `fee_rate`, but the file has `"rat"`. The code shows `fee_rate` is the intended name: `main.py:11`, `billing/report.py:7` and `billing/export/csv_writer.py` all look up `"fee_rate"`.

2. **The missing key is silently replaced with 0.** In `main.py:10-13`:
   ```python
   try:
       rate = cfg["fee_rate"]
   except KeyError:
       rate = 0
   ```
   Because `fee_rate` isn't in the file, `cfg["fee_rate"]` raises `KeyError`. The `except` block then sets `rate = 0`, so `total = 0 * 10 = 0`. The program prints a wrong number instead of reporting a configuration error. For comparison, `billing/report.py` and `billing/export/csv_writer.py` stop with `SystemExit("fee_rate is missing")` in the same situation.

## Suggested fix (not applied)

- In `settings.json`, rename `"rat"` to `"fee_rate"`. The output then becomes `Total: 5.0`.
- In `main.py`, stop falling back to `0` when the key is missing. Let the `KeyError` surface, or exit with a clear message like the `billing` modules do, so a broken config fails loudly next time. body
