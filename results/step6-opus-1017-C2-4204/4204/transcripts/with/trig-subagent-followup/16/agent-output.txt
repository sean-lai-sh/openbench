## Actual vs. expected
- **Actual:** `python3 main.py` prints `Total: 0`
- **Expected:** `Total: 5.0`. The only rate in the config is `0.5` (`settings.json:2`) and `COUNT = 10` (`main.py:5`), so 0.5 × 10 = 5.0.

## Root cause
**`settings.json:2`**
```json
"rat": 0.5,
```
Every piece of code that reads the rate looks for the key `fee_rate`. No `fee_rate` key exists in `settings.json`, so the 0.5 value is never picked up.

**Why it shows up as 0 instead of an error: `main.py:10-13`**
```python
try:
    rate = cfg["fee_rate"]
except KeyError:
    rate = 0
```
`app/config.py:9-10` loads `settings.json` into `SETTINGS` as is. `cfg["fee_rate"]` then raises `KeyError`, the `except` sets `rate = 0`, and line 14 computes `0 * 10 = 0`.

**More evidence it's a config problem, not a `main.py` problem:** the other two scripts that read the same key both fail clearly. I ran each with `PYTHONDONTWRITEBYTECODE=1` so no files were written.
- `python3 -m billing.report` prints `fee_rate is missing` (`billing/report.py:7-9`, uses `get_setting("fee_rate")`)
- `python3 -m billing.export.csv_writer` prints `fee_rate is missing` (`billing/export/csv_writer.py:8-10`)

1. **Main fix:** in `settings.json:2`, rename `"rat"` to `"fee_rate"`. After that, `main.py` should print `Total: 5.0` and both billing scripts should work.
2. **Make `main.py` fail loudly:** remove the `try/except KeyError: rate = 0` at `main.py:10-13`, or replace it with a clear error like `report.py` uses. A missing config key should stop the program, not produce a believable wrong total.
