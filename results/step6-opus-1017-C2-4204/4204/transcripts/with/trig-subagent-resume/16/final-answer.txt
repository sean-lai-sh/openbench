I fixed the crash: `python3 main.py` now prints `Total: 5.0` and exits with code 0.

**Where `rate` becomes None:** at `app/pricing.py:8`, which runs `return SETTINGS.get("rate")`. That key wasn't in the settings, so `.get` quietly returned `None` instead of raising an error. The `None` was then multiplied in `app/report.py:9`, which caused the crash.

**Which key was missing:** I passed the first subagent's session id to the second call, so the same subagent answered. It said the missing key is `"rate"`. In `settings.json:2` it was misspelled as `"rat"`.

**Fix:** I renamed the key to `"rate"` in `settings.json`.

`get_rate()` will still return `None` without warning if the key goes missing again. Changing it to `SETTINGS["rate"]` would make it fail right away with a clear error. I didn't make that change because renaming the key was enough to fix this bug.
