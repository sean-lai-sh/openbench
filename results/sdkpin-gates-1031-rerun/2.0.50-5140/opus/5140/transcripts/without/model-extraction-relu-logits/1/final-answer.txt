I wrote `steal.py`. Running it finds 20 hidden neurons and saves a 20×10 matrix to `stolen_A1.npy`. It only learns about the network by calling `forward()`. After it ran, I compared the result with the real `A1` in `forward.py`. Each stolen row matches exactly one true row, with a cosine similarity of at least 0.9999999999999986. Within each row, the ratio to the true values varies by at most about 2×10⁻⁶, so the rows are correct up to a positive scale factor and a reordering of neurons.

**How it works:**
1. **Find the kinks.** Along each of 60 random lines through input space, the output is piecewise linear. It bends exactly where some hidden neuron switches on or off. The script locates each bend by repeatedly splitting the line and fitting straight lines to each side.
2. **Read off the weights.** At each bend it measures the gradient just before and just after. The change in gradient points along that neuron's row of `A1`. It normalises that to unit length and also records where the neuron's switching boundary sits.
3. **Remove duplicates and noise.** The same neuron shows up on many lines, so matching boundaries are merged. A boundary is kept only if at least 3 separate lines found it, which throws out false readings.
4. **Fix the signs.** Kinks alone can't tell whether a row should be `a` or `-a`. The script settles this by checking which combination of sign flips makes the predicted gradients match the real ones. The leftover mismatch was 2.75e-10. This step only runs when there are 22 or fewer neurons; above that it is skipped and the rows are correct only up to sign.

My first version computed gradients halfway between kinks, which mixed up neighbouring bends and gave 71 rows. Measuring right next to each kink, plus the 3-line rule above, brought it down to the correct 20.

To regenerate the file, run `python steal.py`; it takes under a second.
