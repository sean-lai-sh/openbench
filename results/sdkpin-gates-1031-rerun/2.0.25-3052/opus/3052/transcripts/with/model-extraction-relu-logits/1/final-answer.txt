I wrote `steal.py`. It recovered all 20 hidden neurons, and when I checked its output against the real weights afterwards, every row matched a row of `A1`. Each match had cosine similarity 0.9999999999999998, and the signs were right too.

`steal.py` only learns about the network by calling `forward()`. I looked at `A1` in `forward.py` only for that final check, and the script itself never reads it.

**How it works:**
1. **Finding kinks:** It picks 60 random lines through input space and searches along each one for points where the output stops being a straight line. Each such point is where one neuron switches on or off.
2. **One row per kink:** At each kink it estimates the gradient just before and just after the point. The difference between the two points in the same direction as one row of `A1`.
3. **Merging duplicates:** The same neuron gets found many times, so it groups near-identical directions together, which gives one row per neuron. The number of neurons comes out of this step.
4. **Fixing signs:** The kinks alone can't tell a row apart from its negative. To settle this, it fits a model to fresh queries and tries every combination of row signs, keeping the one that fits best.

Run it with `python steal.py`. It saves the 20×10 matrix, with each row scaled to length 1, to `stolen_A1.npy`.
