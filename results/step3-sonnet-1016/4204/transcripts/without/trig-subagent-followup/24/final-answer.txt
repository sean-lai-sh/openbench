The `fee_rate` setting is read in three places, and all three work now. The cause was the misspelled key in `settings.json`, so I fixed it there and nothing else.

**Where it's read**
| File:line | How it reads it |
|---|---|
| `main.py:11` | `cfg["fee_rate"]`, with a `KeyError` fallback to 0 |
| `billing/report.py:7` | `get_setting("fee_rate")` |
| `billing/export/csv_writer.py:8` | `settings.get("fee_" + "rate")`. The string is built in two pieces, so a plain search for `fee_rate` misses it. |

Four other files mention the name but don't read the setting:
- `billing/invoice.py:4-5` uses it only as a label string.
- `billing/discount.py:5` is a local variable, `archived_fee_rate`, set to 0.15.
- The `SystemExit` messages in `report.py:9` and `csv_writer.py:10` only print the name.

**The fix**
In `settings.json:2` I renamed `"rat"` to `"fee_rate"`.

**Results**
- `python3 main.py` prints `Total: 5.0`. Before the fix it printed `Total: 0`.
- `python3 -m billing.report` prints `Report fee: 0.5`. Before the fix it exited with "fee_rate is missing".
- `python3 -m billing.export.csv_writer` prints `CSV fee: 0.5`. Before the fix it exited with "fee_rate is missing".

I left the `except KeyError: rate = 0` fallback at `main.py:12-13`. It's what hid this bug, since a missing key gave a quiet 0 instead of an error. Removing it would make `main.py` fail loudly like the other two paths. I can do that if you want.
