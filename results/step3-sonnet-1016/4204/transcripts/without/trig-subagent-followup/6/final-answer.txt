The setting `fee_rate` is read in three places, and all three now work. I fixed it by renaming the misspelled key in `settings.json`.

**Where `fee_rate` is read**
- `main.py:11` reads `cfg["fee_rate"]`. A missing key is caught and replaced with `0`.
- `billing/report.py:7` reads `get_setting("fee_rate")` and exits with an error if the value is `None`.
- `billing/export/csv_writer.py:8` reads `settings.get("fee_" + "rate")`. The key is built by concatenation, so a plain search for `fee_rate` misses it. It also exits with an error if the value is missing.

**Matches that don't read the setting**
- `billing/invoice.py:4-5` only uses `"fee_rate"` as a column-name string, and its docstring says it is unused by the total.
- `billing/discount.py:5,8` has a local variable `archived_fee_rate = 0.15` that has nothing to do with the config.
- `app/config.py` loads the JSON and exposes it. It doesn't read this key itself.

**The fix:** in `settings.json` line 2, `"rat": 0.5` is now `"fee_rate": 0.5`.

I ran all three paths after the change:
- `python3 main.py` prints `Total: 5.0`.
- `python3 -m billing.report` prints `Report fee: 0.5`.
- `python3 -m billing.export.csv_writer` prints `CSV fee: 0.5`.

I left the silent `except KeyError: rate = 0` fallback in `main.py` as it was. A misspelled key could still produce a wrong total there without any error. I can make it fail loudly like the other two paths if you want.
