The `fee_rate` setting is read in three places, and all three now work. I fixed the bug by renaming the key in `settings.json` from `"rat"` to `"fee_rate"`.

**Where it's read**

| File | Line | How it reads the key |
|---|---|---|
| `main.py` | 11 | `cfg["fee_rate"]`, with `except KeyError: rate = 0` at lines 12-13 |
| `billing/report.py` | 7 | `get_setting("fee_rate")`, which exits with "fee_rate is missing" if the value is `None` |
| `billing/export/csv_writer.py` | 8 | `settings.get("fee_" + "rate")`, which exits with the same message |

The `csv_writer.py` read builds the key from two strings, so a plain search for `fee_rate` wouldn't find it. I also searched for other indirect reads and found none.

`app/config.py` loads `settings.json` and provides `get_setting`, but it doesn't read this key itself.

These mentions of `fee_rate` or fee-like names are not reads of the setting:
- `billing/invoice.py:5` is a column name string.
- `billing/discount.py:5` is a local variable, `archived_fee_rate = 0.15`.
- `billing/audit.py:4` builds `"fee_code…"` strings.
- `billing/tax.py:5` is a local dict called `fee_schedule`.

**Results after the fix**
- `python3 main.py` prints `Total: 5.0`.
- `python3 -m billing.report` prints `Report fee: 0.5`.
- `python3 -m billing.export.csv_writer` prints `CSV fee: 0.5`.

Before the fix, `report.py` and `csv_writer.py` would have exited with an error. `main.py` was the only one that failed silently.

I left the `except KeyError: rate = 0` fallback in `main.py` alone. It's what hid this bug, so removing it would make a missing key fail loudly. Do you want me to change it?
