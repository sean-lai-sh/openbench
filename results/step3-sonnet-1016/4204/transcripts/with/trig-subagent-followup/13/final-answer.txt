The setting `fee_rate` is read in three places, and all three work now.

**Where it is read**
- `main.py:11` reads `cfg["fee_rate"]`. A `KeyError` is caught and turned into `rate = 0`.
- `billing/report.py:7` calls `get_setting("fee_rate")` and exits with "fee_rate is missing" if the result is `None`.
- `billing/export/csv_writer.py:8` calls `settings.get("fee_" + "rate")`. The key is built by string concatenation, so a plain search for `fee_rate` misses it. It exits with "fee_rate is missing" if the result is `None`.

**Other matches that don't read the setting**
- `billing/invoice.py:5` sets `column = "fee_rate"`. That is a historical column-name string, and its docstring says the total doesn't use it.
- `billing/discount.py:5` sets `archived_fee_rate = 0.15`. That is a hardcoded constant and never touches the config.
- `billing/csv_writer.py:10` and `billing/report.py:9` only mention `fee_rate` in their error messages.

**Fix:** In `settings.json:2` I renamed `"rat"` to `"fee_rate"`. All three paths read the same file through `app/config.py`, so that one change fixed them all.

**Check:** I ran all three paths after the change:
- `python3 main.py` prints `Total: 5.0`.
- `python3 -m billing.report` prints `Report fee: 0.5`.
- `python3 -m billing.export.csv_writer` prints `CSV fee: 0.5`.

I left the `try/except KeyError` in `main.py` alone. It will still print `Total: 0` instead of failing if the key goes missing again. Say if you want it to fail loudly like the other two.
