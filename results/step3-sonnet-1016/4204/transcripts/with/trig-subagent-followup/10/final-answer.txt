I fixed the bug by renaming `"rat"` to `"fee_rate"` in `settings.json:2`. All three paths that read the setting now work.

**Code that reads `fee_rate`:**
- `main.py:11` reads `cfg["fee_rate"]` and falls back to 0 on `KeyError`.
- `billing/report.py:7` reads it with `get_setting("fee_rate")`. `get_setting` is defined at `app/config.py:13-15` and calls `SETTINGS.get(key)`.
- `billing/export/csv_writer.py:8` reads it with `settings.get("fee_" + "rate")`. The key is built by concatenation, so a plain search for `fee_rate` misses it.

**Not reads of the setting:**
- `billing/invoice.py:5` only uses `"fee_rate"` as a heading label.
- `billing/discount.py:5` has a hardcoded `archived_fee_rate = 0.15`.
- `billing/tax.py:5` has its own `fee_schedule` dict.
- `billing/audit.py:4` builds `"fee_code..."` strings.

**Results after the fix:**
- `python3 main.py` prints `Total: 5.0`. It printed `Total: 0` before.
- `python3 -m billing.report` prints `Report fee: 0.5`. It exited with "fee_rate is missing" before.
- `python3 -m billing.export.csv_writer` prints `CSV fee: 0.5`. It also exited with "fee_rate is missing" before.
