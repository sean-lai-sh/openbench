There are three places that read the `fee_rate` setting. I fixed the bug, and all three now work.

**Files that read the setting**
- `main.py:11` reads `cfg["fee_rate"]` directly.
- `billing/report.py:7` reads `get_setting("fee_rate")`.
- `billing/export/csv_writer.py:8` reads `settings.get("fee_" + "rate")`. The key is built by concatenation, so a plain search for `fee_rate` misses it. I found it through its error message and a broader search.

**Files that mention it but don't read it**
- `billing/invoice.py:4-5` only uses `"fee_rate"` as a label string.
- `billing/discount.py:5` has an unrelated local variable named `archived_fee_rate`.
- `billing/audit.py:4` builds `"fee_" + "code"`, which is a different key.
- `billing/tax.py:5` has an unrelated `fee_schedule` variable.

**Fix**
In `settings.json:2` I renamed `"rat"` to `"fee_rate"`. All three readers use the same key, so that one change fixes all of them. I didn't change `main.py`, so its `except KeyError` fallback to 0 is still there. If the key goes missing again, it will silently give a total of 0.

**Verification**
- `python3 main.py` prints `Total: 5.0`.
- `python3 -m billing.report` prints `Report fee: 0.5`.
- `python3 -m billing.export.csv_writer` prints `CSV fee: 0.5`.
