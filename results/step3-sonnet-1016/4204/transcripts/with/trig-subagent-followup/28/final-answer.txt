The setting is read in four places, and one typo in `settings.json` broke all of them. I fixed it, and all three paths that read the setting now work.

**Where `fee_rate` is read:**
| File:line | How it reads it | Behavior with the typo |
|---|---|---|
| `main.py:11` | `cfg["fee_rate"]` | `KeyError` was caught at `main.py:12-13`, so it printed `Total: 0` |
| `billing/report.py:7` | `get_setting("fee_rate")` | Exited with "fee_rate is missing" |
| `billing/export/csv_writer.py:8` | `settings.get("fee_" + "rate")` | Exited with "fee_rate is missing" |

The `csv_writer.py` read builds the key from two strings, so a plain search for `fee_rate` doesn't find it.

**Other matches that don't read the setting:**
- `billing/invoice.py:5` only assigns a local `column` string.
- `billing/discount.py:5` has a hardcoded `archived_fee_rate = 0.15`.
- `billing/audit.py:4` builds `"fee_code…"`.
- `billing/tax.py` has a local `fee_schedule`.

**Fix:** In `settings.json:2` I renamed `"rat"` to `"fee_rate"`.

**Checks:**
- `python3 main.py` prints `Total: 5.0`.
- `billing.report.main()` prints `Report fee: 0.5`.
- `billing.export.csv_writer.main()` prints `CSV fee: 0.5`.

I left the `except KeyError: rate = 0` fallback in `main.py` alone. It turned the typo into a wrong total instead of an error. I can change it to fail loudly like the other two modules if you want.
