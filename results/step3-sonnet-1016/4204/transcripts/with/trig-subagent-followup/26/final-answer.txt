Three files read the `fee_rate` setting. I fixed the bug, and all three now work.

**Files that read the setting**
- `main.py:11` reads `cfg["fee_rate"]`. When the key was missing, it silently fell back to `0`.
- `billing/report.py:7` reads `get_setting("fee_rate")`. When the key was missing, it exited with "fee_rate is missing".
- `billing/export/csv_writer.py:8` reads `settings.get("fee_" + "rate")`. The key is built by string concatenation, so a plain search for `fee_rate` doesn't find it. When the key was missing, it exited with "fee_rate is missing" (line 10).

**Mentions that don't read the setting**
- `billing/invoice.py:5` only uses `"fee_rate"` as a label string. Its docstring (line 4) mentions the name.
- `billing/discount.py:5` and `:8` use a local variable, `archived_fee_rate = 0.15`, which has nothing to do with the config.

**Fix**
- I renamed the key `"rat"` to `"fee_rate"` in `settings.json:2`. All three readers use the same config, so this one change fixes all of them.

**Verification**
- `python3 main.py` prints `Total: 5.0`.
- `python3 -m billing.report` prints `Report fee: 0.5`.
- `python3 -m billing.export.csv_writer` prints `CSV fee: 0.5`.

I left the silent `rate = 0` fallback in `main.py:10-13`. It is what hid this typo, so you may want it to fail loudly instead.
