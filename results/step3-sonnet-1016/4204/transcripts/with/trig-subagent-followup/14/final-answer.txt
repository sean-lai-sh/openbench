Three places read the `fee_rate` setting. All three now work.

| File | Line | How it reads the setting |
|---|---|---|
| `main.py` | 11 | `cfg["fee_rate"]`, with a `KeyError` fallback to 0 |
| `billing/report.py` | 7 | `get_setting("fee_rate")`, which calls `SETTINGS.get(key)` in `app/config.py:15` |
| `billing/export/csv_writer.py` | 8 | `settings.get("fee_" + "rate")`. The key is built by concatenation, so a plain search for `fee_rate` misses it. |

Three other files mention `fee_rate` but don't read the setting:
- `billing/invoice.py:4-5` has a docstring and a local string, `column = "fee_rate"`.
- `billing/discount.py:5,8` has a hardcoded local `archived_fee_rate = 0.15`.
- `app/config.py:9-10` loads `settings.json` and `app/config.py:15` is the lookup helper. This is the loading path, not a separate read.

**Fix:** I renamed `"rat"` to `"fee_rate"` in `settings.json:2`. All three read paths use the same `SETTINGS` dict, so that one edit covers them. I ran each one:
- `python3 main.py` prints `Total: 5.0`.
- `python3 -m billing.report` prints `Report fee: 0.5`.
- `python3 -m billing.export.csv_writer` prints `CSV fee: 0.5`.

I left the silent `KeyError` fallback at `main.py:10-13` alone. It's what hid this bug, so you may want it to fail loudly instead.
