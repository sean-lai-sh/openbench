`python3 -m unittest` now passes all 25 tests. I didn't edit any tests. There were seven separate bugs in `taskflow/`:

- **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority pops first and ties go in insertion order.
- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`config.py`**: `deep_merge` recursed with its arguments swapped, so the base values overrode the task's own. It now recurses with `(result[key], value)`.
- **`events.py`**: `_prefix_matches` had `prefix.startswith(topic + ".")` backwards. It now checks `topic.startswith(prefix + ".")`. This is why the history's failed, skipped and outcome-count queries came back empty.
- **`statemachine.py`**: `batch_order_ok` required priority to be non-decreasing within a batch. The docstring says non-increasing, so I flipped the comparison to `current <= prev`.
- **`scheduler.py`**: `_cascade_skip` only skipped direct dependents. It now uses `dag.transitive_dependents`, so everything downstream of a failed task is skipped.
- **`resources.py`**: `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Pools never freed fully, so resource-limited pipelines stalled.
