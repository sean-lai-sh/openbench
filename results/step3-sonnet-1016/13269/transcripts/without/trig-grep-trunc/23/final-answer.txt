`python3 -m unittest` now passes: all 25 tests, with no test files changed. There were seven bugs, each in a different module:

- **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority pops first and ties go in FIFO order.
- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave one attempt too few. It now uses `attempts_made < max_attempts`.
- **`config.py`**: `deep_merge` recursed with its arguments swapped, so the defaults overrode the task's own settings. It now calls `deep_merge(result[key], value)`.
- **`resources.py`**: `ResourcePool.release` subtracted 1 instead of `cost`. Multi-unit resources leaked capacity and stalled the scheduler.
- **`scheduler.py`**: `_cascade_skip` skipped only direct dependents. It now uses `dag.transitive_dependents`.
- **`statemachine.py`**: `batch_order_ok` had its comparison reversed. It rejected the normal non-increasing priority order within an admission batch and wrongly failed those tasks.
- **`events.py`**: `_prefix_matches` had `topic` and `prefix` swapped. `History` never saw the `job.term.*` events, so the failed, skipped and succeeded sets and the outcome counts were empty.
