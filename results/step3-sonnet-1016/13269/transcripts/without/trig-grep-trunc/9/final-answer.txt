All 25 tests now pass with `python3 -m unittest`. I didn't modify any tests. The failures traced back to eight defects:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so the queue ignored priority and ran in insertion order. It now returns `(-priority, seq)`.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`config.py`:** `deep_merge` swapped its arguments when recursing into nested dicts, so the defaults overrode task-level settings such as `retry`. It now calls `deep_merge(result[key], value)`.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Multi-unit tasks leaked capacity, which blocked later tasks.
- **`events.py`:** `_prefix_matches` had its operands reversed (`prefix.startswith(topic + ".")`). `job.term.*` events never reached `History`, so its failed, skipped and succeeded sets and counts were empty. It now checks `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` required non-decreasing priority, but its docstring says non-increasing. That made the scheduler fail jobs during batch admission. It now checks `current_priority <= prev_priority`.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so skips reach the whole downstream subtree.
