`python3 -m unittest` now passes all 25 tests. I didn't touch any tests. I made seven fixes in five modules:

- **`taskflow/queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so insertion order beat priority. It now returns `(-priority, seq)`.
- **`taskflow/retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`taskflow/config.py`:** `deep_merge` recursed with its arguments swapped, so the pipeline defaults overrode a task's own retry settings. It now calls `deep_merge(result[key], value)`.
- **`taskflow/statemachine.py`:** `batch_order_ok` used `>=`, which allowed priorities to rise within an admission batch. It now uses `<=`, so priorities are non-increasing.
- **`taskflow/scheduler.py`:** `_cascade_skip` only skipped the direct dependents of a failed task. It now uses `dag.transitive_dependents`, so everything downstream is skipped.
- **`taskflow/events.py`:** `_prefix_matches` had the prefix check backwards. It now checks `topic.startswith(prefix + ".")`. Before the fix, `History` never received the `job.term.*` events, which broke its failed, skipped and outcome-count queries.
- **`taskflow/resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Pools never fully released, which blocked later tasks.
