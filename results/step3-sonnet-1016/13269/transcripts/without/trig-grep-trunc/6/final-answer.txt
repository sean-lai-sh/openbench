`python3 -m unittest` now passes: 25 tests, no failures. I didn't touch the tests. There were eight root-cause bugs, all in `taskflow/`, and each was a one-line fix:

- **`queue.py`:** The sort key was `(seq, -priority)`. It is now `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which was off by one. It is now `attempts_made < max_attempts`.
- **`resources.py`:** `ResourcePool.release` did `self.used -= 1` instead of `-= cost`. Multi-unit resources leaked, so tasks waiting on a pool never got admitted.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing within a batch. It now requires `current <= prev`, as its docstring says. The old check failed the second task admitted in any batch.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so defaults overrode a task's own settings. That is why `max_attempts` came out as 1 instead of 3 or 5.
- **`scheduler.py`:** `_cascade_skip` only skipped direct dependents. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.
- **`events.py`:** `_prefix_matches` had the arguments reversed (`prefix.startswith(topic + ".")`). It is now `topic.startswith(prefix + ".")`. Before the fix, `job.term.*` events never reached `History`, so `failed_jobs()` and `outcome_counts()` came back empty.

The failures masked each other, so I fixed and re-ran in rounds. The `resources.py` and `statemachine.py` bugs were also hiding behind the retry and priority failures.
