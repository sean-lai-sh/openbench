`python3 -m unittest` now reports all 25 tests passing. I didn't modify any tests.

I started with the grep for `self` you asked for. It matched 1,325 lines and showed only the first 100, so it didn't help. I ran the suite and read the failures instead.

Most of the failures came from the same few defects. The pipeline tests were failing because of bugs in other modules. I fixed seven defects:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so tasks came out in insertion order. It now returns `(-priority, seq)`, which gives highest priority first with FIFO ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, so the last permitted attempt never ran. It now uses `attempts_made < max_attempts`.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so defaults overrode task settings. It now calls `deep_merge(result[key], value)`.
- **`events.py`:** `_prefix_matches` tested `prefix.startswith(topic + ".")`, the wrong way round. As a result, `job.term.*` events never reached `History`. It now tests `topic.startswith(prefix + ".")`.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`, so multi-unit resource tasks leaked capacity and later tasks were never admitted.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing within an admission batch. The docstring says non-increasing, so it now checks `current <= prev`.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so a failure skips every downstream task.
