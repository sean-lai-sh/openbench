`python3 -m unittest` now passes all 25 tests. I didn't modify any tests.

There were seven separate bugs, each a one-line logic error:

- **`taskflow/queue.py`:** `_Entry.sort_key` ordered by `(seq, -priority)`. It now orders by `(-priority, seq)`, so higher priority runs first and ties go first-in, first-out.
- **`taskflow/retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`taskflow/config.py`:** `deep_merge` recursed with its arguments swapped, so the pipeline defaults overrode a task's own settings. It now recurses with `(result[key], value)`.
- **`taskflow/statemachine.py`:** `batch_order_ok` required priority to be non-decreasing within a batch. It now requires non-increasing, as the docstring says. The wrong check had been failing runs during dispatch.
- **`taskflow/scheduler.py`:** `_cascade_skip` skipped only direct dependents. It now uses `dag.transitive_dependents`, so the whole downstream chain is skipped.
- **`taskflow/resources.py`:** `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Pools never fully freed, which blocked resource-limited tasks.
- **`taskflow/events.py`:** `_prefix_matches` had its arguments reversed: `prefix.startswith(topic + ".")` instead of `topic.startswith(prefix + ".")`. `job.term.*` events never reached `History`, so the failed, skipped and outcome-count queries came back empty.
