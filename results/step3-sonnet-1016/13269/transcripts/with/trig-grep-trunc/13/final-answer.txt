`python3 -m unittest` now passes all 25 tests. I didn't modify any tests. The first grep for `self` matched 1,325 lines and only showed 100, so I ran the suite and read the failing modules instead.

There were seven separate bugs:

- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It is now `attempts_made < max_attempts`.
- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. That ordered the queue by arrival and ignored priority. It now returns `(-priority, seq)`.
- **`statemachine.py`:** `batch_order_ok` had its comparison reversed, so a batch admission rejected valid non-increasing priority order. It is now `current_priority <= prev_priority`.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which only returns direct children. It now uses `dag.transitive_dependents`, so a permanent failure skips everything downstream.
- **`resources.py`:** `ResourcePool.release` did `used -= 1` instead of subtracting the cost. Multi-unit tasks leaked capacity and later work stalled. It now does `used -= cost`.
- **`events.py`:** `_prefix_matches` had the arguments swapped (`prefix.startswith(topic + ".")`). `subscribe_prefix` never matched the subtree, so the history missed terminal events. It is now `topic.startswith(prefix + ".")`.
- **`config.py`:** `deep_merge` recursed with `(value, result[key])`, so the base overrode the override. A task-level `retry` override lost to the defaults. It now recurses with `(result[key], value)`.

Some of these hid others. The priority-order failures were caused by the queue sort key, and the history failures came from the prefix matching. Once those were fixed, the resource, skip and retry failures showed up.
