`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. There were seven defects:

- **`retry.py`:** `should_retry` stopped one attempt early (`attempts_made < max_attempts - 1`). It now uses `attempts_made < max_attempts`, so `max_attempts=3` gives three attempts.
- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own nested settings. It now merges `(result[key], value)`.
- **`resources.py`:** `ResourcePool.release` always subtracted 1 instead of `cost`. This left multi-unit resources stuck as in use.
- **`statemachine.py`:** `batch_order_ok` had its comparison reversed. It rejected the normal high-to-low dispatch order and marked those tasks `FAILED`. It now checks `current_priority <= prev_priority`.
- **`events.py`:** `_prefix_matches` tested `prefix.startswith(topic + ".")` backwards. It now tests `topic.startswith(prefix + ".")`. Without this, `History` never received the `job.term.*` events.
- **`scheduler.py`:** `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `dag.transitive_dependents`, so everything downstream of a permanent failure is skipped.
