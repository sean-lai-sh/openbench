All 25 tests now pass with `python3 -m unittest`. I didn't touch the tests. The initial grep for `self` returned 1,325 matches and only showed 100, so I read the failing code directly instead.

I fixed these seven defects:

1. **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority dispatches first and insertion order breaks ties.
2. **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave one attempt too few. It now uses `attempts_made < max_attempts`.
3. **`config.py`**: `deep_merge` recursed with its arguments swapped, so the defaults overrode a task's own `retry` settings. It now calls `deep_merge(result[key], value)`.
4. **`events.py`**: `_prefix_matches` had the prefix and topic reversed, so a `job.term` subscription never received `job.term.failed` and similar topics. It now checks `topic.startswith(prefix + ".")`. This is why the history's failed, skipped and succeeded sets and outcome counts were empty.
5. **`resources.py`**: `ResourcePool.release` subtracted 1 instead of `cost`, so multi-unit resources leaked and later tasks never got admitted.
6. **`statemachine.py`**: `batch_order_ok` required priorities to be non-decreasing, but its docstring says non-increasing. After the queue fix, this guard failed the second job in a batch. It now checks `current <= prev`.
7. **`scheduler.py`**: `_cascade_skip` skipped only the direct dependents of a failed task. It now uses `dag.transitive_dependents`, so everything downstream is skipped.

Defects 1 and 6 masked each other: the wrong sort order was hiding the wrong guard direction.
