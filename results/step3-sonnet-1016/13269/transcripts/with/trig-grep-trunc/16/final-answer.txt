`python3 -m unittest` now passes: 25 tests, all OK. I didn't modify any tests.

I found seven defects and fixed each at its root. Some were reported under a different module's test name:

- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It is now `attempts_made < max_attempts`.
- **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`, so the queue ignored priority. It now returns `(-priority, seq)`.
- **`resources.py`**: `ResourcePool.release` did `used -= 1` instead of `used -= cost`. Pools leaked capacity, so resource-limited tasks never finished.
- **`events.py`**: `_prefix_matches` had its operands swapped (`prefix.startswith(topic + ".")`). It is now `topic.startswith(prefix + ".")`. Because of this, `History` never received any `job.term.*` events.
- **`statemachine.py`**: `batch_order_ok` required priorities to be non-decreasing within an admission batch. They must be non-increasing, so it now checks `current <= prev`.
- **`config.py`**: `deep_merge` recursed with its arguments reversed, so the defaults overrode the task's own `retry` settings. It now merges `(result[key], value)`.
- **`scheduler.py`**: `_cascade_skip` used `dag.dependents`, which returns only direct children. It now uses `transitive_dependents`, so a failure skips everything downstream.

The bugs did mask each other. After the first few fixes, the retry, priority and resource tests passed. The skip and history tests then showed the cascade bug and the event-prefix bug.
