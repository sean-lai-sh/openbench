`miniconf.loader.load(path)` now expands `@include` directives. The change is in `miniconf/loader.py`.

The existing 13 tests pass. I didn't add new tests for includes. I tried it by hand:
- **Example files:** loading `examples/service.conf` pulls in the `logging` section from `logging.conf`.
- **Cycle:** a file that includes itself raises `ConfigError`.
- **Missing file:** an include of a nonexistent file raises `ConfigError`.

I did not check relative-path resolution from a different working directory, nesting beyond one level, or override ordering.

Behaviours to be aware of:
- **Path resolution:** include paths resolve against the directory of the file containing the directive.
- **Nesting and cycles:** nested includes are expanded recursively, and cycles are detected by following the include chain. Including the same file twice, without a cycle, is allowed.
- **Other `ConfigError` cases:** an `@include` with no path, or a target that can't be read (for example a directory), also raises `ConfigError`.
- **Unchanged paths:** `loads()` and the parser are untouched. `loads()` still ignores `@` lines.
