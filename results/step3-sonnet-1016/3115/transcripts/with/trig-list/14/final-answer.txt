`miniconf.loader.load(path)` now expands `@include` directives, and the 13 existing tests still pass. The change is in `miniconf/loader.py`, with no changes to the parser or `loads`.

- **Inline expansion:** an `@include` line is replaced by the included file's lines before parsing, so later assignments win as usual.
- **Relative paths:** the include path is resolved against the directory of the file containing the directive.
- **Nesting:** includes inside included files are expanded recursively.
- **Missing target:** a missing or unreadable include raises `ConfigError`. A missing top-level file still raises `FileNotFoundError`, as before.
- **Cycles:** direct or indirect cycles raise `ConfigError`.
- **Empty path:** an `@include` line with no path also raises `ConfigError`.

I ran `examples/service.conf` and it picks up the `[logging]` section from `logging.conf`. I also checked a cycle (`a.conf` ↔ `b.conf`) and a missing include by hand, and both raised `ConfigError`. I didn't add tests for `@include` to the test suite.

Line numbers in parse errors now refer to the expanded text, not the original file, whenever includes are present.
