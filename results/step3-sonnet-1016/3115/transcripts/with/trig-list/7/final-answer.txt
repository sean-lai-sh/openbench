`miniconf.loader.load` now expands `@include` directives as specified. The change is in `miniconf/loader.py`.

- **Checks run:** the existing suite passes (13 tests). `examples/service.conf` loads with the `logging` section pulled in. A two-file include cycle and a missing include target each raise `ConfigError`.
- **Not checked:** I didn't separately test relative paths from a different working directory, nested includes that aren't cycles, or override ordering. The code handles them: paths resolve against the including file's directory, includes expand recursively, and expansion is positional.
- **Unchanged behavior:** `loads` and `parse_lines` are untouched. A missing top-level file still raises `FileNotFoundError`, as before.
- **Error line numbers:** `ConfigError` messages for parse problems now show line numbers in the expanded text, not in the original file.
- **Section carry-over:** a section header inside an included file stays active after the include ends. This follows from inline expansion.
- **Repeated includes:** including the same file twice is allowed. Only a real cycle is rejected.
