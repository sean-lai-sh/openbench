`miniconf.loader.load(path)` now expands `@include` directives. The change is in `miniconf/loader.py`.

- **Checks run:** The existing 13 tests pass. `examples/service.conf` loads with the `[logging]` section from `logging.conf` included. I also tried these cases with throwaway files, which I deleted afterwards:
  - **Nesting:** includes resolved relative to the including file's directory, including from a subdirectory.
  - **Override order:** a key set after an include overrides the included value.
  - **Missing target:** raised `ConfigError`.
  - **Cycles:** both a two-file cycle and a self-include raised `ConfigError`.
- **Tests:** I didn't add tests for `@include` to `tests/`.
- **Other errors:** Any unreadable include target is also reported as `ConfigError`, not just a missing one. An `@include` line with no path raises it too.
- **Sections carry over:** The expansion is textual, so a section header inside an included file stays active after the include ends. In `service.conf`, that is why `[http]` has to be declared again after the `@include`.
- **Unchanged paths:** `loads()` and `parse_lines()` are untouched, so `@include` in a string passed to `loads()` is still ignored.
- **Line numbers:** Parse errors in a file that uses includes report line numbers in the expanded text, not in the original file.
