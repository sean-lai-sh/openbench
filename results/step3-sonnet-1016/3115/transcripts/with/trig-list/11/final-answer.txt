`miniconf.loader.load(path)` now expands `@include` directives. The change is in `miniconf/loader.py`.

- **Checks run:** The existing 13 tests pass. I loaded `examples/service.conf` and it pulled in the `[logging]` section from `logging.conf` correctly. A two-file include cycle and a missing include target each raised `ConfigError`. I did not add new tests for includes.
- **Expansion:** Each `@include` line is replaced in place by the included file's lines. Parsing then runs over the expanded text, so later assignments win as usual.
- **Paths and nesting:** Include paths resolve relative to the including file's directory. Nested includes expand recursively.
- **Errors:** A missing or unreadable include target raises `ConfigError`. So does an `@include` with no path. Cycles are caught by tracking the real paths of the files currently being expanded, so symlinks can't hide a loop.
- **Unchanged:** `loads()` and `parse_lines` are untouched, and files without `@include` load as before.

Because expansion is purely textual, an included file's `[section]` header stays in effect for any keys that follow the `@include` line in the including file. That's what "as if written there" implies. In `service.conf`, `[http]` comes after the include, so it isn't affected.

Parse errors in an expanded file report line numbers in the expanded text, not the original file.
