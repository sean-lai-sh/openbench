`miniconf.loader.load(path)` now expands `@include` directives. The existing suite passes (13 tests), and `examples/service.conf` loads with the logging values merged in.

I also checked these cases by hand in a temp directory:
- A direct self-include raises `ConfigError`.
- An `a`→`b`→`a` cycle raises `ConfigError`.
- A missing include target raises `ConfigError`.
- A nested include in a subdirectory resolves relative to the including file.
- A key set after an `@include` overrides the included value.

I did not add these checks to `tests/`.

The change is in `miniconf/loader.py`. `loads()` and the parser are unchanged.

- **Line numbers:** `ConfigError` messages for syntax errors use line numbers from the expanded text, so they can be off when an include comes earlier in the file.
- **Section carry-over:** Because expansion is positional, a section opened in an included file stays active until the next `[section]` header in the parent. This follows from the "as if written inline" rule.
- **Empty path:** An `@include` line with no path raises `ConfigError`.
- **Unreadable includes:** An included file that can't be read or decoded raises `ConfigError`. The top-level file still raises the original `OSError` or `UnicodeDecodeError`, as before.
