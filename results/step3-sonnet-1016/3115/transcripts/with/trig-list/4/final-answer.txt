`miniconf.loader.load(path)` now expands `@include` directives. The change is in `miniconf/loader.py`.

- **Checks run:** the existing 13 tests pass. I loaded `examples/service.conf` and got `logging.level = info`, `name = billing` and `http.port = 8080`. A throwaway cycle (`a.conf` includes `b.conf`, which includes `a.conf`) and a missing include target both raised `ConfigError`. I didn't add new tests to `tests/`.
- **Expansion:** the loader replaces each `@include` line with the referenced file's lines before parsing, so sections, keys, comments and value coercion work as they do now. Nested includes expand recursively, and paths resolve relative to the including file's directory. Override order follows position, because later assignments win.
- **Errors:** an include whose target can't be read raises `ConfigError`. That covers a missing file, and also an unreadable file, a directory, or non-UTF-8 content. An include cycle, direct or indirect, raises `ConfigError`, as does an `@include` with no path.
- **Unchanged:** `loads()`, the parser, and files without `@include` behave as before.

An included file's `[section]` header stays active after the include ends. Keys written after the directive land in that section unless a new header comes first. This follows from the "as if written inline" rule, and `service.conf` avoids it by following the include with `[http]`.
