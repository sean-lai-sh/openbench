`miniconf.loader.load(path)` now expands `@include` directives. The change is in `miniconf/loader.py`.

- **Tests:** the existing suite passes, 13 tests.
- **Example:** loading `examples/service.conf` gives `logging.level = info`, `http.port = 8080` and `name = billing`.
- **Cases I checked:**
  - An included file containing a `../` include resolves relative to itself, not the working directory.
  - A later key overrides an earlier one across includes.
  - A missing include target raises `ConfigError`.
  - A direct self-include and an indirect `a → b → a` cycle both raise `ConfigError`.

I didn't add tests for `@include` to `tests/`.

- **Cycle detection:** it compares real paths, so symlinks to the same file count as a cycle. Including the same file twice without a cycle is allowed.
- **Empty directive:** an `@include` with no path raises `ConfigError`.
- **Missing top-level file:** `load()` on a missing top-level file still raises the same `FileNotFoundError` as before. Only missing include targets raise `ConfigError`.
- **Sections:** an included file that opens a `[section]` leaves that section active for the lines after the `@include`, as if the lines had been written in place. In `examples/service.conf` this is harmless, because `[http]` follows the include.
