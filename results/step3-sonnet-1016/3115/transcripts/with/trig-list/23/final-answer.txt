`miniconf.loader.load(path)` now expands `@include` directives. The change is in `miniconf/loader.py`. The existing 13 tests still pass, and `examples/service.conf` loads with the `logging` section pulled in from `logging.conf`.

- **Where it happens:** includes are expanded into one list of lines before `parse_lines` runs, so parsing and "later assignment wins" behave as before.
- **Paths:** each include is resolved relative to the directory of the file that contains it, and nested includes are expanded recursively.
- **Errors:** a missing or unreadable include target, or a cycle (a file including itself directly or through other files), raises `ConfigError`. I checked a two-file cycle and a missing target by hand. A bare `@include` with no path also raises `ConfigError`.
- **Unchanged:** `loads()` and `parse_lines` are untouched. A missing top-level file still raises the original `OSError`.

I didn't add tests for the new behavior.

Line numbers in parse errors now count the expanded text, so for a file that uses `@include` they can differ from the line numbers in the source file.
