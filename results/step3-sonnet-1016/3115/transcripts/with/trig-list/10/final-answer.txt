`miniconf.loader.load(path)` now expands `@include` directives. The change is in `miniconf/loader.py`.

I ran the existing 13 tests and they pass. I also ran the `examples/` pair and some throwaway files, with these results:
- **Example files:** loading `examples/service.conf` gives `logging.level` of `info` and `http.port` of 8080, so the include works.
- **Ordering:** a key set before an include is overridden by the included file, and a key set after it overrides the included file.
- **Cycles:** both a file including itself and a two-file loop raise `ConfigError`.
- **Missing target:** an include of a file that doesn't exist raises `ConfigError`.
- **Repeated includes:** including the same file twice (not a cycle) is allowed.

Behaviors you might not assume:
- **Section carry-over:** a section header inside an included file stays in effect after the include ends, because expansion is purely textual. A key written after the `@include` line lands in the included file's last section unless you add a new `[section]` header.
- **Top-level missing file:** `load()` on a nonexistent top-level file still raises `FileNotFoundError`, as before. Only a missing include target becomes `ConfigError`.
- **Missing path:** an `@include` line with no path also raises `ConfigError`.
- **Error line numbers:** parse errors report line numbers in the expanded text, not the original file.

I didn't add tests for includes to `tests/`.
