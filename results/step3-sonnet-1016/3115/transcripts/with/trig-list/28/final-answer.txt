`miniconf.loader.load(path)` now expands `@include` directives, and the existing test suite still passes (13 tests). The change is all in `miniconf/loader.py`.

- **Example files:** Loading `examples/service.conf` pulls in the `logging` section from `logging.conf` as expected.
- **Missing and cyclic includes:** I checked these with throwaway files, which I've since deleted. A missing include target and an `a → b → a` cycle both raise `ConfigError`. I didn't add tests for either case, or for nesting and override order.
- **Expansion:** Each `@include <path>` line is replaced inline by the included file's lines, recursively. Paths resolve relative to the file containing the directive.
- **Cycles:** Cycles are caught by tracking the real paths of the files currently being expanded, so symlinks can't hide one.
- **Error behaviour:** A bare `@include` with no path also raises `ConfigError`, as does an include target that can't be read (for example a directory or bad encoding). A missing top-level file still raises `FileNotFoundError` as before.
- **Error line numbers:** After expansion, line numbers in parse errors count lines of the expanded text, not the original file.
- **Unchanged:** `loads()` is unchanged and still ignores `@` lines. Files with no `@include` parse exactly as before.
