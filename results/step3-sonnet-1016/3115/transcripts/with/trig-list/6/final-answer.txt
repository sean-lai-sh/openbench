`miniconf.loader.load(path)` now expands `@include` directives inline. The change is in `miniconf/loader.py`.

- **Verification:** The existing suite still passes (13 tests). `examples/service.conf` loads with the `logging` section pulled in. I also checked a two-file include cycle and a missing include target by hand, and both raise `ConfigError`. I didn't add tests for the new behavior.
- **Paths and nesting:** Include paths resolve relative to the directory of the file containing the directive. Nested includes expand recursively.
- **Errors:** A missing or unreadable target raises `ConfigError`, and so does any cycle, direct or transitive. An `@include` line with no path also raises `ConfigError`, which the spec didn't cover.
- **Unchanged behavior:** `loads` and `parse_lines` are untouched, and files without `@include` load as before.
- **Line numbers:** Parser error messages report line numbers in the expanded text, so they can be off for files that use includes.
