`miniconf.loader.load(path)` now expands `@include` directives, and the existing 13 tests still pass. The change is in `miniconf/loader.py`.

- **Example files:** `load('examples/service.conf')` pulls in `logging.conf` and gives the `[logging]` section, with `level` as `info` and `json` as `True`.
- **Cycles and missing files:** I checked these by hand with throwaway files. A cycle (a.conf includes b.conf, which includes a.conf) raises `ConfigError`. A missing include target also raises `ConfigError`. I did not add tests for includes to the suite.
- **Relative paths:** each include is resolved against the directory of the file that contains it. Nested includes expand recursively.
- **Top-level file errors:** if the file passed to `load()` itself is missing, you still get the original `FileNotFoundError`, since that is existing behavior.
- **Empty path:** a bare `@include` with no path raises `ConfigError`, which the spec didn't cover.
- **Section carry-over:** expansion is plain text substitution, so a section header inside an included file stays active for the lines after the `@include`. In `service.conf`, the `[http]` header is what ends the `[logging]` section.
- **Line numbers:** parse errors report line numbers in the expanded text, so they can differ from the original file's line numbers when includes are present.
