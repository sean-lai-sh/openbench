`miniconf.loader.load` now expands `@include` directives. The existing 13 tests pass.

I also ran an ad-hoc script against temporary files. It showed:
- **Overrides:** a key set after an include overrides the included value, and the include overrides keys set before it.
- **Nesting and paths:** nested includes work, and paths resolve relative to the including file's directory.
- **Errors:** a missing target and a cycle both raise `ConfigError`.
- **Example files:** `examples/service.conf` loads with the `logging` section merged in.

I did not add tests for includes to `tests/`.

The change is in `miniconf/loader.py`. `loads()` and the parser are untouched, so `@include` is still ignored there. A bare `@include` with no path also raises `ConfigError`, which the spec didn't cover.

An include isn't scoped to its own section. If the including file is inside `[http]` and the included file has no section header, its keys land in `[http]`. This follows from "as if those lines had been written where the directive appears".
