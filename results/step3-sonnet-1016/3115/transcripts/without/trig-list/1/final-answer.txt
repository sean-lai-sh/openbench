`miniconf.loader.load(path)` now expands `@include` directives. The change is in `miniconf/loader.py`.

- **Checks run:** The 13 existing tests pass. `examples/service.conf` loads with the `logging` section included. A two-file cycle (`a.conf` and `b.conf` including each other) and a missing include target each raise `ConfigError`.
- **Cycle detection:** It follows the chain of files currently being expanded. A file included twice from different places, with no loop, is still allowed.
- **Errors:** An `@include` with no path, or an included file that can't be read, also raises `ConfigError`.
- **Top-level file:** If `load` is given a path that doesn't exist, it still raises `FileNotFoundError`, as before.
- **Sections:** The current `[section]` carries into an included file, and a section the include opens stays active after it. That follows from expanding the lines in place.
- **Error line numbers:** Parser errors report line numbers in the expanded text, not in the original file.
