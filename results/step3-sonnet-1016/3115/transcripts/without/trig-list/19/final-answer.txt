`miniconf.loader.load(path)` now expands `@include` directives, and the change is in `miniconf/loader.py`.

I ran the existing 13 tests and they pass. I also ran `examples/service.conf`, which loads with `logging.level` = `info` and `http.port` = `8080`. In a throwaway test, a cycle (`a.conf` → `b.conf` → `a.conf`) and a missing include target each raised `ConfigError`. I didn't add new tests to `tests/`.

- **Expansion:** an `@include` line is replaced in place by the included file's lines. This works recursively, and paths resolve relative to the including file's directory.
- **Ordering:** because expansion is positional, a key set after an include overrides the included value. A key set before it is overridden by the include.
- **Section carry-over:** an included file's last `[section]` stays active for the lines after the include, as if they had been written inline. For example, in `examples/service.conf` the `[logging]` section from `logging.conf` is still active until `[http]` appears.
- **Errors:** a missing include target, a cycle, or an `@include` with no path raises `ConfigError`. A missing top-level file still raises the original `FileNotFoundError`, so existing behavior is unchanged.
- **Repeated includes:** including the same file twice without a cycle is allowed.
- **Line numbers:** parse errors report line numbers in the expanded text, not in the original file.
