`miniconf.loader.load(path)` now expands `@include` directives, and the existing 13 tests still pass. I made the change in `miniconf/loader.py`.

- **Expansion:** an `@include` line is replaced in place by the lines of the referenced file. Nested includes are expanded recursively, and the combined text then goes through `parse_lines` as before.
- **Paths:** each include path is resolved relative to the directory of the file that contains it.
- **Errors:** a missing or unreadable include target raises `ConfigError`. A cycle, direct or transitive, also raises `ConfigError`. An `@include` with no path raises `ConfigError` too.
- **Unchanged:** `loads()` and the parser are untouched. A missing top-level file still raises `FileNotFoundError`, as it did before.

I ran `examples/service.conf` and got the `logging` section from the included file. In a throwaway test, `x=1` before an include is overridden by the included `x=2`, and `x=3` after the include overrides it. A two-file cycle and a missing target both raised `ConfigError`.

Expansion is purely textual, so a section header inside an included file stays active for the lines after the `@include`. In `service.conf`, any key placed after the include but before `[http]` would land in `[logging]`. This follows from the "as if written in place" rule you specified.
