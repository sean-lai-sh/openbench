`miniconf.loader.load(path)` now expands `@include` directives, and the existing 13 tests still pass. The change is in `miniconf/loader.py`.

- **Expansion and paths:** `@include` lines are replaced inline by the included file's lines before parsing. Paths resolve relative to the including file, and nested includes expand recursively.
- **Errors:** A missing or unreadable target raises `ConfigError`. So does an `@include` with no path. A file that includes itself, directly or through other files, also raises `ConfigError`. Including the same file twice without a cycle is allowed.
- **Checks I ran:** `examples/service.conf` loads with `logging.level` = `info`, `http.port` = 8080 and `name` = `billing`. A two-file cycle and a missing include target both raised `ConfigError`. I didn't test the before/after override ordering directly.
- **Not changed:** `loads()` is untouched, so `@include` is still ignored there. I didn't add new tests to the suite.
- **Line numbers:** Parse errors in a file that uses includes report line numbers in the expanded text, not the original file.
