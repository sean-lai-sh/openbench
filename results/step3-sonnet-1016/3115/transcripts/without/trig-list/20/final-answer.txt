`miniconf.loader.load(path)` now expands `@include` directives, and the existing tests still pass (13 of 13). The change is in `miniconf/loader.py`.

- **Inline expansion:** an `@include` line is replaced by the included file's lines, and the parser then runs over the expanded text. Later assignments win, so keys before or after an include override as the spec describes.
- **Relative paths:** each include path is resolved against the directory of the file that contains the directive. Nested includes expand recursively.
- **Missing target:** a missing or unreadable include raises `ConfigError`.
- **Cycles:** a direct or transitive cycle raises `ConfigError`. The same file included twice without a cycle is allowed.
- **Empty directive:** an `@include` with no path also raises `ConfigError`. You didn't specify this case.
- **Top-level file:** if the file you pass to `load` is missing, it still raises the original `OSError`, as before.
- **`loads` and other `@` lines:** `loads()` is unchanged and does not expand includes. Other lines starting with `@` are still ignored by the parser.

I checked `examples/service.conf` after the change. It gives `name=billing`, `logging.level=info` and `http.port=8080`. I also checked a cycle and a missing include by hand. Both raised `ConfigError`. I didn't add new test cases to `tests/`.
