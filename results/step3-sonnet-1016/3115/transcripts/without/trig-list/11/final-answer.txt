`miniconf.loader.load(path)` now expands `@include` directives, following the semantics you listed. The change is in `miniconf/loader.py`. The existing 13 tests pass.

I also ran `examples/service.conf` and a few throwaway files in a temp directory:
- **Example:** `service.conf` loads with `logging.level` = `info` and `http.port` = `8080`.
- **Nesting and override:** a nested include through a subdirectory resolves relative to the including file. A key assigned after an include overrides the included value, and an include overrides a key assigned before it.
- **Errors:** a missing include target raises `ConfigError`. So do a file that includes itself and a two-file cycle.

I didn't add tests for `@include` to `tests/`.

- **Error line numbers:** errors raised during parsing report line numbers in the expanded text, not in the original file. Include-specific errors (missing file, empty path) do show the file and line of the directive.
- **Section carry-over:** an included file's `[section]` header stays active after the include ends. A key written after the include with no new header lands in that section, as it would with the text pasted in.
- **Missing top-level file:** a missing top-level file still raises `FileNotFoundError`, as before. Only missing include targets raise `ConfigError`.
- **Empty path:** an `@include` with no path raises `ConfigError`. You didn't specify this case.
- **`loads()`:** it doesn't expand includes, as you specified.
