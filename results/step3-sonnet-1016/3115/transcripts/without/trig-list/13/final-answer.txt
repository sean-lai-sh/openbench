`miniconf.loader.load(path)` now expands `@include` directives. The change is in `miniconf/loader.py`. The existing 13 tests still pass. I didn't add new tests for includes; I checked them with a throwaway script.

- **Expansion:** an `@include <path>` line is replaced in place by the included file's lines. Includes nest recursively, and the path is resolved relative to the including file's directory.
- **Override order:** later assignments win after expansion. With `examples/service.conf` I got `level` = `info` in `[logging]` and `port` = `8080` in `[http]`.
- **Errors:** a missing include target raises `ConfigError`. So does a self-include or a cycle across files (I tried `a→b→a` and `s→s`). I also made an `@include` with no path raise `ConfigError`, which the spec didn't ask for.
- **Unchanged:** `loads()` and the parser are untouched. A missing top-level file still raises the plain `FileNotFoundError`, as before. Only include targets are wrapped in `ConfigError`.

Because expansion is purely textual, a `[section]` header inside an included file stays active for the lines after the `@include`. In `service.conf` that's harmless because `[http]` follows.

Parse-error line numbers now count lines in the expanded text, not in the original file.
