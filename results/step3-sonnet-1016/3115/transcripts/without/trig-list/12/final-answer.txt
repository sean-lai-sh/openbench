`miniconf.loader.load(path)` now expands `@include` directives, and `miniconf/loader.py` is the only file I changed. The existing suite still passes (13 tests). I tried it on `examples/service.conf` and a few throwaway files, but I didn't add new tests to `tests/`.

- **Example files:** `service.conf` pulls in `logging.conf` correctly. `logging.level` came out as `info` and `http.port` as `8080`.
- **Override order:** with `x=1` before an `@include` of a file that sets `x=2`, the result is `x=2`, as the spec describes.
- **Cycles:** a file that includes itself, directly or through another file, raises `ConfigError` instead of looping.
- **Missing target:** an include of a file that doesn't exist raises `ConfigError`.
- **Unreadable or empty includes:** a target that can't be read, or an `@include` with no path, also raises `ConfigError`. I added that case since the spec didn't cover it.
- **Same file included twice:** this is allowed, as long as it isn't a cycle.
- **Top-level file:** if the file you pass to `load` is missing, you still get the same error as before. Only include targets are wrapped in `ConfigError`.
- **Sections after an include:** because expansion is inline, the last `[section]` in an included file stays active for the lines after the `@include`.

I didn't touch `loads()`, since the spec limits this to `load()`.
