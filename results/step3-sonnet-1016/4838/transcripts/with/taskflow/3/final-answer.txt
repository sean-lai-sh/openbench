`python3 -m unittest` now passes: all 25 tests, with no test files modified. I found and fixed seven defects. The tests only exposed some of them directly, so I fixed the rest from what the docstrings said the code should do.

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave one attempt too few. It now uses `attempts_made < max_attempts`.
- **`statemachine.py`:** `batch_order_ok` had its comparison backwards. It now requires `current_priority <= prev_priority`, matching the "non-increasing priority within a batch" rule.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`. Multi-unit resources leaked capacity and the pipelines stalled.
- **`events.py`:** `_prefix_matches` had its operands reversed, so a prefix subscriber never saw its own subtree. It now checks `topic.startswith(prefix + ".")`.
- **`scheduler.py`:** `_cascade_skip` skipped only direct dependents. It now uses `dag.transitive_dependents`, so a permanent failure skips everything downstream.
- **`config.py`:** `deep_merge` recursed as `deep_merge(value, result[key])`, which let the base win over the override. It now recurses as `deep_merge(result[key], value)`, so overrides win at every leaf.
