`python3 -m unittest` now passes all 25 tests. I didn't edit the tests. There were six root causes, and several of the failures shared one:

- **`queue.py`**: `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority goes first and insertion order breaks ties.
- **`retry.py`**: `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It is now `attempts_made < max_attempts`.
- **`events.py`**: `_prefix_matches` had the arguments reversed (`prefix.startswith(topic + ".")`). It is now `topic.startswith(prefix + ".")`.
- **`statemachine.py`**: `batch_order_ok` required priority to be non-decreasing within an admission batch. The docstring says non-increasing, so I changed `>=` to `<=`.
- **`resources.py`**: `ResourcePool.release` subtracted 1 instead of the cost, which leaked capacity for any task with a cost above 1. It now subtracts `cost`.
- **`config.py`**: `deep_merge` recursed with the base and override swapped, so defaults overrode task values. The recursion is now `deep_merge(result[key], value)`.
- **`scheduler.py`**: `_cascade_skip` skipped only the direct dependents of a failed task. It now uses `dag.transitive_dependents`, so everything downstream is skipped.
