Fix the failing tests in the `taskflow` package (an in-memory job-orchestration engine) so that `python3 -m unittest` passes. The tests are the spec and must not be modified. Work was done in `/tmp/obench-cell-p26vlewk/bench_opencode_taskflow_cjfaw3z9`.

### Result
The suite started at 18 failures out of 25 tests. After the seven fixes below, **all 25 tests pass** (`Ran 25 tests ... OK`).

### Root causes fixed
Each was a logic error where the code contradicted its own docstring.

1. **`taskflow/queue.py`**, `_Entry.sort_key`: it returned `(self.seq, -self.priority)`, so the queue was FIFO only. It now returns `(-self.priority, self.seq)`, giving higher priority first and FIFO within a priority.
2. **`taskflow/retry.py`**, `RetryPolicy.should_retry`: it used `attempts_made < max_attempts - 1`, an off-by-one that denied the last permitted attempt. It now uses `attempts_made < max_attempts`.
3. **`taskflow/statemachine.py`**, `batch_order_ok`: the comparison was inverted (`current >= prev`). It is now `current_priority <= prev_priority`, matching the "non-increasing priority within a batch" invariant. This bug was masked by the queue ordering bug.
4. **`taskflow/scheduler.py`**, `_cascade_skip`: it iterated `dag.dependents(...)`, which returns only direct children. It now iterates `dag.transitive_dependents(...)`, so a permanent failure skips the whole downstream subtree.
5. **`taskflow/config.py`**, `deep_merge`: the recursive call had its arguments swapped (`deep_merge(value, result[key])`), so base values overrode task overrides in nested dicts. It is now `deep_merge(result[key], value)`. This bug was masked by the retry bug, since the per-task `retry.max_attempts` was being lost.
6. **`taskflow/resources.py`**, `ResourcePool.release`: it did `self.used -= 1` instead of `-= cost`, which leaked pool capacity for any cost above 1. It now does `self.used -= cost`.
7. **`taskflow/events.py`**, `_prefix_matches`: the check was reversed (`prefix.startswith(topic + ".")`). It is now `topic.startswith(prefix + ".")`, so `job.term` subscribers receive `job.term.failed` and `job.term.skipped`. This fixed the History tests.
