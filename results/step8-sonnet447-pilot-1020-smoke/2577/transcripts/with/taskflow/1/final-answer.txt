`python3 -m unittest` now passes all 25 tests. I didn't modify any tests.

There were six root causes:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`. It now returns `(-priority, seq)`, so higher priority dispatches first and equal priorities are FIFO.
- **`retry.py`:** `should_retry` was off by one (`attempts_made < max_attempts - 1`). It now uses `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` had its arguments reversed (`prefix.startswith(topic + ".")`). It now uses `topic.startswith(prefix + ".")`.
- **`statemachine.py`:** `batch_order_ok` required priority to be non-decreasing. It now requires non-increasing, as its docstring says.
- **`config.py`:** `deep_merge` recursed with its arguments swapped, so defaults overrode a task's own values. That made per-task `retry` settings lose to the defaults. It now recurses as `deep_merge(result[key], value)`.
- **`scheduler.py`:** `_cascade_skip` used the direct `dependents`, so only immediate children were skipped. It now uses `transitive_dependents`.
- **`resources.py`:** `ResourcePool.release` subtracted 1 instead of `cost`, so multi-unit tasks leaked capacity and later tasks never got admitted.

The state-machine, event-bus and history failures all came from these same defects. The `state_machine` guard and the event-bus prefix match are not covered by a direct test, so their fixes rest on the docstrings. I didn't change any other code.
