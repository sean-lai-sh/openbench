`python3 -m unittest` now passes all 25 tests. I didn't touch the tests. There were six defects, and all the fixes are small:

- **`queue.py`:** `_Entry.sort_key` returned `(seq, -priority)`, so the queue ignored priority. It now returns `(-priority, seq)`.
- **`retry.py`:** `should_retry` used `attempts_made < max_attempts - 1`, which gave up one attempt early. It now uses `attempts_made < max_attempts`.
- **`events.py`:** `_prefix_matches` had its arguments reversed. It now uses `topic.startswith(prefix + ".")`, so prefix subscribers receive their subtree.
- **`statemachine.py`:** `batch_order_ok` required priorities to be non-decreasing. It now requires `current <= prev`, matching the docstring.
- **`config.py`:** `deep_merge` recursed with `(override, base)`, so defaults overrode a task's own settings. It now recurses with `(base, override)`.
- **`scheduler.py`:** `_cascade_skip` skipped only direct dependents. It now uses `dag.transitive_dependents`.
- **`resources.py`:** `ResourcePool.release` subtracted `1` instead of `cost`. Multi-unit tasks therefore never returned their full cost, and later tasks stayed stuck in `READY`.

Several fixes uncovered others. The retry and priority tests were hiding the scheduler's direct-dependents-only skip. The resource tests only failed once the queue ordering was right.
