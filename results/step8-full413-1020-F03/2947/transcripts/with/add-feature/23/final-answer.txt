`miniconf.loader.load(path)` now expands `@include` directives, and the full test suite passes (18 tests, including the new ones). Running it on `examples/service.conf` gives `level` = `info` and `port` = `8080`.

The implementation is in `miniconf/loader.py`.

- **Expansion:** An `@include` line is replaced inline by the included file's lines before parsing. Because of that, sections and overrides behave as if the text had been written in place. A `[section]` opened inside an include stays active after the include ends.
- **Paths:** Each include is resolved relative to the directory of the file containing the directive. Nested includes work recursively.
- **Errors:** A missing or unreadable target raises `ConfigError`. So does an `@include` with no path, and so does a cycle, whether direct, transitive, or a file including itself. Cycles are detected on the real path, so `../a.conf` and `a.conf` count as the same file.
- **Diamond includes:** Two files that both include the same third file are allowed, since that isn't a cycle.
- **No-include files:** A file with no `@include` line takes the original code path, so `loads()` and existing behaviour are unchanged.
- **Tests:** I added tests to `tests/test_loader.py` for ordering and override, relative and nested paths, a missing file, cycles, and the diamond case.

If a file with includes has a syntax error, the line number in the `ConfigError` refers to the expanded text, not the original file.
