`miniconf.loader.load(path)` now expands `@include` directives, and all 19 tests pass. That's the 13 existing tests plus 6 new ones in `tests/test_loader.py`. Loading `examples/service.conf` gives `logging.level = info`, `http.port = 8080` and `name = billing`.

The change is in `miniconf/loader.py`. It follows the semantics you listed:

- **Inline expansion:** the `@include` line is replaced by the included file's lines before parsing. A line counts as a directive when its first token is `@include`, so `# @include x` stays a comment.
- **Relative paths:** the path is resolved against the directory of the file containing the directive.
- **Nesting:** included files are expanded recursively.
- **Errors:** a missing target, an unreadable target, or an `@include` with no path raises `ConfigError`.
- **Cycles:** a self-include or a transitive loop raises `ConfigError`, tracked per include chain by real path. Including the same file twice, not as a loop, is allowed.

Some behaviours to be aware of:

- **Sections carry over:** expansion is purely textual, so a `[section]` opened inside an included file stays active for the lines after the `@include`. The example works because `service.conf` opens `[http]` itself right after the include.
- **Line numbers:** parse errors report line numbers in the expanded text, not the original file.
- **Top-level file:** a missing top-level file still raises `FileNotFoundError`, as before.
- **Other functions:** `loads()` and `parse_lines` are unchanged.

I also added tests for override order, nested includes resolved relative to the including file, a missing include, a self-include, a transitive cycle, and a repeated non-cyclic include.
