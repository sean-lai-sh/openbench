`miniconf.loader.load(path)` now expands `@include` directives. The change is in `miniconf/loader.py`.

I ran the existing 13 tests and they pass. A quick script also checked these cases:
- **Example files:** `examples/service.conf` loads and picks up the values from `logging.conf`.
- **Nesting:** includes in subdirectories resolve relative to the including file, so a chain of three files worked.
- **Errors:** a missing include target, a transitive cycle and a file that includes itself all raise `ConfigError`.

I didn't add new tests to `tests/` for any of this.

- **Sections carry over:** expansion is purely textual, so a `[section]` header inside an included file stays active for the lines after the `@include` in the parent. In `examples/service.conf` this is harmless because `[http]` follows the include. In a file where plain keys come after an include that ends inside a section, those keys would land in that section.
- **Cycle detection:** only a file that includes one of its own ancestors is an error. Including the same file twice from different places is allowed.
- **Missing top-level file:** a missing file passed directly to `load()` still raises `FileNotFoundError`, as before. Only missing include targets raise `ConfigError`.
- **Bare `@include`:** an `@include` with no path raises `ConfigError`.
- **`loads()`:** it is unchanged and doesn't expand includes.
- **Line numbers:** parse-error line numbers now count lines in the expanded text, so they shift in files that use includes.
