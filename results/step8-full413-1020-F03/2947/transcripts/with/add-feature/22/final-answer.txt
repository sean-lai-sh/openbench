`miniconf.loader.load(path)` now expands `@include` directives, and the change is in `miniconf/loader.py`. The existing tests pass (13 run with `unittest`, since pytest isn't installed here). I didn't add new tests for includes.

I also ran `examples/service.conf` and two temporary files that I deleted afterwards. The example loads with `logging` expanded in place. A cyclic include and a missing include target both raise `ConfigError`.

- **Directive:** a line whose first token is exactly `@include` is replaced by the contents of the referenced file, expanded recursively. An `@include` with no path raises `ConfigError`.
- **Paths:** the include path is resolved relative to the directory of the file that contains the directive.
- **Cycles:** I track the chain of files being included, so a file that includes itself, directly or through other files, raises `ConfigError`. Including the same file twice without a cycle is allowed.
- **Unreadable targets:** any `OSError` while reading an include, such as a directory instead of a file, also raises `ConfigError`. The same now applies to the top-level file, so `load()` on a missing file raises `ConfigError` instead of `FileNotFoundError`. If you need the old exception there, I can restore it.
- **Line numbers:** parse errors report line numbers in the expanded text, not the original file.
- **Unchanged:** `loads()` and `parse_lines` are untouched, so `loads()` still ignores `@include` lines.
