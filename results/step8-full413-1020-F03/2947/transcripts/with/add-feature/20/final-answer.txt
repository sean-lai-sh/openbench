`miniconf.loader.load(path)` now expands `@include` directives as the spec describes. The existing 13 tests pass. I also ran `examples/service.conf` and a few throwaway files, but I didn't add any tests to `tests/`.

- **Example files:** loading `examples/service.conf` gives `logging.level = info` and `http.port = 8080`.
- **Ordering:** with `x=1` followed by an include that sets `x=2`, the result is `x = 2`.
- **Relative paths and nesting:** a nested include through a subdirectory (`sub/h` including `i`) resolved correctly.
- **Errors:** a missing include target, a file that includes itself, and a two-file cycle each raise `ConfigError`.
- **Missing top-level file:** `load()` on a nonexistent path still raises `FileNotFoundError`, as it did before.

- **Cycle detection:** it compares real file paths, so a symlink back to a file that's already being included also counts as a cycle. The same file included twice without a cycle is fine.
- **Malformed include:** an `@include` line with no path raises `ConfigError`.
- **Section carry-over:** included text is spliced in as-is, so an include doesn't reset the current section. If the included file has no `[section]` header, its keys go into whatever section was active at the include.
- **Error line numbers:** `ConfigError` messages from a parse error inside an expanded file report line numbers in the expanded text, not the original file.

The change is in `miniconf/loader.py`; `loads()` and the parser are untouched.
