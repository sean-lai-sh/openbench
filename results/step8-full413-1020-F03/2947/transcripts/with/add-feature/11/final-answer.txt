`miniconf.loader.load(path)` now expands `@include` directives, and the 13 existing tests pass. I ran them with `unittest` because pytest isn't installed here. I didn't add tests for the new behaviour. I only checked it by hand.

I ran three manual checks:
- **Example files:** `examples/service.conf` loads with the `logging` section from `logging.conf` filled in.
- **Cycle:** two files that include each other raise `ConfigError`.
- **Missing target:** an include of a nonexistent file raises `ConfigError`.

The change is in `miniconf/loader.py`.

- **Path handling:** include paths are resolved against the including file's real directory. A diamond (the same file included from two places) is allowed.
- **Section carry-over:** because expansion is purely inline, the current `[section]` carries across an include boundary. If an included file ends inside a section, keys after the `@include` line in the parent land in that section. This follows from "as if written where the directive appears".
- **Line numbers:** parse errors report line numbers in the expanded text, not in the original file.
- **Empty path:** an `@include` line with no path raises `ConfigError`.
- **Unreadable include:** an included file that can't be read or decoded raises `ConfigError`.
- **Top-level file:** a missing top-level file still raises the same `OSError` as before. `loads` is unchanged.
