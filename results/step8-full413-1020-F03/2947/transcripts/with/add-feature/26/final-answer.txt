`miniconf.loader.load(path)` now expands `@include` directives, and the 13 existing tests pass. They ran under `unittest` because pytest isn't installed. I didn't add new tests to the suite.

I checked it by hand:
- `examples/service.conf` loads with the `[logging]` section from `logging.conf` pulled in.
- A two-file cycle (`a.conf` includes `b.conf`, which includes `a.conf`) raises `ConfigError`.
- An include of a file that doesn't exist raises `ConfigError`.

I didn't test nested includes, override ordering or a bare `@include` line, though the code handles them.

The change is in `miniconf/loader.py`. A few behaviours to know about:
- **Paths:** the include path is everything after `@include`, stripped, and resolved against the directory of the file containing the directive.
- **Cycles:** cycles are detected on resolved real paths, so symlinks can't hide one. The same file included twice without a cycle is allowed.
- **Bare `@include`:** a line with no path raises `ConfigError`.
- **Unreadable includes:** an included file that exists but can't be read or decoded also raises `ConfigError`.
- **Top-level file:** a missing or unreadable top-level file still raises the same `OSError` as before.
- **Sections:** since expansion is purely textual, a section header inside an included file stays active for the lines after the `@include`. That follows from the "as if written inline" rule.
