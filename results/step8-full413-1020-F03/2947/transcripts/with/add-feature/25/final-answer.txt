`miniconf.loader.load(path)` now expands `@include` directives. The change is in `miniconf/loader.py`, and I didn't touch `parser.py`.

I checked it with the existing suite, which still passes (13 tests), and with throwaway files:
- `examples/service.conf` loads with the included `[logging]` section, giving `level = info`.
- A file that includes a file in a subdirectory, which in turn includes another file, expands correctly. Relative paths resolve against the including file's directory.
- A cycle (`a` includes `b`, `b` includes `a`) raises `ConfigError`.
- A missing include target raises `ConfigError`.

I didn't add tests for the new behavior to `tests/`.

- **Sections:** Expansion is literal, so a `[section]` header inside an included file stays in effect for the lines after the `@include` in the parent. A parent key after an include lands in whatever section the include ended in.
- **Missing top-level file:** `load()` on a missing top-level file still raises `FileNotFoundError`, as it did before. Only missing include targets become `ConfigError`.
- **Diamond includes:** If two files both include the same third file, that is allowed. Only real cycles are rejected.
- **Empty `@include`:** An `@include` line with no path raises `ConfigError`.
- **Error line numbers:** Parse errors report line numbers in the expanded text, not in the original file.
