`miniconf.loader.load(path)` now expands `@include` directives. The change is all in `miniconf/loader.py`.

The existing 13 tests pass. I also ran `examples/service.conf`, which now pulls in the `[logging]` section from `logging.conf`. I tried a transitive include cycle and a missing include target by hand, and both raised `ConfigError`. I didn't add new test files, so nesting and override ordering are untested.

How it behaves:
- **Expansion and paths:** An `@include` line is replaced inline by the referenced file's lines, resolved relative to the including file's directory. Nested includes are expanded recursively.
- **Errors:** A missing target, a cycle (direct or transitive) and an `@include` with no path all raise `ConfigError`. So do unreadable targets, such as a directory or a permission problem.
- **Repeated includes:** Including the same file twice from different places is allowed. Only a file that includes itself, directly or through other files, counts as a cycle.
- **Sections leak:** Because expansion is purely textual, a section header inside an included file stays active after the include. Keys that follow the directive land in that section unless the including file declares its own section. This follows from the "as if written in place" rule.
- **Unchanged:** `loads()` and `parse_lines` are untouched, so files without `@include` parse exactly as before.
