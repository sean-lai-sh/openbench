`miniconf.loader.load(path)` now expands `@include` directives. I put the change in `miniconf/loader.py`. The 13 existing tests pass, and `examples/service.conf` loads with `level` set to `info` and `port` set to `8080`.

I also checked these cases by hand:
- **Relative paths:** includes resolve against the including file's directory, including in a subdirectory.
- **Nesting:** an included file that includes another file expands recursively.
- **Ordering:** a key set after an `@include` overrides the included value.
- **Cycles:** a self-include and an include loop between two files both raise `ConfigError`.
- **Missing target:** a missing include target raises `ConfigError`.

I did not add tests for any of this to `tests/`.

- **Section carry-over:** expansion is purely textual, so a section header inside an included file stays active for the lines after the `@include` in the parent file. The example avoids this because `[http]` follows the include.
- **Extra `ConfigError` cases:** an `@include` with no path, or a target that can't be read or decoded, also raises `ConfigError`.
- **Top-level file and line numbers:** a missing top-level file passed to `load` still raises the usual `FileNotFoundError`. Line numbers in parse errors now count lines after expansion.
