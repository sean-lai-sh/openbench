`miniconf.loader.load(path)` now expands `@include` directives, and the existing 13 tests pass (run with `unittest`, since pytest isn't installed). The change is in `miniconf/loader.py`.

- **Example files:** loading `examples/service.conf` pulls in `logging.conf` correctly. The result has `name` and `workers` at the top level, then the `logging` and `http` sections.
- **Cycles and missing files:** both raise `ConfigError`. I checked a two-file cycle and a nonexistent path by hand.
- **Other semantics:** I didn't test relative-path resolution, nesting or the before/after override order. They follow from how the expansion is written. I also didn't add test cases for any of this.

Details beyond the spec:
- **Section leaking:** a section header inside an included file stays active after the include, because the expansion is purely textual. In the example, any key placed right after `@include logging.conf` would land in `[logging]`.
- **Diamond includes:** the same file included from two different places is allowed. Only a file that includes itself, directly or through other files, counts as a cycle.
- **Empty path:** an `@include` line with no path raises `ConfigError`.
- **Unreadable targets:** any file that can't be read, such as a directory, also raises `ConfigError`.
- **Error line numbers:** line numbers in parse errors now count lines of the expanded text, so they can differ from the original file's numbering when includes are used.

`loads()` is unchanged and still ignores `@include` lines.
