`miniconf.loader.load(path)` now expands `@include` directives. The change is in `miniconf/loader.py`.

- **Tests:** The existing 13 tests pass. pytest isn't installed here, so I ran them with `python3 -m unittest discover -s tests -t .`. I didn't add new tests for includes.
- **Example:** `examples/service.conf` loads with the `[logging]` section from `logging.conf` filled in.
- **Cycles and missing files:** I checked both by hand. A cycle (`a.conf` includes `b.conf`, which includes `a.conf`) and a missing include target each raise `ConfigError`.
- **Not run:** I didn't test nested includes, relative paths from a different working directory, or override ordering. The code handles them: it expands recursively and resolves each path against the including file's directory. Ordering follows from positional expansion.

A few behaviours you might not assume:
- An `@include` with no path raises `ConfigError`.
- An included file that can't be read or decoded also raises `ConfigError`.
- Including the same file twice without a cycle is allowed.
- The top-level file passed to `load` still raises the original `FileNotFoundError` if it's missing, as before.
- After expansion, line numbers in parse error messages count lines in the expanded text, not the original file.
