`miniconf.loader.load(path)` now expands `@include` directives. The change is in `miniconf/loader.py`.

- **Checks:** The existing suite passes (13 tests). `examples/service.conf` loads with `logging.level` = `info` and `http.port` = 8080. In a throwaway test, nested includes and relative paths resolved correctly, and the ordering override worked as specified. A missing target, a self-include and an indirect cycle all raised `ConfigError`.
- **Not added:** I didn't add tests for `@include` to `tests/`.
- **Section leakage:** Expansion is purely textual, as the spec describes. An included file's `[section]` header therefore stays active for any keys after the `@include` line in the parent file.
- **Extra errors:** An `@include` with no path raises `ConfigError`. So does an include target that can't be read or decoded.
- **Repeated includes:** The same file included twice without a cycle is allowed.
- **Unchanged behavior:** `loads()` and the parser are untouched.
