`miniconf.loader.load(path)` now expands `@include` directives. The change is in `miniconf/loader.py`.

I ran the existing 13 tests with `unittest` because `pytest` isn't installed, and they pass. I didn't add tests for `@include`, so my checks were by hand:
- `examples/service.conf` loads correctly. The values from `logging.conf` appear in a `logging` section.
- A cycle (`a.conf` includes `b.conf`, which includes `a.conf`) raises `ConfigError`.
- An include of a missing file raises `ConfigError`.

I did not exercise ordering or override, nesting beyond the two-file cycle case, or include paths relative to a subdirectory.

- **How it works:** `load` reads the file, replaces each `@include` line with the included file's lines (recursively), then parses the combined text as before. Include paths are resolved relative to the file containing the directive.
- **Cycles:** I detect them using resolved real paths along the current include chain. Including the same file twice from different places (not a cycle) is allowed.
- **Extra errors:** an `@include` with no path also raises `ConfigError`. So does any other unreadable target, such as a directory.
- **Unchanged:** `loads()`, the parser and files without `@include` behave as before.
- **Line numbers:** parse errors in a file that uses includes report line numbers in the expanded text, not in the original file.
