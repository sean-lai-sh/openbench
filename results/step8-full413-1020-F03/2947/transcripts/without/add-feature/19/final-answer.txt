`miniconf.loader.load(path)` now expands `@include` directives. The change is in `miniconf/loader.py`.

I ran the existing 13 tests and they pass. Loading `examples/service.conf` gives `name=billing`, `logging.level=info` and `http.port=8080`. A manual check showed a two-file include loop and a missing include target each raising `ConfigError`. I didn't add new tests to `tests/`.

- **Expansion:** an `@include path` line is replaced inline, recursively, before parsing.
- **Paths:** relative include paths resolve against the directory of the file that contains the directive.
- **Errors:** a missing or unreadable target raises `ConfigError`, and so does an include with no path. A cycle, direct or transitive, also raises `ConfigError`. The same file can still be included from two different places without being treated as a cycle.
- **Unchanged:** `loads()`, `parse_lines` and files without `@include` behave as before.

Two behaviours to know about:
- **Section carry-over:** expansion is purely textual. An included file starts in whatever section was current at the directive, and any section it opens stays open afterwards.
- **Line numbers:** parse-error line numbers refer to the expanded text, so they can differ from the original file's line numbers after an include.
