`load(path)` now expands `@include` directives. The change is in `miniconf/loader.py`.

I ran the 13 existing tests and they pass. I also loaded `examples/service.conf`, which gives `logging.level` = `info` and `http.port` = `8080`. A two-file include cycle and a missing include target both raised `ConfigError`. I didn't add new tests to the suite.

- **Expansion:** an `@include <path>` line is replaced by the included file's lines before parsing. Nested includes are expanded recursively.
- **Paths:** the path is resolved relative to the directory of the file containing the directive.
- **Cycles:** a file that includes itself, directly or through other files, raises `ConfigError`. A file included twice by different routes (not a cycle) is allowed.
- **Errors:** a missing, unreadable or undecodable include target raises `ConfigError`. So does an `@include` with no path.
- **Top-level file:** the file you pass to `load` behaves as before, so a missing top-level file still raises `FileNotFoundError`.
- **`loads()` and `parse_lines`:** neither is changed.

Expansion is purely textual. If an included file ends inside a section such as `[logging]`, any keys after the `@include` line in the parent file will land in that section, unless the parent starts a new section.

Because the included lines are spliced in, line numbers in parse errors count the expanded text, not the original file.
