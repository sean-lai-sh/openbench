`miniconf.loader.load(path)` now expands `@include` directives. The 13 existing tests pass, and `examples/service.conf` loads with the logging values from `logging.conf` and `port` from `[http]`. I didn't add tests for includes. I only ran the example and a few throwaway files.

The change is in `miniconf/loader.py`.

- **Inline expansion:** an `@include` line is replaced by the included file's lines, and the combined text goes through `parse_lines` as before. `parse_lines` and `loads` are unchanged.
- **Paths:** the include path is resolved relative to the directory of the file that contains the directive.
- **Nesting and ordering:** includes expand recursively, and normal "later assignment wins" gives the override behaviour you described.
- **Errors:** a missing or unreadable target raises `ConfigError`. So does an include cycle (a file including itself, directly or through other files) and an `@include` with no path. I checked a missing file, a self-include and a two-file cycle.
- **Repeated includes:** including the same file twice, without a cycle, is allowed.

Since expansion is purely textual, a section header inside an included file stays active for the lines after the `@include`. This follows "as if those lines had been written there".

Line numbers in parse errors now count lines in the expanded text, so they can be off for files that use includes.
