All 25 tests now pass with `python3 -m unittest`. I fixed seven logic errors, all in `taskflow/`, and didn't touch any test files.

1. **`retry.py:100`**: `should_retry` used `attempts_made < max_attempts - 1`, so tasks got one attempt fewer than their budget. Changed it to `< max_attempts`, which matches the docstring.
2. **`config.py:77`**: `deep_merge` passed the base and override in the wrong order when recursing. That let the pipeline defaults overwrite a task's own nested settings, e.g. `retry.max_attempts: 3` went back to 1. This was the real reason the retry pipeline tests failed.
3. **`queue.py:40`**: the queue sorted by insertion order before priority. Changed it to `(-priority, seq)`: higher priority first, ties first-in-first-out.
4. **`statemachine.py:76`**: the check on the order tasks are started within one tick was backwards. It rejected correctly ordered batches and failed the high-priority tasks. The queue bug had been hiding this one.
5. **`resources.py:99`**: releasing a task's resources gave back 1 unit instead of the task's full cost. Tasks that needed the whole pool could then never start, which is why the resource tests failed.
6. **`events.py:34`**: the prefix match was reversed (`prefix.startswith(topic + ".")`). As a result, the history never received the `job.term.*` events for finished, failed or skipped jobs.
7. **`scheduler.py:264`**: when a task failed for good, only its direct dependents were skipped. Now everything downstream of it is skipped, using `dag.transitive_dependents`.
