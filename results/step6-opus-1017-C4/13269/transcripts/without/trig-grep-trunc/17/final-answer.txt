All 25 tests pass now (`python3 -m unittest` reports OK). I found 8 bugs across 7 files, and in each case the code did something different from what its own docstring describes.

| File | Bug | Fix |
|---|---|---|
| `taskflow/queue.py` `_Entry.sort_key` | Sorted on `(seq, -priority)`, so the order tasks were added beat their priority | `(-priority, seq)` |
| `taskflow/retry.py` `should_retry` | `attempts_made < max_attempts - 1` gave one retry too few | `attempts_made < max_attempts` |
| `taskflow/config.py` `deep_merge` | The recursive call had its arguments swapped, so defaults overwrote a task's own settings | `deep_merge(result[key], value)` |
| `taskflow/events.py` `_prefix_matches` | Checked whether the prefix started with the topic, which is backwards | `topic.startswith(prefix + ".")` |
| `taskflow/statemachine.py` `batch_order_ok` | Required priority to go *up* within a batch; it should never go up | `current_priority <= prev_priority` |
| `taskflow/resources.py` `ResourcePool.release` | Gave back 1 unit no matter what the cost was, so resources leaked | `self.used -= cost` |
| `taskflow/scheduler.py` `_cascade_skip` | Skipped only the direct dependents of a failed task, not everything further downstream | Uses `dag.transitive_dependents(...)` |

As you warned, several failures came from a different module than the one the test is named for:
- **Priority tests in `test_pipelines`:** fixing the queue order wasn't enough. The state machine's check that priority never rises within a batch was inverted, so it rejected every correct batch and marked those runs FAILED.
- **History tests:** these failed because the event bus's prefix matching was backwards, so the history's `job.term` subscription never received the success, failure or skip events.
- **Resource tests:** these failed because of the 1-unit leak in `release`. Pools filled up and later tasks were never admitted.

The scheduler code also mostly calls `dag.dependents` where it means its direct dependents. That's correct for those uses, so the only call that needed changing was in `_cascade_skip`.
