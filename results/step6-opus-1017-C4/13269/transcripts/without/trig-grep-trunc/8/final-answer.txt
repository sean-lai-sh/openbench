All 25 tests now pass with `python3 -m unittest`. I found eight bugs in seven files and fixed each with a one-line change. I didn't touch any tests.

| File | Bug | Fix |
|---|---|---|
| `taskflow/queue.py:40` | The queue sorted by insertion order before priority, so higher priority didn't win. | Sort key is now `(-priority, seq)`. |
| `taskflow/retry.py:100` | `attempts_made < max_attempts - 1` allowed one attempt too few. | Now `attempts_made < max_attempts`. |
| `taskflow/config.py:77` | The recursive `deep_merge` call had its arguments swapped, so defaults overwrote a task's own settings in nested blocks like `retry`. | Now `deep_merge(result[key], value)`. |
| `taskflow/statemachine.py:76` | `batch_order_ok` was inverted. It rejected the correct high-to-low priority order within a batch, and the scheduler then marked those tasks as failed. | Now `current <= prev`. |
| `taskflow/events.py:34` | `_prefix_matches` had the prefix and topic swapped. Subscribers to `job.term` never received `job.term.failed` and similar events, so the run history stayed empty. | Now `topic.startswith(prefix + ".")`. |
| `taskflow/scheduler.py:264` | When a task failed for good, only its direct dependents were skipped. Tasks further downstream stayed `PENDING`. | Now uses `dag.transitive_dependents`. |
| `taskflow/resources.py:99` | `release` always freed 1 unit instead of the task's full cost, so pools filled up and tasks could never be admitted. | Now `self.used -= cost`. |
