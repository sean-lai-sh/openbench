All 25 tests pass now; `python3 -m unittest` reports `OK`. I changed nothing under `tests/`.

A note on the search you asked for first: grep found 1,325 matches for `self` and only showed the first 100, so it didn't help locate anything. I worked from the test failures and read the code directly instead.

There were seven bugs, each a one-line fix where the code did something different from what its docstring says:

1. **`taskflow/queue.py`, `_Entry.sort_key`**: the sort key was `(seq, -priority)`, so tasks ran in the order they arrived and priority was ignored. Changed it to `(-priority, seq)` so higher priority goes first and arrival order only breaks ties.
2. **`taskflow/retry.py`, `should_retry`**: it compared against `max_attempts - 1`, so tasks got one fewer attempt than configured. It's now `attempts_made < max_attempts`.
3. **`taskflow/config.py`, `deep_merge`**: the two arguments were swapped in the nested call, so pipeline defaults overwrote a task's own settings (e.g. `max_attempts`) instead of the other way round.
4. **`taskflow/events.py`, `_prefix_matches`**: the prefix check was backwards (`prefix.startswith(topic + ".")`). As a result the history never received the `job.term.*` events, which is why its failed/skipped/succeeded lists and counts were empty.
5. **`taskflow/resources.py`, `ResourcePool.release`**: it freed 1 unit instead of the task's actual cost. That leaked capacity and left later tasks stuck waiting.
6. **`taskflow/statemachine.py`, `batch_order_ok`**: the comparison was inverted, so a correctly ordered batch was rejected and the scheduler failed the task. Once the queue was fixed, this was why the priority tests started failing on `report.ok()` instead of on order.
7. **`taskflow/scheduler.py`, `_cascade_skip`**: it used `dag.dependents()`, which only gives direct children. It now uses `dag.transitive_dependents()`, so everything downstream of a failed task is skipped.

As you warned, several of these hid each other. The pipeline tests that failed under one module's name were mostly caused by bugs elsewhere: the queue, retry, event-bus, resource-pool and state-machine fixes are what got them passing.
