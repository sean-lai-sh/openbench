Several of these were hidden behind others, as you warned:
- **History tests:** these looked like `history.py` bugs (failed and skipped job lists were empty), but the cause was the reversed prefix check in `events.py`.
- **Priority tests:** once the queue order was fixed, these still failed because of the inverted priority check in `statemachine.py`. With the queue wrong, that check had been making tasks fail outright.
- **Resource tests:** these only failed for tasks needing more than one unit of a resource. The release miscount left the pool looking full, so later tasks could never start.
