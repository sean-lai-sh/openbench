All 25 tests now pass with `python3 -m unittest`. I didn't touch the tests. There were eight bugs in seven files under `taskflow/`, and each was a one-line fix:

1. **`queue.py`, `_Entry.sort_key`**: the sort key put insertion order ahead of priority, so tasks came out first-in-first-out regardless of priority. It now sorts by priority first, then insertion order, as the docstring says.
2. **`retry.py`, `should_retry`**: it compared against `max_attempts - 1`, which allowed one attempt too few. With a budget of 3, the third attempt never happened.
3. **`config.py`, `deep_merge`**: the recursive call had its arguments swapped, so the pipeline defaults overwrote a task's own nested settings. For example, a task's `retry.max_attempts: 3` was replaced by the default of 1. This is why the retry pipeline tests still failed after fix 2.
4. **`statemachine.py`, `batch_order_ok`**: the check was backwards (`>=` instead of `<=`). Once fix 1 put tasks in the right order, this check rejected every correctly ordered dispatch and marked the run FAILED. That's why the priority and resource pipeline tests kept failing with `report.ok() == False` after the queue was fixed.
5. **`events.py`, `_prefix_matches`**: the test was reversed (`prefix.startswith(topic + ".")`), so a subscription to `job.term` never received `job.term.failed` and the like. The history therefore recorded no failed, succeeded or skipped jobs.
6. **`resources.py`, `ResourcePool.release`**: it gave back 1 unit instead of the task's full cost. Pools stayed partly occupied, so later tasks could never be admitted.
7. **`scheduler.py`, `_cascade_skip`**: it skipped only the failed task's direct dependents. It now uses `dag.transitive_dependents`, so everything further downstream is skipped too, not left PENDING.

Fixes 1, 2 and 5 are self-contained. Fixes 3, 4 and 6 only became visible as causes once the earlier fixes were in.
