`python3 -m unittest` now passes all 16 tests. Before the fixes it ran 15: `tests/test_search.py` couldn't be imported, so its two tests were counted as one error. I didn't change any tests. I tracked the work with the todo list tool, and a subagent investigated `test_inventory.py`.

Fixes in `catalog/`:
- **`books.py`**: `parse_book` left the year as a string, so `age()` crashed when subtracting it. It now converts the year with `int(year)`.
- **`factory.py`**: added the missing third sample book, `Book("Emma", "Austen", 1815, 1)`.
- **`fees.py`**: the fee was `days_late + DAILY_FEE`; it's now `days_late * DAILY_FEE`.
- **`inventory.py`**: `recent()` had an off-by-one slice (`[-n - 1:]`) that returned one event too many. The subagent found this. It's now `[-n:] if n > 0 else []`. The `n > 0` check is a small addition no test asks for: without it, `recent(0)` would return the whole history.
- **`members.py`**: `MAX_BORROWED` was 3, but the comment above it and the tests both say 5. Changed it to 5.
- **`search.py`**: it imported `normalize` from `catalog.nonexistent`; it now imports it from `catalog.text`.
