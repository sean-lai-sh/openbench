I wrote `convert_masks.py` and ran it on the demo files. It uses MobileSAM (`vit_t`) on CPU to redraw all 48 masks as polylines. The run took about 1 minute.

**How it works:**
1. It loads the image into MobileSAM once. For each row, it gives the model the annotation's bounding <USER> plus a point at the <USER> centre, and gets back three candidate masks.
2. It picks one candidate per cell:
   - **Polyline rows:** the candidate that best matches the original polygon, also weighted by MobileSAM's confidence score.
   - **Rectangle rows:** the most confident candidate. Candidates that fill nearly the whole <USER> or are tiny are penalised.
3. Each mask is limited to its <USER> plus a small margin, cut down to its largest connected piece, and has any holes filled. If MobileSAM returns nothing usable, it falls back to the original polygon (or an ellipse inside the rectangle).
4. **Overlaps:** a pixel claimed by two cells goes to whichever MobileSAM is more confident about. Each mask is then cut down to one piece again, and every cell is guaranteed a mask.
5. Each outline is traced straight from its mask with no simplification, so neighbouring polygons can't overlap once they're filled in. Any outline that comes out as a plain rectangle gets its corners trimmed.

**Checked on the demo output:**
- The output has the same rows and columns as the input, and only `xmin`, `ymin`, `xmax`, `ymax`, `coords_x` and `coords_y` changed.
- When I filled in all the polygons, no pixel belonged to more than one cell.
- Every mask is one connected piece and none is a rectangle.
- Coordinates use the input's format, with the first point repeated at the end.
- I also drew an overlay of old and new outlines. The new ones follow the nuclei well, including inside the loose rectangle boxes.

**Decisions for you:**
- **`type` column:** I left it unchanged, because you said only those six columns should be updated. So former rectangle rows still say `rectangle` even though they're now polylines. Changing them to `polyline` is a one-line edit if you'd prefer.
- **Output location:** if `output_path` is a folder, the file is saved there under the input CSV's name. If it ends in `.csv`, it's used as the file path.

The arguments work either as positional values in the order weights, output, rgb, csv, or as flags:
```
python convert_masks.py --weights_path mobile_sam.pt --output_path out/ --rgb_path img.png --csv_path meta.csv
```
