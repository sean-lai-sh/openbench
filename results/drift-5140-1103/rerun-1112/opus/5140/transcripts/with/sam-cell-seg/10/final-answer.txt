I wrote `convert_masks.py`, which uses MobileSAM to turn every mask in the CSV into a polyline. On the demo slide it handled all 48 masks (19 rectangles, 29 polylines) in about 6 seconds on CPU.

**Usage**
```
python convert_masks.py --weights_path mobile_sam.pt --output_path out.csv \
       --rgb_path demo_rgb.png --csv_path demo_metadata.csv
```
The arguments are named flags, not positional ones. If `--output_path` ends in `.csv`, the result is written to that file. Otherwise it's treated as a folder, created if needed, and the CSV is saved inside it under the input file's name.

**How it works**
1. **MobileSAM on every row:** the image is processed once with the `vit_t` model. Each mask's bounding <USER> is then used as the prompt, and SAM returns three candidate masks.
2. **Choosing a candidate:**
   - For existing polylines, it picks the one that best matches the original outline (overlap plus SAM's confidence score).
   - For rectangles, it uses SAM's score, with a penalty for masks that are tiny or fill the whole <USER>.
   - Masks are kept within a slightly enlarged <USER> so they stay on the annotated cell.
   - If SAM returns almost nothing, it falls back to the original outline, or to an ellipse inside the <USER> for rectangles.
3. **Cleanup:** each mask is lightly smoothed, holes are filled, and only the largest connected piece is kept.
4. **No overlaps:** masks are added from highest to lowest confidence, each taking only free pixels. A 1-pixel gap is kept between neighbours so outlines never touch or cross. If one mask ends up surrounding another, it's cut open so its outline doesn't enclose the inner cell.
5. **Output:** each outline is traced into a polyline. Any outline that comes out as a plain rectangle has its corners trimmed. `coords_x`, `coords_y`, `xmin`, `xmax`, `ymin` and `ymax` are updated, and the `type` column is also set to `polyline`. The other columns and the index column are unchanged.

**Results on the demo**
- All 48 masks are non-rectangular polylines, each a single connected piece.
- No pixel belongs to more than one mask, and each bounding <USER> matches its new outline.
- Polylines kept 0.64–0.87 overlap with their original outlines, so they were refined rather than replaced.
- Overlay images showed the outlines following the nuclei well.
- Former rectangles overlap their boxes less (0.26–0.86), as expected when a <USER> shrinks to fit the cell. The lowest, row 0 at 0.26, became a thin elongated fibroblast outline inside a much larger <USER>.
- I couldn't run a strict geometric check for self-crossing outlines because `shapely` isn't installed. The 1-pixel gap is what prevents outlines of different cells from crossing.
