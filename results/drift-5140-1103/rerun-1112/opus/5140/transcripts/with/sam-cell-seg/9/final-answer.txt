I wrote `convert_masks.py` in the working directory and ran it on the demo files. All 48 masks came out as polylines, with no overlaps and exactly one connected region per cell. In an overlay of new versus original outlines, the new ones follow the nuclei closely, with one exception covered below.

**Usage** (named flags or the same four values in order both work):
```
python convert_masks.py --weights_path mobile_sam.pt --output_path out_dir --rgb_path demo_rgb.png --csv_path demo_metadata.csv
python convert_masks.py mobile_sam.pt out_dir demo_rgb.png demo_metadata.csv
```
If `output_path` is a folder, the result is saved there under the input CSV's file name. If it ends in `.csv`, it is used as the output file.

**What it does:**
1. Loads MobileSAM (`vit_t`) from the installed `mobile_sam` package, unmodified, on CPU (it uses a GPU only if one is available). It processes the image once, then uses each row's bounding <USER> to ask MobileSAM for three candidate masks.
2. Picks one candidate per cell:
   - **Rectangles:** the candidate MobileSAM is most confident in, penalising any that almost fill the <USER> or are very small.
   - **Polylines:** the candidate that best matches the original outline. If MobileSAM clearly fails (overlap with the original below 0.3), it keeps the original polyline instead.
3. Cleans each mask: keeps only the largest region, fills holes, and limits it to the <USER> plus a small margin.
4. Removes overlaps: where masks compete for a pixel, the one MobileSAM is most confident about gets it. Each cell is then cut back to one region, and a 1-pixel gap is left between neighbouring cells. A final check draws the saved polylines and makes sure none overlap.
5. Turns each mask's outline into a closed polyline. The output keeps the input CSV's columns and index and changes only `xmin`, `ymin`, `xmax`, `ymax`, `coords_x` and `coords_y`.

**Things to know:**
- I left the `type` column unchanged (so it still says `rectangle` for those rows), because you asked for only the coordinate and <USER> columns to change. If you want every row to say `polyline`, that's a one-line change.
- **Weak spot:** for the rectangle at the top edge (x 246–294, y 0–38), MobileSAM picked up mostly background rather than a nucleus. Rectangles drawn around faint or partly visible cells will be less reliable.
- **Speed:** on this machine the demo took about 70 seconds. About 6 seconds of that is processing the image, then about 1 second per cell, which is MobileSAM's own time, not the script's extra steps.

I tested with the official weights file (`weights/mobile_sam.pt` from the MobileSAM repo), downloaded to `/tmp/mobile_sam.pt`.
