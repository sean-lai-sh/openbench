I've written `convert_masks.py`, and on the demo files it produces 48 polyline masks that pass my checks. I ran it with both argument styles: four positional arguments in your order (weights, output, rgb, csv) or `--weights_path` style flags. It took about 6 seconds on CPU.

**How it works:**
1. It loads MobileSAM (`vit_t`) on CPU through the `mobile_sam` package, without changing any of its source code. Each cell's bounding <USER> is given to MobileSAM as the prompt. For images larger than 1024 px, it processes the image in overlapping tiles and uses the tile that best contains each <USER>.
2. MobileSAM returns three candidate masks per cell. The script picks one using the model's own quality score, penalises masks that fill nearly the whole <USER> (which would just be the rectangle again) or are tiny fragments, and, where the original is a polyline, prefers masks that agree with it.
3. Each mask is clipped to its <USER> with a few pixels of margin, holes are filled, and only the largest connected piece is kept.
4. Where two masks overlap, each pixel goes to the cell MobileSAM is most confident about. Smaller cells are then fixed in place first, and a 1-pixel gap is kept between neighbouring cells. Because of the gap, the outlines never touch or cross, even diagonally, though borders between touching cells lose about a pixel.
5. Each mask is turned back into an outline. If that outline is still an axis-aligned rectangle, or a mask comes out empty, the script falls back in this order: MobileSAM's raw mask, the original polyline, then an ellipse inside the <USER>. On the demo, all 48 masks came from MobileSAM's output (step 4) without needing a fallback.

**Output:** a CSV identical to the input except for `xmin`, `ymin`, `xmax`, `ymax`, `coords_x` and `coords_y`. Coordinates use your format: comma-separated, with the first point repeated at the end to close the shape. Two choices you may want changed:
- **File name:** if `output_path` is a folder, the file is saved as `<output_path>/<input csv name>`. If it ends in `.csv`, that exact path is used.
- **`type` column:** I left it unchanged because you said only those six columns should change, so former rectangles are still labelled `rectangle`. If it should say `polyline`, that's a one-line change.

**Checks on the demo output:**
- Columns and all unchanged columns match the input.
- When the polygons are drawn, no two overlap.
- Each mask is one contiguous region with no rectangles, with 27–43 points per outline (mean about 43).
- The new `xmin`/`xmax`/`ymin`/`ymax` match the new outlines.
- An overlay on the image shows the outlines following the nuclei closely.

`shapely` isn't installed, so I couldn't measure overlap between the polygons as exact shapes. The 1-pixel gap is there to prevent it.
