I wrote `convert_masks.py` and ran it on the demo files. It refines all 48 masks with MobileSAM, and every check I ran on the output passed. It runs on CPU in about 6 seconds for the demo image. The MobileSAM source code is not modified.

```
python convert_masks.py --weights_path /path/to/mobile_sam.pt --output_path out_dir \
    --rgb_path demo_rgb.png --csv_path demo_metadata.csv
```

**Checks on the demo output** (I filled each output polygon in and tested it):
- The output has 48 rows and the same columns as the input.
- No mask is rectangular, and each polyline has 29–167 points.
- No pixel belongs to more than one mask.
- Each mask is one connected piece.
- `xmin`/`xmax`/`ymin`/`ymax` match each new polyline's extent.
- In an overlay, the new outlines follow the cell nuclei closely, including the cells that were rectangles before.

**How it works:**
1. It loads the image once and asks MobileSAM for a mask for each row, using the row's bounding <USER> plus the centre of the original shape as prompts.
2. MobileSAM gives three candidate masks per cell. The script picks one based on MobileSAM's confidence and how well it matches the original shape: the polyline itself, or an ellipse fitted inside the <USER> for rectangles. Candidates far too small or large for the <USER> are penalised.
3. Each mask is kept within a slightly enlarged version of the original <USER>, lightly smoothed, cut down to its single largest piece, and has any holes filled.
4. Where two masks overlap, each pixel goes to the cell MobileSAM is more confident about. If a cell loses its whole mask this way, it falls back to free pixels inside its original shape.
5. Each mask's outline becomes a closed polyline, written as comma-separated text in the same format as the input.

**Decisions you may want to change:**
- **`type` column:** I also set this to `"polyline"` for every row, although you only listed the coordinate columns. To leave it as it was, delete the two lines near the end that set `out["type"]`.
- **Output file name:** if `output_path` ends in `.csv`, the script writes to exactly that file. Otherwise it treats it as a folder, creates it if needed, and saves the result under the input CSV's file name.
- **Weights:** the script doesn't download them, so `weights_path` has to point to an existing `mobile_sam.pt`. For testing I used a copy already on this machine at `/opt/uvcache/git-<REDACTED_B64>mobile_sam.pt`.

The script also imports `timm`, which `mobile_sam` itself needs and which wasn't on your list. It is installed here.
