I created `pipeline_parallel.py` with `train_step_pipeline_afab`. I tested it on a small randomly initialised LLaMA (5 layers, 3 microbatches, gloo backend on CPU, float32). With world_size 1 and 2, the loss and every parameter gradient matched an ordinary single-process run exactly (difference of 0). I only tested with transformers 5.22.2, which I installed because it wasn't in the environment. I didn't test bfloat16.

**What the function does:**
- **Splitting the layers:** the decoder layers are divided as evenly as possible, with any extra layers going to the earlier ranks. With 5 layers and 2 ranks, rank 0 runs layers 0–2 and rank 1 runs layers 3–4. Rank 0 also runs the embedding; the last rank also runs the final norm and `lm_head`.
- **Forward pass, all microbatches first:**
  - Rank 0 embeds the input IDs.
  - Every other rank receives hidden states of shape `[microbatch, seq_len, hidden_size]` from the previous rank, using `P2POp` with `batch_isend_irecv`.
  - Each rank runs its own layers and sends the result to the next rank.
  - The last rank computes the cross-entropy loss against the targets and divides it by the number of microbatches.
  - Inputs, hidden states and gradients are always moved to the given `device` and `dtype`.
- **Backward pass, all microbatches after:**
  - The last rank calls `loss.backward()`.
  - Every other rank receives the output gradient from the next rank and backpropagates it with `torch.autograd.backward`.
  - Each rank except rank 0 then sends the gradient of its received hidden states back to the previous rank.
- **No hooks, model unchanged:** the function calls the layer modules directly, so the test's hooks fire and each rank runs only its own layers. It doesn't modify the model itself.
- **Return value:** the last rank returns the total scaled loss as a float. The other ranks return `None`.

**Compatibility with other transformers versions:** the function looks at each layer's signature to decide which arguments to pass: `position_embeddings`, `position_ids`, `attention_mask`, `cache_position`. It builds the causal mask with transformers' `create_causal_mask` and falls back to building the mask itself if that call fails. This is meant to make it work across versions, but only 5.22.2 was actually run.

**The loss calculation is a guess:** the cross-entropy runs directly on the logits in the model's dtype, without converting them to float32 first. In float32 this makes no difference. In lower precision it will only match the reference if the reference computes the loss the same way.
