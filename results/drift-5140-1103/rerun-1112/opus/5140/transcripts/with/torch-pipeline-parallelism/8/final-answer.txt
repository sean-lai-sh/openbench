I created `pipeline_parallel.py` with `train_step_pipeline_afab`. I tested it with world sizes 1 and 2 on CPU, using a small 5-layer LLaMA and 3 microbatches. On every rank, the parameter gradients and the loss matched a reference model trained normally (within 1e-5). I didn't run your hook-based activation test, since I don't have it, so that check is still open.

**How it works**
- **Splitting the layers:** decoder layers are divided as evenly as possible, with any leftover layers going to the lowest ranks. With 5 layers and 2 ranks, that's 3 + 2. Rank 0 also runs the embedding. The last rank also runs the final norm, the output layer, and the loss.
- **Each stage's forward pass:** it does what the stock model's forward does, using the same causal mask, position IDs and rotary embeddings, but only over this rank's own layers. No hooks are used.
- **All forward:** for each microbatch, rank 0 embeds the input IDs. Other ranks receive hidden states of shape `[microbatch, seq_len, hidden_size]` from the previous rank, run their layers and send the result on. The last rank computes cross-entropy against the targets and divides it by the number of microbatches.
- **All backward:** the last rank runs backward on each saved loss. Every other rank receives the gradient from the next rank and back-propagates it through its saved outputs. Every rank except rank 0 sends the gradient of its input hidden states back to the previous rank.
- **Communication:** all sends and receives use `torch.distributed.P2POp` with `batch_isend_irecv`. Hidden states and gradients are moved to the given `device` and `dtype`. Input IDs are moved to the device but stay integers, because the embedding needs integer IDs.

**Things you might not expect**
- The function returns the summed scaled loss on the last rank and `None` on the other ranks.
- Every rank keeps the full model in memory and simply skips layers it doesn't own. So gradients only appear on the parameters that rank used (28 on rank 0 and 20 on rank 1 in the 2-rank test).
- The function assumes every rank receives `inputs`, because receiving ranks read the microbatch shape from them. It doesn't move the model to `device` or cast it to `dtype`.
