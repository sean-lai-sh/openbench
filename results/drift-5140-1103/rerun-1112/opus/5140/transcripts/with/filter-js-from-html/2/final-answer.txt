I created `filter.py`. It removes JavaScript from the HTML file you pass as `argv[1]` and rewrites that file in place. In my tests, a normal page (doctype, title, style block, comment, tables, headers, inline styles, links, a `data:image/png` image, a `<pre>` block, a bare `<` in text) came out byte-for-byte unchanged. All 36 attack strings I tried came out with the dangerous parts removed. I didn't test it in a real browser or with an outside HTML parser.

**How it works:** it uses only the Python standard library. It scans the raw text the way a browser reads HTML and keeps the original bytes of everything it doesn't remove. It doesn't rebuild the page from a parse tree, so spacing, quotes, letter case, entities, comments and Windows line endings stay as they were. If nothing is removed, the file isn't rewritten at all.

**What gets removed:**
- **Elements with their contents:** `<script>` and `<iframe>`.
- **Tags only, inner content kept:** `<object>`, `<embed>`, `<applet>`, `<frame>`, `<frameset>`.
- **Event handlers:** every `on*` attribute, including disguised forms like `=onclick`. Also `srcdoc`.
- **Script links:** any attribute whose value uses `javascript:`, `vbscript:` or a similar scheme. Encoded forms are caught too, such as `&#106;`, `&colon;`, or tabs and newlines hidden inside the word.
- **`data:` URLs:** removed unless they are ordinary images (PNG, GIF, JPEG, WebP and similar). SVG images in `data:` URLs are removed.
- **Dangerous CSS:** `style` attributes, and the contents of `<style>` blocks, that use `expression()`, `behavior`, `-moz-binding` or script URLs, including when written with CSS escape codes or comments.
- **Tricks:** SVG animation attributes that try to set an event handler or a link, and malformed tag names containing `<`.

**Tricky cases also handled:**
- Text inside elements like `<noscript>`, `<title>`, `<textarea>` and `<style>` is cleaned as HTML too, so it's safe either way a browser reads it (for example inside `<svg>`, or with scripting turned off).
- Comment edge cases such as `<!-->` are read the same way a browser reads them.
- The filter repeats until nothing more changes, so removing one piece can't join the leftovers into a new working tag (e.g. `<scr<script></script>ipt>`).

**Where it removes more than strictly needed:**
- Text in `<title>` or `<textarea>` that looks like a script tag or event handler gets removed, even though browsers would only display it there.
- Any attribute containing `javascript:` loses that attribute, even a harmless `title` that just mentions it.
- A `<style>` block with dangerous CSS is emptied entirely rather than having just the bad rule taken out.
- A value like `src=x/onerror=alert(1)` is removed. Browsers treat it as one harmless value, but some looser parsers would see an `onerror` handler in it.

Run it with `python3 filter.py page.html`.
