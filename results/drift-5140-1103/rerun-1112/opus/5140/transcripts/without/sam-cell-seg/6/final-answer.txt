I wrote `convert_masks.py` and ran it on the demo files. On the demo, every mask came out as a single closed polyline, with no overlaps between masks and no rectangles left. The whole run takes about 6 seconds on CPU.

**How to run it.** The four arguments can be given positionally in your order or as flags:
```
python convert_masks.py --weights_path mobile_sam.pt --output_path out_dir --rgb_path img.png --csv_path meta.csv
python convert_masks.py mobile_sam.pt out_dir img.png meta.csv
```
- If `output_path` ends in `.csv`, the result is written to that file.
- Otherwise `output_path` is treated as a folder, which is created if needed, and the result is saved there under the input csv's file name.

**What it does:**
1. **MobileSAM:** it loads the `vit_t` model from your weights file and runs it on CPU, prompting it with each cell's bounding <USER>. The installed `mobile_sam` package is used as-is, with no changes to its code.
2. **Picking a mask:** MobileSAM returns three candidate masks per <USER>. The script picks one using:
   - the model's own confidence score
   - how much of the mask falls inside the <USER>
   - a penalty for masks that are almost empty or fill the whole <USER> (those are usually background)
   - for cells that were already polylines, how closely the candidate matches the original outline

   The chosen mask is then trimmed to the area around its <USER>. Small specks are removed, holes are filled and only the largest piece is kept.
3. **Fallbacks:** if MobileSAM fails on a cell, the script uses the original outline for polylines, or an ellipse fitted inside the <USER> for rectangles.
4. **No overlap:** where two masks claim the same pixel, it goes to the cell the model is more confident about. Each mask is then cut back to its largest connected piece.
5. **Final check:** the script draws every output outline and checks again for overlaps, trimming the larger mask if any remain. If a mask surrounds another cell completely, it cuts a narrow channel through it so the outline doesn't swallow that cell.
   - Any cell left with no pixels gets a small seed region so it still has a mask.
   - Any outline that came out as a perfect axis-aligned rectangle has its corners clipped.
6. **Output:** each polyline is closed (the first point is repeated at the end), and `xmin/xmax/ymin/ymax` are recalculated from its points. All other columns, and the blank-named first column, are written back unchanged.

**Checks on the demo (48 cells):**
- Every mask has exactly one connected region.
- No pixel belongs to more than one mask.
- No output is a rectangle.
- All columns other than the six you named match the input exactly.
- For cells that were already polylines, the new outline overlaps the original by 0.78 on average (intersection over union), with a minimum of 0.63.
- I also drew the new outlines over the image, and they follow the nuclei well, including the cells that started as rectangles.
