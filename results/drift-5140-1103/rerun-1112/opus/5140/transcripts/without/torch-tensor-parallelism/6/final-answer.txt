I created `parallel_linear.py` with both classes. I tested it with gloo on CPU at world sizes 1, 2 and 4, and every check passed. Against a plain `torch.nn.Linear` using the same weight, outputs, input gradients and each rank's weight and bias gradient slice all match.

- **`ColumnParallelLinear`**: each rank keeps its share of the weight's output rows, `master_weight[r*out/ws : (r+1)*out/ws, :]`, and its matching part of the bias. Each rank computes its piece of the output, and the pieces are joined along the last dimension with all_gather. In the backward pass, each rank takes its own slice of the output gradient, and the input gradient is summed across ranks with all_reduce.
- **`RowParallelLinear`**: each rank keeps its share of the weight's input columns, `master_weight[:, r*in/ws : (r+1)*in/ws]`. The partial outputs are summed with all_reduce, and then the full bias (kept on every rank) is added. If the input has all `in_features` columns, each rank takes its own slice of it, and the backward pass gathers the input gradient back together. If the input is already split per rank, it is used as is.

Things to know:
- **Weight layout:** `master_weight` must have shape `(out_features, in_features)`, the same as `nn.Linear`. "Splitting by columns" is read here as splitting the output dimension, as in Megatron-style tensor parallelism. If your tests treat the weight as `(in, out)`, the slicing would need to be swapped.
- **Divisibility:** both classes assert that the split dimension divides evenly by world_size.
- **Bias:** when `bias=True`, it starts at zero.
- **Type-checker errors:** the editor flags the `backward` methods with signature errors. These are false alarms on the standard `torch.autograd.Function` pattern and don't affect how the code runs.
