I wrote `steal.py` and ran it. It found 20 hidden neurons and saved a 20×10 matrix to `stolen_A1.npy`.

To check it, I compared the result with the real `A1` in `forward.py`. `steal.py` itself never reads those weights; it only calls `forward(x)`. Every true row has a matching recovered row and vice versa, with |cosine similarity| above 0.99999999999999 each way. The run took about 0.4 seconds.

How it works:
1. **Find the kinks.** Along a random line `x0 + t·d`, the network's output is made of straight segments. It bends where one neuron's input `A1_i·x + b1_i` crosses zero. The script finds these bends by repeatedly halving the line wherever the output stops being straight. It then pins each bend down exactly by working out where the straight pieces on either side meet.
2. **Read off a row.** Just past a bend, one neuron has switched on or off. The gradient on one side minus the gradient on the other is `A2_i · A1_i`, which is a scaled copy of that neuron's row of `A1`. The gradients are estimated by finite differences.
3. **Tidy up.** Each row is scaled to unit length with a fixed sign, and duplicates are dropped. The script stops once 15 lines in a row turn up no new neurons.

The rows come out unit-length, so they match `A1` only up to reordering and scaling, as you asked. A row may also have the opposite sign to the real one, so that scaling includes negative factors.
