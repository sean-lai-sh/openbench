I've created `filter.py`. It takes the HTML file path as its argument and removes JavaScript from the file in place. I tested it on a sample clean page (headers, tables, comments, styles, forms, entities, a data-image) and the output was byte-for-byte identical to the input. I also ran it against about 30 common XSS payloads, and every one came out with the script part removed or made inert. I only checked the output text; I didn't load the results in a browser to confirm nothing runs.

**How it works:** it splits each tag into its name and attributes using the same rules browsers follow. Anything not judged dangerous is copied through exactly as it was. The file is read and written as raw bytes, so UTF-8 text such as `café` survives, and an unchanged file is never rewritten. It repeats the pass until nothing more changes, which catches tricks where removing one piece creates a new one, such as `<<script>x</script>script>…`.

**What it removes:**
- **Whole elements, contents included:** `<script>…</script>` and `<iframe>…</iframe>`. An unclosed `<script>` is removed to the end of the file.
- **Tags only (any fallback content inside is kept):** `object`, `embed`, `applet`, `frame`, `frameset`, `base` and `portal`, plus `<meta http-equiv=refresh>` and `<link rel=import>`.
- **Attributes:**
  - every event handler (`onclick`, `onerror`, `onload`, …) and `srcdoc`.
  - any attribute whose value contains `javascript:`, `vbscript:` or `livescript:`. Encoded forms are caught too, such as `&#106;avascript:`, `jav&#x09;ascript:` and `javascript&colon;`.
  - `data:` links in link and source attributes, except ordinary images like PNG, JPEG or GIF. SVG images are not exempt.
  - `style` attributes that use CSS tricks like `expression(` or a `javascript:` link.
  - SVG animation that targets `href` or an event handler.

**Formatting changes:** the only edits are where something is removed. When an attribute is removed, the space before it goes too, so `<img src=x onerror=…>` becomes `<img src=x>`.

**Decisions for you:**
- **`<` inside attribute values is rewritten as `&lt;`.** This is the one change that isn't a removal: it happens whenever the `<` could start a tag. It stops attacks that hide a tag inside a quoted value, such as `<noscript><p title="</noscript><img onerror=…>">`. The page behaves the same, but the file text changes. Dropping this would keep the text exact but leave that gap open.
- **The `javascript:` check covers every attribute, not just links.** So a harmless `title="javascript: a tutorial"` would also be removed. Limiting the check to link and animation attributes would keep such text, but would miss encoded tricks in attributes I haven't listed.
- **All iframes, embeds and objects are removed, even trusted ones.** A YouTube embed, for example, would disappear, because what they load can run scripts. Keeping iframes from trusted sites would mean checking each link against an allowlist.
