I wrote `steal.py`. When run, it saves a 20×10 matrix to `stolen_A1.npy`. I checked that matrix against the true `A1` from `forward.py`. Each recovered row matches exactly one true row, with cosine similarity of at least 0.9999999999999962, so all 20 neurons are recovered.

It uses only `forward()` queries and never reads `A1` directly:
- **Finding kinks:** it samples the output along random lines through input space and finds the points where the slope changes, which is where a neuron switches on or off.
- **Recovering a row:** at each kink it estimates the gradient on both sides by finite differences. The difference between the two gradients points along that neuron's row of `A1`.
- **Clustering:** it groups the directions, treating a row and its negative as the same, and keeps groups with at least two hits. It then normalizes each row to unit length.

The recovered rows are only defined up to permutation and scale, as you specified. The rows are unit-length, so the original scale (and sign) is not recovered.

The script assumes the hidden layer is small enough that 60 random lines hit every neuron's kink at least twice. That held here. A much wider layer might need more lines.
