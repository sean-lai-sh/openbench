I've written `filter.py`. It edits the file given in `argv[1]` in place and cuts out only the dangerous parts; everything else is copied unchanged, byte for byte.

**Testing:**
- **Normal page:** a page with a doctype, meta, title, CSS, comments, tables, headers, forms, SVG, `<pre>` and inline styles came back identical to the input.
- **Attacks:** about 55 known XSS payloads were all neutralised, including encoded `javascript:` links, mixed-case tags, broken or nested `<script>` tags, SVG and MathML tricks, and IE conditional comments.
- **File handling:** Windows line endings and non-UTF-8 bytes survived unchanged.
- **Speed:** a 2.3 MB file took about 6 seconds.

The tests were scripts I wrote and then deleted, so there's no test file in the folder. The results were checked by text pattern matching, not by loading the output in a real browser.

**How it works:** it splits the HTML into tags, attributes, comments and text the same way a browser does. Because the original text is kept and only bad pieces are deleted, formatting and whitespace don't change. It runs repeatedly until nothing more is removed, so a deletion can't glue leftover fragments into a new working tag (e.g. `<<script></script>script>`).

**What gets removed:**
- **Whole elements with their content:** `<script>` and `<iframe>`.
- **Tags only (anything inside is kept and cleaned):** `<object>`, `<embed>`, `<applet>`, `<frame>`, `<frameset>`, `<param>`, `<portal>`.
- **Event handlers:** every `on*` attribute, such as `onclick` or `onerror`.
- **Script links:** any attribute whose value contains `javascript:`, `vbscript:` or similar. This is checked after decoding tricks like `&#106;`, `&colon;`, and hidden tabs or newlines inside the word.
- **`data:` links in link/source attributes:** removed, except plain images (PNG, GIF, JPEG and similar) in `src`-type attributes.
- **`srcdoc` and meta refreshes:** `srcdoc` attributes, and meta refreshes that point anywhere other than http or https.
- **Dangerous CSS:** `style` attributes or `<style>` blocks containing `expression(`, `behavior`, `-moz-binding`, or script links. This catches hiding tricks like `ex/**/pression` or `\65 xpression`.
- **Dangerous comments:** IE conditional comments, and comments that contain markup the filter would strip.

**Cases where safe content is also removed:**
- An attribute that merely mentions `javascript:` is dropped even if it's harmless, e.g. `title="Learn javascript: basics"`.
- An attribute value that contains HTML the filter would clean is dropped completely, e.g. a `title` holding an encoded `<script>` example.
- A whole `<style>` block goes if any rule in it is dangerous; the safe rules are not kept separately.
- Text inside `<title>`, `<textarea>`, `<noscript>` and similar is cleaned as if it were HTML. A browser shows that text literally, so a page displaying a literal `<script>` example there would lose it. This also blocks attacks that rely on browsers reading that text differently.
- Tags with malformed names like `<scr<script>` are dropped. Browsers ignore them anyway.
