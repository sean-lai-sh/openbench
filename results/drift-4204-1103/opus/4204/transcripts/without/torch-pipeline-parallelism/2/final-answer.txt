I've created `pipeline_parallel.py` with `train_step_pipeline_afab`. I tested it against an unsplit copy of a small LLaMA model at world sizes 1 and 2, with both eager and SDPA attention. The parameter gradients matched exactly (max difference 0) in every case. I didn't run your hook-based test of the activations; I only compared final gradients.

**How it works:**
- **Splitting the layers:** decoder layers are divided as evenly as possible, and any extra layers go to the lowest ranks. In the 5-layer test, rank 0 got 3 and rank 1 got 2. Rank 0 also runs the token embedding, and the last rank runs the final norm and output layer.
- **Forward phase:** every microbatch is run forward first. Ranks other than 0 receive hidden states shaped `[microbatch, seq_len, hidden_size]` from the previous rank, using `torch.distributed.P2POp` / `batch_isend_irecv`. Every rank except the last sends its output to the next rank. The last rank computes cross-entropy against the targets and divides it by the number of microbatches.
- **Backward phase:** then every microbatch is run backward. The last rank backpropagates from the loss; the others receive the gradient from the next rank. Every rank except rank 0 sends the gradient of its input back to the previous rank.
- **Device and dtype:** inputs, received hidden states and gradients are all moved to the given `device` and `dtype`. The model itself is not moved.
- No hooks are used.

**Other behaviour to know about:**
- The function returns the total scaled loss on the last rank and `None` on the other ranks.
- It doesn't zero gradients or take an optimizer step; it only accumulates gradients.
- The loss is computed directly against the targets with no shift, as the spec describes.
- With eager attention it builds an explicit causal mask. With SDPA it passes no mask, so the built-in causal mode is used, the same as the reference model.
