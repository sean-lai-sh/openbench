I created `pipeline_parallel.py` with `train_step_pipeline_afab`. In a quick test against an ordinary single-process model, the gradients matched exactly (max difference 0) with world_size 1 and with world_size 2. That test used a small 5-layer model, 3 microbatches, CPU and float32. I haven't run your actual test suite, so the hook-based activation checks haven't been tried.

**How it works:**
- **Splitting the layers:** decoder layers are divided evenly, and any leftover layers go to the earlier ranks (`_partition_layers`). With 5 layers on 2 ranks, rank 0 runs 3 and rank 1 runs 2. Rank 0 also does the token embedding; the last rank also does the final norm, `lm_head` and the loss. The model itself isn't changed.
- **Forward, all microbatches first:** each stage gets hidden states of shape `[mb, seq, hidden]` in the given `dtype` from the previous rank. It marks them as needing gradients, runs its layers, and sends the result on to the next rank. Position embeddings and the causal mask are computed separately on each stage.
- **Loss:** on the last rank, cross-entropy against the targets, divided by the number of microbatches.
- **Backward, all microbatches after:** the last rank runs `loss.backward()`. Earlier ranks receive the output gradient and call `torch.autograd.backward(output, grad)`. Every rank except 0 then sends the gradient of its input back to the previous rank.
- **Communication** uses `dist.P2POp` with `batch_isend_irecv`. There are no hooks in the implementation.
- **Device and dtype:** inputs, hidden states and gradients are all moved to the given `device` and `dtype`. The model itself is not moved, so it needs to already be on that device and in that dtype.

The function returns the total loss on the last rank and `None` on the others.

One thing to know: other ranks work out the size of incoming tensors from `inputs[mb].shape`, so every rank needs to be given the input microbatches, not just rank 0.
