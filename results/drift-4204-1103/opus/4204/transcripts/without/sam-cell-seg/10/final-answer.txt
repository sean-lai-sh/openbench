I wrote `convert_masks.py` and ran it on the demo files. Every mask now comes out as a polyline from MobileSAM, and my checks found no overlaps, one contiguous region per cell, and no rectangles. It takes about 30 seconds on CPU for the 48 masks. In a side-by-side render of before and after on the demo image, the new outlines follow the cells closely.

**How to run it.** The four arguments work either in order or as flags:
```
python convert_masks.py WEIGHTS OUTPUT RGB CSV
python convert_masks.py --weights_path W --output_path O --rgb_path R --csv_path C
```
If `output_path` ends in `.csv`, the result is written to that file. Otherwise it's treated as a folder (created if needed) and the file keeps the input CSV's name.

**How it works:**
- **Prompts:** every row, rectangle or polyline, is sent to MobileSAM as a box prompt. The image is processed once, and the boxes are run in batches of 16.
- **Choosing a mask:** MobileSAM gives three candidate masks per box. The script picks the one that scores best on MobileSAM's own confidence plus how well it matches the original annotation. For rectangles, it compares against an oval drawn inside the box, since cells are roughly oval. Candidates that spill well beyond the box lose points, and pixels far outside the box are ignored.
- **No overlap:** where two masks claim the same pixel, it goes to the mask MobileSAM is more confident about there. The script then keeps the largest connected piece of each mask, fills any holes, and leaves a 1-pixel gap from masks already placed. It redraws the final outline and checks it doesn't touch any other mask.
- **Never a rectangle:** if a result would be an axis-aligned box, its corners are cut off. If MobileSAM returns nothing usable, the script falls back to the original annotation, and failing that to a tiny shape at the box centre.
- **Output format:** same layout as the input, including the unnamed index column. Coordinates are comma-separated whole numbers with the first point repeated at the end, as in your file. `xmin`/`xmax`/`ymin`/`ymax` are recalculated from the new outline. All other columns are unchanged.

**Notes:**
- **`type` column:** it still says `rectangle` for the 19 rows that started as rectangles, because you asked that only the six position columns change. If you'd rather those rows say `polyline`, it's a one-line change.
- **Weights loading:** I load the weights myself, forcing them onto the CPU, because MobileSAM's own loader would fail on a machine without a GPU if the weights file was saved from a GPU. MobileSAM's source code isn't modified.
- **Speed:** it was faster here with PyTorch limited to one CPU thread, but I left the default since the best setting depends on the machine.
- **Match with the original masks:** the new polyline masks overlap their original outlines by about 78% on average (overlap ÷ combined area). For former rectangles the overlap is about 61%, which is expected since the box included background around each cell.
