I wrote `convert_masks.py`, and it converts every mask in the demo file to a polyline. I ran it on the demo image and all 48 masks came out as polylines, with no overlaps and one connected piece per cell. It took about 5 seconds on CPU.

**Usage**
```
python convert_masks.py <weights_path> <output_path> <rgb_path> <csv_path>
```
If `output_path` is a folder, the csv is saved inside it under the input csv's file name (e.g. `out/demo_metadata.csv`). If it ends in `.csv`, it's used as the output file path.

**How it works**
1. **Prompting:** it loads MobileSAM (`vit_t`) on CPU, computes the image features once, and uses each row's bounding box (from `coords_x`/`coords_y`) as a box prompt. It asks for three candidate masks per cell, 16 cells at a time.
2. **Choosing a mask:**
   - For existing polylines, it picks the candidate that best combines SAM's confidence score with overlap with your original outline.
   - For rectangles, it uses SAM's score plus how much of the mask stays inside the box, and penalises masks that fill almost the whole box or almost none of it.
3. **One mask per cell, no overlaps:**
   - Each mask is limited to a slightly enlarged version of its box and reduced to its largest connected piece, with holes filled.
   - Where two masks claim the same pixel, the cell SAM is more confident about wins.
   - A 1-pixel gap is kept between neighbouring cells so the polylines can't cross each other.
   - If one outline would enclose another cell, it is shrunk until it doesn't.
   - If a cell ends up with no pixels, it gets a small ellipse inside its box.
4. **Output:** each outline is traced from the mask edge and closed (first point repeated at the end), like your input. `xmin`/`ymin`/`xmax`/`ymax` are recalculated from the new outline. Every other column, including the index, is copied unchanged.

**Results on the demo**
- No two outlines overlap, checked both at pixel level and at 8× resolution.
- Each outline fills a single connected region, and none is a rectangle. All other columns match the input exactly.
- Visually the outlines fit the nuclei well, including those that started as loose rectangles. Overlap with the original outlines averages 0.77 for polylines and 0.57 for rectangles. The rectangle figure is lower mainly because the boxes are bigger than the cells.

**Things to know**
- **`type` column:** it still says `rectangle` for rows that were rectangles, because you asked for only the coordinate columns to change. If you'd rather it say `polyline`, that's a one-line change.
- **Your system Python can't run it yet:** it doesn't have numpy, torch or mobile_sam installed. For testing I created a local `.venv` with MobileSAM from its GitHub repo and downloaded `mobile_sam.pt` into this folder. Delete both if you don't need them.
- **Extra dependency:** MobileSAM itself needs `timm`, which isn't on your list of installed packages. If your test machine has a working `mobile_sam`, it should already have `timm`, but it's worth confirming. I didn't modify the MobileSAM source.
