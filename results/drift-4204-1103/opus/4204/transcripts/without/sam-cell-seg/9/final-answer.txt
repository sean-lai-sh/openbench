I wrote `convert_masks.py` and ran it on the demo files. All 48 masks came out as non-overlapping, single-piece polylines, and none are rectangles. It takes about 70 seconds on CPU for this 374×355 image.

**Running it:** the four arguments work either by name or in order:
```
python convert_masks.py --weights_path mobile_sam.pt --output_path out/ --rgb_path demo_rgb.png --csv_path demo_metadata.csv
python convert_masks.py mobile_sam.pt out/ demo_rgb.png demo_metadata.csv
```
If `output_path` is a folder, the result is saved there under the input csv's file name. If it ends in `.csv`, it's used as the output file name.

**How it works:**
1. **Model:** it loads MobileSAM (`vit_t`) on CPU and processes the image once. MobileSAM's source code is untouched.
2. **Prompting:** each cell is prompted with its bounding box, with and without a positive point. For rectangles the point is the box centre; for polylines it's the deepest point inside the annotated outline. Each prompt gives 3 candidate masks.
3. **Choosing a mask:** candidates are limited to a slightly enlarged box, smoothed, cut down to their largest piece, and holes are filled. Masks that are tiny or nearly fill the whole box are penalised. Rectangles then use MobileSAM's own confidence score. Polylines combine that score with overlap against the original outline, so their existing shape still counts.
4. **Fallbacks:** if MobileSAM gives an empty mask, the script uses the original outline, or an ellipse inside the box for rectangles.
5. **Removing overlap:** where two masks claim the same pixel, it goes to the cell whose centre is closest relative to its size. A 1-pixel gap is then left between neighbouring cells so the saved outlines can't overlap. Each cell is cut down to one piece again.
6. **Saving:** each outline is saved closed (first point repeated, as in your input). `xmin`, `xmax`, `ymin` and `ymax` are recalculated from it. All other columns, including the unnamed index column, are copied unchanged.

**Checks on the demo output:**
- Redrawing every saved outline gives 0 overlapping pixels, and each mask is exactly one piece.
- The refined former polylines overlap their original outlines by 78% on average (lowest 64%).
- A visual comparison shows the outlines follow the cell nuclei closely, including where former rectangles were.

**Things to know:**
- The `type` column still says `rectangle` for cells that were rectangles, because you asked for only the coordinate and bounding-box columns to change. If you'd rather every row say `polyline`, that's a one-line change.
- Some former rectangles come out noticeably smaller than their original box, because MobileSAM outlines just the nucleus. For example, cell 0's box was x 43–139 and its mask now spans x 45–115.
- A test run that passes a weights path won't need this, but I found MobileSAM weights in the local cache at `/opt/uvcache/git-v0/checkouts/e7d9320a8522f22d/34bbbfd/weights/mobile_sam.pt` and used them for testing.
