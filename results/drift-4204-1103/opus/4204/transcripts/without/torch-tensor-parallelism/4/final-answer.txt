I created `parallel_linear.py` with `ColumnParallelLinear` and `RowParallelLinear`. A test with the `gloo` backend passed at world sizes 1, 2 and 4. It compared outputs, input gradients, and the gradients of each rank's weight and bias slice against a plain `nn.Linear` using the same weights. I deleted the test script afterwards.

**ColumnParallelLinear**
- `master_weight` has shape `(out_features, in_features)`. Each rank keeps rows `[rank*n:(rank+1)*n]`, where `n = out_features // world_size`. That's the output dimension, which is what "columns" means in Megatron-style tensor parallelism.
- Bias is sharded the same way, with `n` values per rank, all starting at zero.
- In the forward pass, each rank computes its share of the output, and the shares are gathered and joined along the last dimension. In the backward pass, each rank takes its own slice of the output gradient, and the input gradient is summed across ranks.

**RowParallelLinear**
- Each rank keeps columns `[rank*n:(rank+1)*n]` of `master_weight`, where `n = in_features // world_size` (the input dimension).
- Bias is full size on every rank, starts at zero, and is added once after the sum, so it isn't counted `world_size` times.
- In the forward pass, each rank computes a partial output and the partials are summed across ranks. The gradient passes straight through that sum in the backward pass.
- **Input handling:** the spec doesn't say whether the input arrives already split, so the layer accepts both. If the input's last dimension equals `in_features`, it splits it and gathers the gradient back. Otherwise it treats the input as already being this rank's slice.

**Other details**
- If `torch.distributed` hasn't been initialised, both classes fall back to world size 1 and rank 0.
- `out_features` (column) and `in_features` (row) must divide evenly by the world size; an assertion checks this.
- The type checker flags the `backward` method signatures, but that's a known false positive with PyTorch's type stubs and has no effect when the code runs.
