I created `parallel_linear.py` with both classes, and they match `nn.Linear` at world sizes 1, 2 and 4. I checked this with a short throwaway script using the gloo backend; it isn't saved in the project. On every rank it compared the output, the input gradient, and the weight and bias gradients against the matching slice of a reference `nn.Linear`.

**How each class works:**
- **`ColumnParallelLinear`**: `master_weight` has shape `(out_features, in_features)`. Each rank keeps its own block of rows, `out_features / world_size` of them, and a zero-initialised bias of the same length. The forward pass computes the local output and then gathers all ranks' pieces along the last dimension. In the backward pass, the output gradient is split so each rank gets its own piece, and the input gradient is summed across ranks.
- **`RowParallelLinear`**: each rank keeps a slice of `master_weight` along `in_features`, `in_features / world_size` columns wide, and a full-size zero-initialised bias. Each rank computes a partial output, the partial outputs are summed across ranks, and the bias is added once after that sum.

**Things you might not assume:**
- **Input to `RowParallelLinear`**: it takes either the full input, which it splits itself, or an input that's already split. It tells them apart by the size of the last dimension and raises a `ValueError` if that size matches neither.
- **Gradients**: they flow through the gather, split and sum steps correctly because those steps are custom autograd functions. If `torch.distributed` hasn't been initialised, both layers act as single-process layers.
- **Divisibility**: `out_features` (column) or `in_features` (row) must divide evenly by `world_size`; an assertion fails otherwise.
