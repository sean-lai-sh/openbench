I wrote the polyglot to `polyglot/main.rs`. I compiled it with both `rustc` and `g++ -x c++`, and both builds printed the same results for N = 0, 1, 2, 3, 10, 50, 90 and 150 (for example, 10 gives 89).

**How it works:** Rust allows comments inside comments, and C++ doesn't, so the two compilers read the file differently.
- **First line, `/* /* */`:** C++ sees one complete comment and goes on to read the C++ code below it. Rust sees two comments opened and only one closed, so it treats the C++ code as still inside a comment.
- **Before the Rust code:** `#if 0` tells C++ to skip everything until `#endif`. Rust is still inside the comment here, so it ignores this line.
- **The `// */` line:** in Rust this closes the comment and the Rust code starts. C++ just reads it as a one-line comment.
- **End of the file:** `/* /* */ #endif // */` uses the same trick in reverse, so C++ reaches `#endif` and Rust skips it.

Both versions use 128-bit unsigned integers. That gives exact results up to about N = 183; beyond that the numbers overflow. In the Rust build, which has overflow checks off by default, that would give a wrong answer rather than an error.
