I created `parallel_linear.py` with both layers. I tested them against a plain `torch.nn.Linear` with world sizes 1, 2 and 4, running on CPU with the gloo backend. Outputs, weight and bias gradients, and input gradients all matched.

Weights use `nn.Linear`'s layout, `(out_features, in_features)`.

**`ColumnParallelLinear`**
- **Sharding:** each rank keeps its slice of the output dimension, `master_weight[r*O/ws:(r+1)*O/ws, :]`, plus a matching zero bias of size `O/ws`.
- **Forward:** each rank computes its local output, then the pieces are all-gathered and joined along the last dimension.
- **Backward:** each rank keeps only its own slice of the output gradient. The input gradient is all-reduced (summed across ranks).

**`RowParallelLinear`**
- **Sharding:** each rank keeps its slice of the input dimension, `master_weight[:, r*I/ws:(r+1)*I/ws]`, plus the full zero bias of size `O`.
- **Forward:** each rank multiplies its part of the input, the partial results are all-reduced (summed), and the bias is added once at the end.
- **Backward:** the output gradient passes through unchanged, and the input gradient is all-gathered.

**Choices I made where the spec was unclear:**
- **Input to `RowParallelLinear`:** it accepts either the full input, which it splits itself, or an input that's already split for this rank. It tells them apart by the size of the last dimension.
- **Divisibility:** `out_features` (column) and `in_features` (row) must divide evenly by `world_size`, or the constructor raises an error.
- **No process group:** if `torch.distributed` hasn't been initialized, both layers run as a single process (world size 1).
