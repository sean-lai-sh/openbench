I created `parallel_linear.py` with both classes. I tested them against a plain `torch.nn.Linear` using world sizes 1, 2 and 4. The outputs and the gradients for the weights, bias and input all matched the reference on every rank.

Both classes expect `master_weight` to have shape `(out_features, in_features)`, the same layout `nn.Linear` uses. Each rank keeps a copy of its own slice, and the bias starts at zero.

**ColumnParallelLinear**
- **Weight:** each rank keeps its share of the output rows (`weight[rank*out/ws:(rank+1)*out/ws, :]`).
- **Bias:** split the same way, so each rank holds `out/ws` values.
- **Output:** each rank's partial outputs are gathered from all ranks (all_gather) and concatenated along the last dimension.
- **Gradients:** each rank gets back only the part of the output gradient that belongs to its slice. The input gradients are summed across ranks (all_reduce).

**RowParallelLinear**
- **Weight:** each rank keeps its share of the input columns (`weight[:, rank*in/ws:(rank+1)*in/ws]`).
- **Bias:** every rank holds the full bias, added once after the partial outputs are summed.
- **Output:** the partial outputs are summed across ranks with all_reduce.
- **Gradients:** passed straight through for the output. When the layer split a full input itself, it gathers the input gradient back to full size.

**Input to RowParallelLinear:** your spec didn't say whether this layer receives the full input or an already-split one, so it accepts both. If the last dimension equals `in_features`, it splits the input itself; if it equals `in_features / world_size`, it uses it as is. With a world size of 1 the two cases are the same.

If `torch.distributed` hasn't been initialised, both classes fall back to a world size of 1 and rank 0 instead of raising an error.
