I've created `pipeline_parallel.py` with `train_step_pipeline_afab`. In a local test with world sizes 1 and 2, the loss matched a reference model run on the same microbatches, and every parameter gradient matched exactly (difference 0).

transformers isn't installed in the main Python environment, so I tested in a separate virtualenv at `/tmp/tvenv` using transformers 5.22.1. The test was a small 5-layer model, float32 on CPU, with 3 microbatches. I deleted the test script afterwards. I didn't recreate the real test's hooks, so its activation checks haven't been run against this code.

**How it works:**
- **Layer split:** layers are divided as evenly as possible, with earlier ranks taking one extra when they don't divide evenly (5 layers on 2 ranks gives 3 and 2). Only rank 0 runs the embedding, and only the last rank runs the final norm and output layer.
- **Forward, all microbatches first:** rank 0 embeds the input IDs; other ranks receive hidden states of shape `[microbatch, seq_len, hidden_size]` from the previous rank. Each rank runs its own layers and sends the result on. The last rank computes cross-entropy against the targets and divides it by the number of microbatches.
- **Backward, then all microbatches:** the last rank calls `loss.backward()`. Other ranks receive the gradient from the next rank, backpropagate it through their layers, and send the gradient of their input back to the previous rank.
- **Communication:** stages talk using `torch.distributed.P2POp` with `batch_isend_irecv`. Inputs, hidden states and gradients are always moved to the given `device`/`dtype`. No hooks are used.
- **Return value:** the summed loss on the last rank, and `None` on the other ranks.

**Things that could differ from the test's reference:**
- I build the causal attention mask myself instead of using transformers' helper, because that helper's signature changes between versions. This works with the default attention backends but won't work with flash attention.
- The loss is computed in float32 even when `dtype` is lower precision. With float16 or bfloat16 this may give a slightly different value from a reference that computes it at the lower precision.
- The function doesn't move the model itself to `device`/`dtype`; it assumes the test already did that.
